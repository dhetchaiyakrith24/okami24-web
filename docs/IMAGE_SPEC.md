## 2. ต้นฉบับที่รับได้

- **เกณฑ์คุณภาพ WebP (เจ้าของสั่ง 2026-09-06): คุณภาพ 82 คือ "ขั้นต่ำ" ห้ามลดต่ำกว่านี้เพื่อให้ไฟล์เล็ก** — ถ้าไฟล์เกินเพดานขนาดที่คุณภาพ 82 ให้ลดขนาดผืน/หาต้นฉบับที่เหมาะกว่า ห้ามลดคุณภาพลง · **สคริปต์ตรงกฎนี้แล้ว [แก้ + ตรวจจริง 2026-09-06 — LAUNCH_AUDIT ข้อ 32]**: `scripts/process-images.ts` ลบบันไดลดคุณภาพ `WEBP_FALLBACK_QUALITIES` ทิ้งแล้ว บันทึกที่ 82 เสมอ · ไฟล์ที่ยังเกินเพดานที่ 82 **ถูกเขียนที่ 82 พร้อมคำเตือน** ไม่ถูกลดคุณภาพ และขึ้นสรุป `!! N file(s) exceed the size cap at q82` ท้ายการรัน พร้อมวิธีแก้ (ใส่ `canvas` ในแม็ป หรือหาต้นฉบับใหม่) · `scripts/product-image.ts` → `saveWebp()` ก็ถูกล็อกพื้นที่ 82 เช่นกัน (ผู้เรียกขอต่ำกว่านี้จะถูกดันขึ้นเป็น 82) · **ไม่มีรูปไหนบนเว็บที่ถูกบันทึกต่ำกว่า 82** — dry-run ทั้งแม็ป 2026-09-06 ทุกไฟล์ (59 รูป) = q82 และไม่มีไฟล์ไหนชนเพดาน (ข้อจำกัดเดิมยังอยู่: ไฟล์ WebP ไม่เก็บค่าคุณภาพไว้ในตัวไฟล์ ย้อนดูได้เฉพาะจากรายงานการรัน ซึ่งถูกเขียนทับทุกครั้งที่รัน)
- **เกณฑ์ขนาด (เจ้าของแก้ 2026-09-06): ไม่ยึด 800 px แล้ว** — ใช้**ต้นฉบับใหญ่สุดที่หาได้**จากแหล่งที่ระบุที่มาได้ · ถ้าไม่มีรูปใหญ่ รูปเล็กแต่**ชัด/สวย**ใช้ได้ ปรับขนาดบนการ์ดให้เหมาะ · **ห้ามยืด** (ทำให้คมด้วย AI = §0 ข้อ 7 เท่านั้น) · เดิมกำหนด "ด้านยาว ≥ 800 px" — สคริปต์ยังใช้ 800 เป็นค่าตั้งต้น ต้นฉบับที่เล็กกว่าต้องเขียน `minLong` ในแม็ปพร้อม `note` ว่าทำไม (เป็นบันทึกว่าตั้งใจ ไม่ใช่การขออนุมัติซ้ำ)
- **ห้ามขยายรูป** (upscale) — ตัวสินค้าจะถูกย่อลงให้พอดีผืนผ้าใบเท่านั้น · ข้อยกเว้นเดียวที่เจ้าของอนุมัติ: ขยายได้ไม่เกิน **5%** เพื่อให้พอดีขอบ (เช่น ต้นฉบับสูง 800 → 840) เพราะทดสอบแล้วไม่เห็นความต่าง; ถ้าต้องขยายเกิน 5% ให้วางเล็กกว่าขอบแทน และบันทึกไว้ · ขยาย/ทำใหม่ด้วย AI = §0 ข้อ 7 (คนละเรื่องกับการขยายไฟล์เดิม)
- ต้องเป็นรูปสินค้า**ของจริง** จากผู้ผลิต/ตัวแทนจำหน่าย/ร้านค้าที่ระบุที่มาได้ ห้ามรูปที่เดาว่าเป็นสินค้าตัวนั้น · รูปที่ทำด้วย AI = §0 ข้อ 7 ที่เดียว (ไฟล์จากเน็ตตรวจ metadata `AIGC` ก่อนใช้เสมอ)
- **สีต้องตรงของจริง** — สีมาจากต้นแบบของสีนั้นเท่านั้น (ย้อม/สร้างสีได้แค่ไหน = §0 ข้อ 7 "ยังห้าม")

## 3. หน้าตาที่ต้องได้

- **พื้นหลังโปร่งใสทั้งร้าน** (alpha channel จริง — ตรวจด้วยพิกเซล ไม่ใช่ดูนามสกุล)
- **เงา** = §0 ข้อ 8 (เก็บเงาสัมผัสพื้น/เงาสะท้อนเป็นส่วนโปร่งแสงได้ · เงาลอยหรือแสงฟุ้งรอบเครื่อง = ตัด)
- **สินค้ากึ่งกลาง** ผืนผ้าใบ ทั้งแนวตั้งและแนวนอน
- **ขอบว่างรอบสินค้า:** รูปสี/กลิ่น 8% ของผืน (1000 px → กรอบ 840×840 กึ่งกลาง) · **การ์ด 3% (ผืน 4:5 → กรอบ 940×1175)** — มาตรฐานการ์ดทั้งร้าน (เจ้าของสั่ง 2026-09-30 "การ์ดในหน้ารวมต้องขนาดเข้าชุดกัน"): กรอบการ์ดในหน้ารวมเป็น 4:5 การ์ดสี่เหลี่ยมจัตุรัสจึงเหลือสินค้าสูงแค่ ~67% ของกรอบ (Muro) ขณะที่การ์ดแนวตั้งเต็ม ~99% (Nexbar) · การ์ดใหม่ทุกใบ = ผืน 4:5 สินค้า 94% (`scripts/process-images.ts` ทำให้เอง) · การ์ดเดิมแก้ตอนไล่การ์ดทั้งร้าน
- **ห้าม** ลายน้ำ · ข้อความ · โลโก้ร้าน · กรอบ · ป้ายชื่อสี · เส้นขอบ (ถ้าต้นฉบับมี ต้องตัดออกโดยไม่ตัดตัวสินค้า — ถ้าตัดไม่ได้ ไม่ใช้รูปนั้น)
- **ห้ามตัดตัวสินค้าแหว่ง** เพื่อเลี่ยงลายน้ำ/ข้อความ — สินค้าต้องครบทั้งชิ้น

## 4. รูปไหนต้องมี

- **เครื่อง (pod / mod / kit) ที่มีหลายสี → ต้องมีรูปแยกทุกสี** (ชั้น 2 ใน IMAGE_AUDIT) — สีที่ยังไม่มีรูปสะอาดให้ใส่เป็น swatch ไว้ก่อน (ห้ามตัดสีทิ้ง)

## 5. การจับคู่รูปกับข้อมูลสินค้า

- ชื่อสี/รสในข้อมูลสินค้า (`src/data/products/*.ts`) **ห้ามเปลี่ยน** เพื่อให้ตรงกับชื่อในรูป — ถ้าชื่อไม่ตรง (เช่น เว็บทางการ "Funta Green" แต่เว็บเรา "Funta Grape") ให้ทำรายการเสนอเจ้าของ ไม่แก้เอง
- รส/สีที่เว็บทางการมีแต่เว็บเรายังไม่มี → **เพิ่มเอง แล้วรายงาน** (กฎแคตตาล็อกครบ `CLAUDE.md` · เจ้าของ 15/10) · ชื่อไม่ตรงกัน = ข้อบนนี้
- ไฟล์ตั้งชื่อตาม id ของตัวเลือกในข้อมูลสินค้า: `public/assets/products/<slug>/variant-<id>.webp` · การ์ด `card.webp` · แกลเลอรี `detail-<n>.webp`
- ทุกรูปต้องมีที่มาบันทึกใน `_incoming/<source>/SOURCE.md` (URL ต้นทาง วันที่ ผู้ผลิต/ร้าน) ก่อนเข้า `public/`

## 6. กฎการทับรูปเดิม

- รันสคริปต์ด้วย `--dry-run` ก่อนทุกครั้ง
- **ทับรูปเดิมเฉพาะเมื่อตัวสินค้าในรูปใหม่ใหญ่กว่า** (วัดด้านยาวของตัวสินค้าจริงหลังตัดพื้นหลัง เทียบกับด้านยาวของตัวสินค้าในไฟล์เดิม) — ถ้าเล็กกว่าหรือเท่ากัน ข้ามและรายงาน
- รูปเดิมที่ทึบ (ไม่มีพื้นหลังโปร่งใส): ตัดพื้นหลังด้วยสคริปต์เดียวกัน **เฉพาะเมื่อพื้นหลังเรียบ** (สีเดียว) — พื้นหลังยุ่ง/ไล่สี/มีของอื่นในรูป ไม่ทำอัตโนมัติ ให้รายงานแทน

## 7. วิธีตรวจ

- `npx tsx scripts/process-images.ts --dry-run` → ดูรายการว่าจะทำอะไรกับไฟล์ไหน
- `npx tsx scripts/product-image.ts audit` → ตรวจคุณภาพทุกไฟล์ใต้ `public/assets/products`

## 8. สคริปต์ `scripts/process-images.ts`

- อินพุต: โฟลเดอร์ `_incoming/` (gitignored) + ไฟล์แม็ป `scripts/process-images.map.json` ที่บอกว่าไฟล์ไหน → slug ไหน / บทบาทอะไร (card / variant-<id> / detail-<n>)
- ขั้นตอนต่อไฟล์: ตรวจ AIGC (ไฟล์ที่มีแท็กถูกปฏิเสธ ยกเว้นรายการที่มีบล็อก `aiRender` ของ §0 ข้อ 7) → ตัดพื้นหลัง (ถ้ายังทึบและพื้นเรียบ) → ตัดขอบว่าง → วัดด้านยาวของตัวสินค้า (**ค่าตั้งต้นของสคริปต์คือ 800 — ไม่ใช่กฎของร้าน** ต้นฉบับที่เล็กกว่าให้ใส่ `minLong` ในแม็ปตามหมวด 0 ข้อ 1 แล้วสคริปต์รับ) → ย่อให้พอดีกรอบ 84% (ขยายได้ไม่เกิน 5%) → วางกึ่งกลางผืนผ้าใบ 1000×1000 (หรือ 1600×1600) → WebP q82 (**พื้นตายตัว ไม่มีการลดคุณภาพเพื่อให้ไฟล์เล็ก**) → ตรวจขนาดไฟล์ (เกินเพดาน = เตือน ไม่ใช่ลดคุณภาพ) → เขียนลง `public/assets/products/<slug>/`
