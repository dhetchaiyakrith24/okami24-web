# OKami24 — IMAGE SPEC (มาตรฐานรูปสินค้าทั้งร้าน)

กำหนดโดยเจ้าของ 2026-09-05 · ใช้กับทุกรูปที่เข้า `public/assets/products/` ตั้งแต่นี้ไป · สคริปต์ที่บังคับใช้: `scripts/process-images.ts` (ดูท้ายไฟล์) · รูปเดิมที่ยังไม่ผ่านสเปคไม่ถูกลบ แต่จะถูกแทนที่เมื่อมีต้นฉบับที่ดีกว่า

## 1. ขนาดและไฟล์

| ชนิด | ผืนผ้าใบ | ฟอร์แมต | ขนาดไฟล์สูงสุด | ใช้ที่ไหน |
|---|---|---|---|---|
| **การ์ด** (card) และ **รูปสีเครื่อง** (variant) | **1000×1000 px** สี่เหลี่ยมจัตุรัส | WebP คุณภาพ 82 | **≤ 150 KB** | การ์ดในแคตตาล็อก, หน้าสินค้า, ตัวเลือกสี, หน้าแรก |
| **แกลเลอรี** (detail) | **1600×1600 px** | WebP คุณภาพ 82 | **≤ 400 KB** | แกลเลอรีในหน้าสินค้า |
| **Hero / แบนเนอร์หน้าแรก** | กว้าง **≥ 1920 px** | WebP | ตามความเหมาะสม | หน้าแรก (ยังไม่มีรูปชนิดนี้ในระบบ) |

## 2. ต้นฉบับที่รับได้

- **เกณฑ์ขนาด (เจ้าของแก้ 2026-09-06): ไม่ยึด 800 px แล้ว** — ใช้**ต้นฉบับใหญ่สุดที่หาได้**จากแหล่งที่ระบุที่มาได้ · ถ้าไม่มีรูปใหญ่ รูปเล็กแต่**ชัด/สวย**ใช้ได้ ปรับขนาดบนการ์ดให้เหมาะ · **ห้ามยืด ห้าม AI upscale** · เดิมกำหนด "ด้านยาว ≥ 800 px" — สคริปต์ยังใช้ 800 เป็นค่าตั้งต้น ต้นฉบับที่เล็กกว่าต้องเขียน `minLong` ในแม็ปพร้อม `note` ว่าทำไม (เป็นบันทึกว่าตั้งใจ ไม่ใช่การขออนุมัติซ้ำ)
- **ห้ามขยายรูป** (upscale) — ตัวสินค้าจะถูกย่อลงให้พอดีผืนผ้าใบเท่านั้น · ข้อยกเว้นเดียวที่เจ้าของอนุมัติ: ขยายได้ไม่เกิน **5%** เพื่อให้พอดีขอบ (เช่น ต้นฉบับสูง 800 → 840) เพราะทดสอบแล้วไม่เห็นความต่าง; ถ้าต้องขยายเกิน 5% ให้วางเล็กกว่าขอบแทน และบันทึกไว้
- ต้องเป็นรูปสินค้า**ของจริง** จากผู้ผลิต/ตัวแทนจำหน่าย/ร้านค้าที่ระบุที่มาได้ — **ห้ามรูปที่สร้างด้วย AI** (ตรวจ metadata `AIGC` ก่อนใช้เสมอ) ห้ามรูปที่เดาว่าเป็นสินค้าตัวนั้น
- **สีต้องตรงของจริง** — ห้ามปรับสี/ย้อมสีให้ตรงชื่อ ถ้ารูปไม่ตรงสีให้หารูปใหม่

## 3. หน้าตาที่ต้องได้

- **พื้นหลังโปร่งใสทั้งร้าน** (alpha channel จริง — ตรวจด้วยพิกเซล ไม่ใช่ดูนามสกุล)
- **ไม่มีเงา** ไม่มีแสงสะท้อนพื้น
- **สินค้ากึ่งกลาง** ผืนผ้าใบ ทั้งแนวตั้งและแนวนอน
- **ขอบว่างรอบสินค้า 8%** ของผืนผ้าใบ (การ์ด 1000 px → สินค้าอยู่ในกรอบ 840×840 กึ่งกลาง)
- **ห้าม** ลายน้ำ · ข้อความ · โลโก้ร้าน · กรอบ · ป้ายชื่อสี · เส้นขอบ (ถ้าต้นฉบับมี ต้องตัดออกโดยไม่ตัดตัวสินค้า — ถ้าตัดไม่ได้ ไม่ใช้รูปนั้น)
- **ห้ามตัดตัวสินค้าแหว่ง** เพื่อเลี่ยงลายน้ำ/ข้อความ — สินค้าต้องครบทั้งชิ้น

## 4. รูปไหนต้องมี

- **กฎเจ้าของ (2026-09-05/06): สินค้าต้องโชว์ครบทุกสี/ทุกรสตามผู้ผลิต แม้ร้านไม่มีสต๊อก ห้ามข้ามเพราะไม่มีของขาย — เรื่องสต๊อก / Sold out / สีจาง เป็นหน้าที่ระบบตะกร้าทีหลัง ไม่ใช่เหตุผลให้ตัดรูปหรือตัดตัวเลือก**
- **เครื่อง (pod / mod / kit) ที่มีหลายสี → ต้องมีรูปแยกทุกสี** (ชั้น 2 ใน IMAGE_AUDIT) — สีที่ยังไม่มีรูปสะอาดให้ใส่เป็น swatch ไว้ก่อน (ห้ามตัดสีทิ้ง)
- **รส (flavor)**: ถ้าผู้ผลิตมีรูปแยกรสทางการ ให้ใช้ (ผ่านสเปคเดียวกับสี) · ถ้าไม่มี ใช้รูปหลักรูปเดียว (เจ้าของ 2026-09-04) — แต่**รายการรสต้องครบ**ตามผู้ผลิตเสมอ
- สินค้าที่มีตัวเลือกเดียว ใช้รูปการ์ดเป็นรูปตัวเลือกได้เลย
- **สินค้าที่ยังไม่มีรูปการ์ดเลย → ซ่อนจากหน้าร้านชั่วคราว** (ข้อมูลยังอยู่ในระบบ) จนกว่าจะมีรูป — เจ้าของสั่ง 2026-09-06; กลไก: ฟิลด์ `hiddenFromStorefront` ในข้อมูลสินค้า (ดู `src/types/catalog.ts`)

### ข้อยกเว้นที่เจ้าของอนุมัติแล้ว (บันทึกไว้ ห้ามใช้เป็นบรรทัดฐานใหม่โดยไม่ถาม)
- zero-pro 8 สี: ต้นฉบับ 796–800px (ต่ำกว่า 800 ไม่เกิน 4px) — รับ, ขยาย 5% ตามข้อ 2
- **joiway-f4 การ์ด: ต้นฉบับ 741px** (ต่ำกว่าเกณฑ์ 59px) — รับเมื่อ 2026-09-06 เพราะเป็นรูปทางการเพียงรูปเดียวที่มี และดีกว่าไม่มีรูป; ถ้าได้รูปใหญ่กว่าให้แทนที่ทันที
- **joiway-f4 คู่รส 16 รูป: ต้นฉบับ 734px** — รับภายใต้เหตุผลเดียวกับการ์ด F4 (รูปทางการชุดเดียวที่มี; ตัดโลโก้เทาที่อยู่หลังเครื่องออกด้วย `keepLargestComponent`)
- **joiway-f3 ทั้งชุด (การ์ด + 30 รส)**: ต้นฉบับทางการมีเงา/แสงจางกึ่งโปร่งใสรอบเครื่อง — ตัดด้วย `alphaCut: 200` (ทิ้งพิกเซลที่โปร่งกว่า ~78%) ให้ตรงกฎ "ไม่มีเงา"; ขอบเครื่องยังคม

## 5. การจับคู่รูปกับข้อมูลสินค้า

- ชื่อสี/รสในข้อมูลสินค้า (`src/data/products/*.ts`) **ห้ามเปลี่ยน** เพื่อให้ตรงกับชื่อในรูป — ถ้าชื่อไม่ตรง (เช่น เว็บทางการ "Funta Green" แต่เว็บเรา "Funta Grape") ให้ทำรายการเสนอเจ้าของ ไม่แก้เอง
- รส/สีที่เว็บทางการมีแต่เว็บเรายังไม่มี → ทำรายการเสนอ ไม่เพิ่มเอง
- ไฟล์ตั้งชื่อตาม id ของตัวเลือกในข้อมูลสินค้า: `public/assets/products/<slug>/variant-<id>.webp` · การ์ด `card.webp` · แกลเลอรี `detail-<n>.webp`
- ทุกรูปต้องมีที่มาบันทึกใน `_incoming/<source>/SOURCE.md` (URL ต้นทาง วันที่ ผู้ผลิต/ร้าน) ก่อนเข้า `public/`

## 6. กฎการทับรูปเดิม

- รันสคริปต์ด้วย `--dry-run` ก่อนทุกครั้ง
- **ทับรูปเดิมเฉพาะเมื่อตัวสินค้าในรูปใหม่ใหญ่กว่า** (วัดด้านยาวของตัวสินค้าจริงหลังตัดพื้นหลัง เทียบกับด้านยาวของตัวสินค้าในไฟล์เดิม) — ถ้าเล็กกว่าหรือเท่ากัน ข้ามและรายงาน
- รูปเดิมที่ทึบ (ไม่มีพื้นหลังโปร่งใส): ตัดพื้นหลังด้วยสคริปต์เดียวกัน **เฉพาะเมื่อพื้นหลังเรียบ** (สีเดียว) — พื้นหลังยุ่ง/ไล่สี/มีของอื่นในรูป ไม่ทำอัตโนมัติ ให้รายงานแทน

## 7. วิธีตรวจ

- `npx tsx scripts/process-images.ts --dry-run` → ดูรายการว่าจะทำอะไรกับไฟล์ไหน
- `npx tsx scripts/product-image.ts audit` → ตรวจคุณภาพทุกไฟล์ใต้ `public/assets/products`
- `docs/IMAGE_AUDIT.md` → รายการรูปที่ยังขาด/ต่ำกว่าเกณฑ์ (นับใหม่เมื่อรูปเปลี่ยน)
- เปิดดูของจริงในเบราว์เซอร์ทั้งจอคอมและมือถือทุกครั้งที่รูปเปลี่ยน — สคริปต์เป็นแค่ด่านแรก คนตัดสินสุดท้าย

## 8. สคริปต์ `scripts/process-images.ts`

- อินพุต: โฟลเดอร์ `_incoming/` (gitignored) + ไฟล์แม็ป `scripts/process-images.map.json` ที่บอกว่าไฟล์ไหน → slug ไหน / บทบาทอะไร (card / variant-<id> / detail-<n>)
- ขั้นตอนต่อไฟล์: ตรวจ AIGC → ตัดพื้นหลัง (ถ้ายังทึบและพื้นเรียบ) → ตัดขอบว่าง → วัดด้านยาวของตัวสินค้า (ต้อง ≥ 800) → ย่อให้พอดีกรอบ 84% (ขยายได้ไม่เกิน 5%) → วางกึ่งกลางผืนผ้าใบ 1000×1000 (หรือ 1600×1600) → WebP q82 → ตรวจขนาดไฟล์ → เขียนลง `public/assets/products/<slug>/`
- รันซ้ำได้ (idempotent): ไฟล์ปลายทางที่มีอยู่จะถูกทับก็ต่อเมื่อผ่านกฎข้อ 6 เท่านั้น
- **`canvas` (เพิ่ม 2026-09-06):** ต้นฉบับที่ใหญ่สุดที่มีจริงแต่ตัวสินค้าต่ำกว่า 840 px → ใส่ `"canvas": <px>` ในแม็ปให้ผืนเล็กลงจนสินค้ากลับมาอยู่ที่ 84% ของผืน (เช่น เครื่อง 722 px → ผืน 860) แทนการขยายพิกเซล · หน้าเว็บย่อ/ขยายรูปให้พอดีกรอบอยู่แล้ว การ์ดจึงเท่ากับสินค้าอื่น · ใช้ครั้งแรกกับ relx-smash-go-12k (designer ชี้ว่าที่ผืน 1000 เครื่องเล็กกว่าเพื่อน ~20%)
- `--dry-run` = รายงานอย่างเดียว ไม่เขียนไฟล์ · `--only <slug>` = ทำเฉพาะสินค้านั้น
