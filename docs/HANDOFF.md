### รอบเสถียรภาพ — OOM บน Render · **merge + deploy แล้ว**

**[ตรวจแล้วจริง]** commit `a790f81` `eb8a727` `a00f048` `7d5cbc1` · รายละเอียดเต็มอยู่ **LAUNCH_AUDIT ข้อ 46**

**หลักฐานตั้งต้น [Cowork ตรวจใน Render Events]:** `Ran out of memory (used over 512MB)` **6 ครั้งใน 2 วัน** ครั้งละ ~1 นาที

**สาเหตุที่พิสูจน์ได้จากภายนอก [ตรวจแล้วจริง]:**
- `/_next/image` เคยตอบ `cf-cache-status: **DYNAMIC**` = **Cloudflare ไม่แคชรูปเลย** เครื่อง Render ย่อและส่งรูปให้ทุกคนเอง
- header เคยเป็น `max-age=**14400**` (4 ชม.) = ค่า default ของ `minimumCacheTTL` ใน Next 16 → **ทุก 4 ชม. รูปทั้งแคตตาล็อกหมดอายุแล้วถูกย่อใหม่จากต้นฉบับซ้ำ**

**แก้อะไร (`next.config.ts` อย่างเดียว):** `minimumCacheTTL` 4 ชม. → **30 วัน** · ตัด `deviceSizes` **2048/3840** · `imgOptConcurrency` 2 → **1** · `/assets/**` cache 30 วัน

**ผลจริงหลัง deploy [ตรวจแล้วจริง ยิงเว็บเอง]:**
- `/_next/image` **DYNAMIC → HIT** (ยิง URL เดิม 3 ครั้ง: MISS แล้ว HIT/HIT) — Cowork สร้าง Cache Rule แล้ว
- `Cache-Control` **14400 → 2592000, must-revalidate**
- `?w=3840` **200 → 400** บน production
- **ข้อควรรู้:** URL ที่ยังไม่เคยถูกขอ (เช่นเปลี่ยน `w=`) จะเป็น MISS ครั้งแรกเสมอ ไม่ใช่ Cache Rule เสีย

**เรื่องที่เจ้าของสั่งเพิ่ม — `priority` ที่ตายเพราะ Next 16:** แก้ครบ **4 จุด** (แกลเลอรีมือถือของเดิม + ของ ProductMaster + hero เดสก์ท็อป 2 สาขา) และ **ถอด prop `priority` ที่ตายออกจาก `ProductMedia` ทิ้ง** · วัด HTML จริงแล้วสไลด์ที่โชว์ได้ `eager`/`high` สไลด์อื่น `lazy`

## 10. Git — งานที่ปนกันใน working tree ควรแยก commit ยังไง

**[ตรวจแล้วจริง] ตอนนี้ working tree สะอาด ไม่มีอะไรปน**

นโยบายที่ใช้มาตลอดและควรใช้ต่อ:
- **แยกก้อนตามชนิด:** `docs` / `scripts` / `code` / `css` / `data` / `deploy` — **ห้าม `git add -A` ก้อนเดียว**
- commit message เป็น**ภาษาอังกฤษ** · เขียนว่า *ทำไม* ไม่ใช่แค่ *อะไร* · ใส่ตัวเลขที่วัดได้จริง
- ใช้ `git commit -F <ไฟล์>` (message ยาวและมีอักขระพิเศษ)
- ปิดท้ายทุกก้อนด้วย `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- **push ทันทีที่จบก้อน** · **ห้าม force push ตลอดไป** · **ห้าม merge/deploy เอง**
