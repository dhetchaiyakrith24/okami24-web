## 10. Git — งานที่ปนกันใน working tree ควรแยก commit ยังไง

[ตรวจแล้วจริง] working tree สะอาด ไม่มีอะไรค้าง

นโยบาย: แยก commit ตามชนิด — `docs` / `scripts` / `code` / `css` / `copy` / `data` / `config` · ห้าม `git add -A` · message อังกฤษ · `git commit -F <ไฟล์>` (backtick พังใน shell) · ปิดท้าย `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` **ต้องอยู่บรรทัดสุดท้าย** (เคยใส่กลาง message แล้วต้อง amend) · push ทันทีที่จบก้อน · **เจ้าของอนุญาต 2026-09-10: ถ้า context ใกล้เต็ม commit+push ก่อนผู้ตรวจตอบได้ แล้ว commit แก้ทับทีหลัง — "commit ราคาถูก ย้อนได้ · context ที่หมดกลางทาง ย้อนไม่ได้"** (แต่ต้องบันทึกในรายงานว่าทำแบบนี้ เพราะ checker จะทักว่าขัด 13.7)
· ไฟล์ dictionary ที่มีทั้งคีย์โค้ดและข้อความ (เช่น `puffUnit`) ใส่ก้อน copy พร้อม `types.ts` เพื่อให้แต่ละ commit tsc ผ่านในตัวเอง
