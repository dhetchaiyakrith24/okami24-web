## 8. ความเสี่ยงและจุดต้องระวัง (อันตรายมากไปน้อย)

1. **OOM ยังไม่ปิดเคส** — เกิด 3 ครั้งในวันเดียวบน 512MB · ขึ้น 2GB แล้วแต่ยังไม่รู้ว่าพอ **[เจ้าของบอก]** · ถ้ายังล่มอีกให้ไปดูข้อ 6 ในไฟล์ v15 (`docs/HANDOFF.2026-09-09-v15.md`) ที่จดสมมติฐานเรื่อง LRU cache ของ Next ไว้ — **ยังไม่เคยพิสูจน์** อย่าเชื่อทันที
2. **ห้าม merge / deploy / force push เอง** — Cowork หรือเจ้าของเป็นคนกด · revert ไม่ reset
3. **desktop ห้ามขยับแม้พิกเซลเดียว** — พิสูจน์ด้วย `node scripts/shot.js <out> <url> --width 1440 --desktop` แล้วเทียบ · baseline ที่ตรงกับโค้ดปัจจุบันคือ `_incoming/m1b/shots/final3/`
4. **หน้าที่ไม่นิ่งเองตอนถ่ายภาพ (อย่าตกใจ)** — จดไว้ครบใน **ข้อ 8.4 ของไฟล์นี้เอง ด้านล่าง** ↓
5. **แตะ JSX บรรทัดที่เดสก์ท็อปเห็น ให้คงรูปทรงเดิม** — เคยเกิดจริง: รวม `{n} {คำ}` เป็นสตริงเดียวทำให้ตัวอักษรขยับ 30px ที่ 1440
6. **นิยาม agent ถูกอ่านตอนเปิดเซสชัน** — แก้ไฟล์ `.claude/agents/*.md` แล้ว **เซสชันปัจจุบันไม่เห็นการเปลี่ยนแปลง** ต้องเปิดเซสชันใหม่ · เป็นข้อจำกัดของเครื่องมือ ไม่ใช่บั๊กของโปรเจกต์

9. **ปิดเซิร์ฟเวอร์ทดสอบ ต้องเจาะจง PID เสมอ — `taskkill //PID <pid> //F` เท่านั้น · ห้ามใช้ `taskkill /F /IM node.exe /T` เด็ดขาด** (เจ้าของสั่ง 2026-09-10) · **เคยเกิดจริงคืน 9 ก.ย.:** checker สั่งฆ่า node ทั้งเครื่องเพื่อเคลียร์เซิร์ฟเวอร์ของตัวเอง **ดับไป 5 process** ซึ่งไม่ใช่ของมันทั้งหมด — ถ้าเจ้าของมี dev server หรืองาน node อื่นค้างอยู่ตอนนั้นก็ดับไปด้วยโดยไม่มีใครรู้ · หา PID ด้วย `netstat -ano | grep ":<port>.*LISTENING"` แล้วฆ่าเฉพาะตัวนั้น · **ข้อนี้ต้องเขียนใส่คำสั่งของ checker/agent ทุกตัวที่ให้รันเซิร์ฟเวอร์เอง** ไม่ใช่หวังว่ามันจะรู้เอง

## 14. ควรหยุดทำ

- **หยุดยิงภาพเดสก์ท็อปซ้ำเพื่อไล่ให้ diff เป็น 0 เป๊ะทุกหน้าทุกรอบ** — 3 หน้าไม่นิ่งเองอยู่แล้ว (ข้อ 8.4) การยิงซ้ำเกิน 2–3 รอบต่อหน้าคือเสียเวลาเปล่า · เกณฑ์ที่ถูกคือ "มีคู่ที่ identical กับ baseline"

- **หยุดหาคลิปวิดีโอพื้นหลังจากเว็บผู้ผลิตรายอื่น** — สำรวจ 4 เว็บแล้ว ตัวที่ดีที่สุดยังสว่างเกินใช้ไม่ได้ · ถ้าจะเอาวิดีโอจริงต้องถ่าย/สั่งทำเอง
