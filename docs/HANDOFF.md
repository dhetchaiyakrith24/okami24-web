## 8. ความเสี่ยงและจุดต้องระวัง (อันตรายมาก → น้อย)

1. **เว็บที่ออนไลน์อยู่ตอนนี้ล่มทุกครั้งที่มีคนกดใส่ตะกร้า** — จนกว่าเจ้าของจะ merge + deploy · ลูกค้าจริงเจอ 502 อยู่ [ตรวจแล้วจริง จาก log ที่เจ้าของส่ง]
2. **ถ้า deploy ด้วย `main` เก่า (ยังไม่ merge) จะได้โค้ดพังเหมือนเดิม** — และถ้า merge แล้ว build ล้มที่ `[native-check]` แปลว่า Node ยังไม่ใช่ 24.14.1 (Blueprint ยังไม่ sync) — build ล้ม = เว็บเก่ายังอยู่ ไม่พังเพิ่ม
3. **ลืมผูกดิสก์ / รันมากกว่า 1 instance / อัป `okami24.db` จากเครื่องนี้** — ยังเป็นความเสี่ยงเดิมจาก v9 ทุกข้อ · ทดสอบดิสก์ตาม `DEPLOY-RENDER.md` ข้อ 6 **ก่อนเปิดขาย**
4. **`_incoming/qc/` โดนล้าง** (ข้อขัดแย้ง 2) — บอก checker ทุกครั้งว่า "ลบได้เฉพาะไฟล์ที่คุณสร้างเอง ระบุชื่อ" · หลักฐานภาพของงานที่ผ่านมาไม่มีบนดิสก์แล้ว ใช้ commit hash
5. **`_incoming/` ทั้งโฟลเดอร์ไม่อยู่ใน git** — ต้นฉบับรูป (ueeshop, salthub, joiway, uwell…) + `SOURCE.md` หายได้ถ้าเครื่องพัง · เจ้าของเคยเจอโฟลเดอร์หลักหายมาแล้ว → push ทุกอย่างที่ commit ได้ทันที
6. **แรม 512MB** — ยังไม่เคยเห็น build ผ่านบน Render เลย (ครั้งแรก build ผ่านแต่ runtime ล่ม) · `imgOptConcurrency: 2` ช่วยตอนรัน · ถ้า build OOM เจ้าของสั่งไว้ว่าขยับแพลนชั่วคราว
7. **ข้อจำกัดของเซสชัน (ไม่ใช่บั๊กโปรเจกต์):** เครื่อง dev เป็น Windows ไม่มี Docker/WSL → ทำอาการ Linux ซ้ำไม่ได้ · Browser pane ใช้กับเว็บนี้ไม่ได้ ใช้ `node scripts/shot.js` (มี `--cookie okami24_locale=en` สำหรับหน้าอังกฤษ) · `next start` เสิร์ฟ build เก่า ต้อง `next build` ก่อนทดสอบ · `grep -c` คืน exit 1 เมื่อไม่พบ อย่าใช้ในสาย `&&` (เซสชันนี้ทำ commit หายไปหนึ่งรอบเพราะข้อนี้ ไม่มีงานเสีย) · เอเจนต์ล้มเพราะโควตาโมเดล ให้เปิดใหม่ระบุ `model: opus` · dev server ค้างจอง port → `taskkill //PID <pid> //F`
8. **`OKAMI24_PROMPTPAY_QR_BASE64` ยังไม่รู้ว่าเจ้าของใส่ในหน้า Environment แล้วหรือยัง** — ถ้ายัง หน้าออเดอร์จะโชว์เลขบัญชีแทน QR (ไม่พัง)

working tree สะอาด · นโยบาย: แยกก้อนตามชนิด (docs / scripts / code / data / deploy) ห้าม `add -A` · `git commit -F <ไฟล์>` · ลงท้าย `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` (ตามที่ระบบบอกตอนนั้น) · push เมื่อจบก้อน · **ห้าม force push** · **ห้าม merge main** (เจ้าของทำ)

**บันทึกไว้ให้ตรง:** เซสชันนี้ใช้ `git reset -q` (แบบไม่มี path = เอาไฟล์ออกจาก staging อย่างเดียว ไม่แตะ history ไม่แตะไฟล์) 1 ครั้ง หลังคำสั่ง commit ล้มเพราะ `grep -c` — ไม่ใช่การย้อน commit แต่รายงานไว้เพราะกฎบอก "revert ไม่ reset"

| ขั้น | ทำได้แล้วหรือยัง |
|---|---|
| ลูกค้าเปิดเว็บเจอภาษาไทย | **ได้แล้ว** (บน production ก็ได้ — ส่วนที่ไม่แตะฐานข้อมูลยังเปิดได้) |

| ทีมเห็นออเดอร์ | ยังไม่มีหน้าแอดมิน |

| เคลม/รับประกัน | ได้แล้ว |
| เว็บออนไลน์บนโดเมนจริง **และใช้งานได้** | **ออนไลน์แล้ว ยังใช้งานไม่ได้** ← รอ deploy โค้ดแก้ |
