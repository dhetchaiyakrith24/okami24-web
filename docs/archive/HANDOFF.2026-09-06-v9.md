## 10. Git — งานที่ปนกันใน working tree ควรแยก commit ยังไง

ตอนนี้ **working tree สะอาด ไม่มีงานปนกัน** · นโยบายที่ใช้: แยกก้อนตามชนิดเสมอ (docs / scripts / code / data / test) ห้าม `add -A` ก้อนเดียว · ลงท้ายทุก commit ด้วย `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` · ใช้ `git commit -F <ไฟล์>` · **ห้าม force push**

**บันทึกไว้ให้ตรง:** เซสชันนี้ commit ก้อนแรกเผลอกลืนไฟล์ที่ถูกลบของก้อนภาษาไปด้วย ผมใช้ `git reset --soft HEAD~1` ถอยกลับมาแบ่งใหม่ (ยังไม่ push ไม่มีงานหาย) — ผิดจากกฎ "revert ไม่ reset" ของเจ้าของ รายงานให้เจ้าของทราบแล้ว

## 13. แนะนำทำอะไรต่อ (เรียงลำดับ)

1. **งานรูปสินค้า 12 ตัว ก้อนละ 3 ตัว** — เป็นสิ่งที่เจ้าของสั่งไว้ชัดและกระทบยอดขายมากที่สุด (ลูกค้าไม่กล้าซื้อของที่รูปไม่ชัด) · จบก้อน = checker + designer + commit + push แล้วค่อยก้อนถัดไป
2. **สมัคร Render กับเจ้าของ** — เมื่อเจ้าของว่าง 30 นาที · เป็นบล็อกเปิดขายเรื่องเดียวที่เหลือ
3. **ข้อ 32 ล็อกคุณภาพ WebP ที่ 82** — 30 นาที ทำได้เลย และควรทำ**ก่อน**เริ่มงานรูป ไม่งั้นรูปใหม่อาจถูกบันทึกต่ำกว่าเกณฑ์เจ้าของ
4. **ข้อ 35 คำไทยใต้ชื่อหมวด + ข้อ 19 hreflang** — งาน SEO สองชิ้นที่ต่อกัน ทำทีเดียวคุ้มกว่า
5. **ข้อ 1 หน้าแอดมิน** — เมื่อเจ้าของสั่ง (ตอนนี้สั่งทดไว้)

## 14. ควรหยุดทำ

## 15. ปลายทางของโปรเจกต์ — flow เต็ม

| ขั้น | ทำได้แล้วหรือยัง |
|---|---|
| ลูกค้าเปิดเว็บเจอภาษาไทย | **ได้แล้ว** |
| หาสินค้า/เห็นรูปครบทุกสีทุกกลิ่น | **ยังไม่ครบ** (งานรูป 12 ตัว) |
| ใส่ตะกร้า → กรอกที่อยู่ → สั่งซื้อ | **ได้แล้ว** |
| จ่ายเงิน (โอน/พร้อมเพย์ + แจ้งชำระ) | **ได้แล้ว** (แนบสลิปยังไม่ได้) |
| ทีมเห็นออเดอร์ | **ยังไม่มีหน้าแอดมิน** (ดูจากฐานข้อมูล) |
| ส่งของ + ลูกค้าตามสถานะ | **ได้แล้ว** (คีย์ Shipnity เอง ยังไม่เชื่อมอัตโนมัติ) |
| เคลม/รับประกัน | **ได้แล้ว** (/warranty) |
| เว็บออนไลน์บนโดเมนจริง | **ยังไม่ได้** ← บล็อกสุดท้าย |
