# /handoff — เอกสารส่งต่อสำหรับแชทใหม่

เจ้าของงาน (SMOGZ) อ่านโค้ดไม่ออก เอกสารนี้ต้องเป็นภาษาคน และต้อง**ซื่อสัตย์ยิ่งกว่าปกติ** เพราะ AI ตัวถัดไปจะเชื่อทุกคำในนี้

---

## ขั้นที่ 1 — ตรวจของจริงก่อน ห้ามข้าม

ก่อนเขียนแม้แต่บรรทัดเดียว ให้รัน:

```
git status
git log -10 --oneline
git diff --stat
```

แล้วอ่านไฟล์เอกสารเดิมที่มีในโปรเจกต์ (เช่น `docs/HANDOFF.md`, `docs/*.md`, `README.md`) ถ้ามี

**กฎ:** ถ้าสิ่งที่จำได้จากแชทขัดกับสิ่งที่เห็นในโค้ด/git → **เชื่อโค้ด** และเขียนระบุไว้ในหัวข้อ "ข้อขัดแย้งที่พบ" ว่าเจออะไรที่ไม่ตรง

---

## ขั้นที่ 2 — เขียนเอกสารตามโครงนี้ ครบทุกหัวข้อ

หัวข้อไหนไม่มีข้อมูล ให้เขียนว่า "ไม่มี" หรือ "ไม่ทราบ" **ห้ามข้ามหัวข้อเงียบ ๆ**

```
# <ชื่อโปรเจกต์> — HANDOFF
สร้างเมื่อ: <วันที่> · อ้างอิงจาก: <git HEAD + สิ่งที่ตรวจจริง>

## ข้อขัดแย้งที่พบ
<สิ่งที่แชท/เอกสารเก่าบอกไว้ แต่ของจริงไม่ตรง — ถ้าไม่มีให้เขียน "ไม่พบ">

## 1. สถานะปัจจุบัน
<โปรเจกต์คืออะไร ใช้อะไรสร้าง อยู่ตรงไหนของเส้นทาง · โฟลเดอร์ · branch · HEAD · จำนวนไฟล์ที่ยังไม่ commit>

## 2. ทำเสร็จแล้ว (ใช้งานได้จริง ตรวจแล้ว)
## 3. เพิ่งทำล่าสุด (เซสชันนี้)
## 4. ยังไม่ได้แก้ (รู้ว่าพัง/ขาด แต่ยังไม่ได้ทำ)
## 5. รอสานต่อ (มีโครงแล้ว ต้องต่อยอด)
## 6. จำเป็นแต่ยังไม่ได้ทำเลย
## 7. คำถามที่เจ้าของต้องตอบ (ตาราง: เรื่อง / รู้แล้ว / ยังไม่รู้ / ต้องตอบอะไร)
## 8. ความเสี่ยงและจุดต้องระวัง (เรียงจากอันตรายมากไปน้อย)
## 9. ห้ามรื้อ (สิ่งที่เจ้าของอนุมัติแล้ว หรือทำงานถูกต้องแล้ว)
## 10. Git — งานที่ปนกันใน working tree ควรแยก commit ยังไง
## 11. ความพร้อมแต่ละระบบ (ตาราง: ระบบ / สถานะ / เหตุผลสั้น ๆ)
## 12. กำลังทำอะไรค้างอยู่ตอนปิดแชท
## 13. แนะนำทำอะไรต่อ (เรียงลำดับ พร้อมเหตุผล)
## 14. ควรหยุดทำ (สิ่งที่ทำต่อแล้วเสียเวลาหรือเสี่ยง)
## 15. ปลายทางของโปรเจกต์ — flow เต็ม ระบุว่าแต่ละขั้นทำได้แล้วหรือยัง

## 16. บล็อกสำหรับวางในแชทใหม่ (copy-paste)
<สรุปย่อ 20-30 บรรทัดที่ AI ตัวถัดไปอ่านแล้วเริ่มงานได้ทันที
 ต้องมี: โปรเจกต์ / โฟลเดอร์ / branch / HEAD / กำลังทำอะไร / ห้ามรื้ออะไร /
 ทำอะไรต่อ / นโยบาย commit / วิธี verify>

## สิ่งแรกที่แชทใหม่ควรทำ
<3 ข้อ — ข้อแรกต้องเป็น "รัน git status + git log แล้วเทียบกับเอกสารนี้ ถ้าไม่ตรงให้เชื่อ repo">
```

## ขั้นที่ 3 — บันทึกเป็นไฟล์ ไม่ใช่แค่ตอบในแชท

- เขียนลง `docs/HANDOFF.md` ในโฟลเดอร์โปรเจกต์ (สร้างโฟลเดอร์ `docs` ถ้ายังไม่มี)
- ถ้ามีไฟล์เดิมอยู่ ให้คัดลอกเก็บเป็น `docs/archive/HANDOFF.<วันที่เดิม>-v<ฉบับเดิม>.md` (สร้างโฟลเดอร์ `docs/archive` ถ้ายังไม่มี — ฉบับเก่าทุกฉบับอยู่ที่นั่น ไม่วางใน `docs/` เจ้าของเคาะ 2026-09-17) แล้วค่อยเขียนทับ
- แล้วบอกเจ้าของว่า: ไฟล์อยู่ที่ไหน + วางบล็อกข้อ 16 ให้ในแชทเลยเพื่อ copy ได้ทันที

## กฎเหล็ก

1. **แยกให้ชัด 3 คำ** ทุกหัวข้อ: "ตรวจแล้วจริง" / "ผมเข้าใจว่า" / "เจ้าของยังไม่ได้ยืนยัน" — ห้ามเขียนสิ่งที่ยังไม่แน่ให้ดูเหมือนแน่
2. **"ผ่าน QC เทคนิค" ≠ "เจ้าของอนุมัติ"** — ต้องเขียนแยกกันเสมอ
3. **ตัวเลขทุกตัวต้องบอกว่านับจากไหน** ถ้าตัวเลขสองชุดวัดคนละอย่าง ต้องเตือนว่าห้ามเอามาบวกกัน
4. **ห้ามซ่อนงานค้างใต้คำว่า "later" หรือ "ทีหลัง"** — ทุกอย่างที่ยังไม่ได้ทำต้องอยู่ในข้อ 4, 5 หรือ 6
5. **หัวข้อ "ควรหยุดทำ" ต้องมีของจริง** ไม่ใช่เว้นว่าง — ทุกโปรเจกต์มีสิ่งที่ทำต่อแล้วเสียเปล่า
6. ถ้าเซสชันนี้มีปัญหาเครื่องมือ (เบราว์เซอร์ค้าง, cache เก่า ฯลฯ) ให้บันทึกไว้ในข้อ 8 ว่าเป็นข้อจำกัดของเซสชัน ไม่ใช่บั๊กของโปรเจกต์
