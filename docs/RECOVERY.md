## 1. เว็บพัง / ขึ้นของผิด → กลับไปเวอร์ชันก่อนหน้า (~2 นาที)

2. เมนูซ้าย กด **Deploys** — จะเห็นรายการ deploy ทุกครั้ง เรียงใหม่สุดอยู่บน แต่ละแถวมีรหัส 7 ตัว (เช่น `857745b`) และวันเวลา

4. กดปุ่ม **⋯** (หรือ **Rollback**) ท้ายแถวนั้น → ยืนยัน **Rollback**
5. รอราว 2 นาที จนแถวใหม่บนสุดขึ้น **Live** สีเขียว → เปิด https://okami24.store ดูว่ากลับเป็นปกติ

## 3. ฐานข้อมูลมีปัญหา (ออเดอร์หาย / เว็บบอกว่าเปิด DB ไม่ได้)

**ตอนนี้ยังไม่ใช่เรื่องใหญ่ [ตรวจแล้ว]:** ตะกร้าปิดอยู่ (ข้อ 43) ลูกค้าสั่งทางไลน์ ออเดอร์จึงไม่เข้า DB — DB บนเว็บจริงมีแต่ของทดสอบ

สำเนามี 3 ชั้น:
1. **บนเครื่อง Render เอง** — เว็บสำรองให้อัตโนมัติทุก 6 ชั่วโมงตั้งแต่เปิดเว็บ ไว้ที่ `/var/data/backups` (เก็บ 60 ชุดล่าสุด) · **ข้อจำกัด:** อยู่ดิสก์ก้อนเดียวกับต้นฉบับ (LAUNCH_AUDIT ข้อ 42)
2. **Render ถ่ายภาพดิสก์ (snapshot) ให้ทุกวัน** — เจ้าของรับเป็น backup หลักไว้แล้ว 2026-09-07 · กู้ได้จากหน้าบริการ okami24 → **Disks** → เลือกดิสก์ `okami24-data` → **Snapshots** → Restore **[ยังไม่ได้ซ้อม — ให้ Cowork กดพร้อมกันครั้งแรก]**
3. **ในคอมเจ้าของ** `C:\Users\dhetc\OKami24-backups\` — สำเนาของ DB **ทดสอบในเครื่อง** เท่านั้น ไม่ใช่ DB เว็บจริง (ล่าสุด 2026-09-10 18:32 · 30 ไฟล์ · ตรวจ integrity ผ่านทุกไฟล์)

**ถ้าต้องกู้จริง:** อย่ากดอะไรใน Render เอง → พิมพ์บอก Cowork/Code ว่า "กู้ DB จากสำเนา ชั้น 1 หรือ 2" · ขั้นตอนละเอียดอยู่ `docs/BACKUP.md` หัวข้อ "กู้คืนจริง"

## 5. ห้ามกดเด็ดขาด

- **Delete service / Delete disk / Suspend** ใน Render — ลบแล้ว DB และสำเนาชั้น 1 หายทั้งหมด
- **เปลี่ยน `OKAMI24_ORDERING` เป็น `on`** — เปิดตะกร้าได้ต่อเมื่อข้อ 44 ครบ 7 เกณฑ์ และต้องผ่าน render.yaml + merge (ไม่ใช่กดใน dashboard)
- **Manual Deploy จาก branch อื่นที่ไม่ใช่ `main`** และ **Sync Blueprint** โดยไม่ถาม — อย่างหลังจะทับค่าที่ตั้งในหน้าจอกลับเป็นค่าในไฟล์
- ใน GitHub: **Delete branch / Delete tag / Force push** — จุดกลับทุกจุดในข้อ 2 อยู่ตรงนั้น
