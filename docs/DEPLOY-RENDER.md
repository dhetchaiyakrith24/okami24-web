# เอาเว็บ OKami24 ขึ้นออนไลน์ที่ Render (สิงคโปร์)

เขียน 2026-09-06 · เขียนให้คนที่อ่านโค้ดไม่ออกทำตามได้ · เจ้าของตัดสินใจเลือก Render สิงคโปร์แล้ว

**สิ่งที่เตรียมไว้ให้แล้วในโปรเจกต์ (ไม่ต้องทำอะไร):** ไฟล์ `render.yaml` คือใบสั่งงานที่บอก Render ว่าต้องตั้งค่าอะไรบ้าง
ถ้าใช้วิธี Blueprint ข้างล่าง Render จะอ่านไฟล์นี้แล้วกรอกช่องต่าง ๆ ให้เอง

> **ตั้งแต่ 21/10: Blueprint ของบริการจริงถูกพัก sync ("Sync paused")** → แก้ `render.yaml` แล้ว**ไม่ถึง Render** · **เปลี่ยนค่าของ Render
> (Auto-Deploy · ตัวแปร · คำสั่ง build) = แก้ในหน้า Render (dashboard)** · ทุกที่ในไฟล์นี้ที่บอก "แก้ไฟล์ → merge" ใช้ไม่ได้จนกว่าจะเปิด sync คืน
> (เปิดคืน = ถามทีมก่อน — sync จะทับค่าในหน้าจอกลับเป็นค่าในไฟล์) · ขึ้นเว็บเองทุก merge = หน้า Render → Settings → Auto-Deploy "On Commit" (`docs/RECOVERY.md` 1ก)

## 0. ก่อนเริ่ม ต้องมีอะไรบ้าง

| ของ | สถานะ |
|---|---|
| บัญชี GitHub ที่มีโค้ดเว็บ (repo `okami24-web`) | มีแล้ว |
| โดเมน `okami24.store` ที่ Cloudflare | มีแล้ว |
| บัตรเครดิต/เดบิตที่จ่ายเงินต่างประเทศได้ | ต้องเตรียม |

ค่าใช้จ่ายที่จะเกิดขึ้น: ประมาณ **$7.25 ต่อเดือน (~250 บาท)** = ค่าเครื่อง $7 + ค่าดิสก์เก็บข้อมูล 1GB $0.25

## 1. สมัคร Render (5 นาที)

1. เปิด `render.com` → กด **Get Started** มุมขวาบน
2. เลือกสมัครด้วย **GitHub** → กด **Authorize Render**
3. หน้าจอถามว่าให้ Render เห็น repo ไหน → เลือก **Only select repositories** → ติ๊ก **okami24-web** → กด **Install**

**สำเร็จเมื่อ:** เห็นหน้า Dashboard ของ Render และมีปุ่ม **New +** อยู่มุมขวาบน

## 2. ผูกบัตร (3 นาที)

4. เมนูซ้าย → **Billing** → **Add payment method** → กรอกข้อมูลบัตร
5. **สำเร็จเมื่อ:** หน้า Billing แสดงเลข 4 ตัวท้ายบัตร (ยังไม่ถูกตัดเงินจนกว่าจะสร้างเครื่องจริง)

## 3. สร้างเครื่อง (10 นาที)

**วิธีที่ง่ายที่สุด — ให้ Render อ่านใบสั่งงานเอง:**

6. กด **New +** → เลือก **Blueprint**
7. เลือก repo **okami24-web** → เลือก branch **main** → กด **Connect**
8. Render จะอ่านไฟล์ `render.yaml` แล้วขึ้นสรุปว่าจะสร้างอะไร ตรวจว่าเห็น 4 อย่างนี้:
   - ชื่อ **okami24**
   - Region **Singapore**
   - Plan **Starter**
   - Disk **okami24-data** ขนาด **1 GB**
9. กด **Apply** / **Create** → Render เริ่มติดตั้งและ build (รอบแรกใช้เวลาประมาณ 5–10 นาที)

**สำเร็จเมื่อ:** สถานะขึ้นเป็น **Live** สีเขียว และกดลิงก์ `okami24-xxxx.onrender.com` แล้วเว็บเปิดได้จริง

> **บริการจริงของเราสร้างด้วย Blueprint** (เจ้าของตรวจจากหน้า Render 2026-09-06) แต่ **Blueprint พัก sync ("Sync paused") ตั้งแต่ 21/10** → แก้ `render.yaml` แล้วไม่ถึง Render · เปลี่ยนค่าใด ๆ = ในหน้า Render โดยตรง (`docs/RECOVERY.md` ข้อ 1 · 1ก) · อย่ากด "Sync Blueprint" โดยไม่ถาม (มันจะทับค่าในหน้าเว็บด้วยไฟล์) · ข้อความเก่าเรื่อง Auto Sync = `git show 0ecdd4bf:docs/DEPLOY-RENDER.md`

> **ถ้า Blueprint ใช้ไม่ได้** (Render เปลี่ยนหน้าตาหรือฟ้อง error เรื่องไฟล์) ให้กด **New + → Web Service** แล้วกรอกมือตามตารางนี้

### ดูจำนวนคนกดปุ่มไลน์ (เพิ่มรอบ 8 · 2026-09-23)

เว็บนับคนกดลิงก์ไลน์เองโดยไม่ใช้คุกกี้ ไม่เก็บข้อมูลบุคคล — ดูยอดได้โดยไม่ต้องตั้งรหัสอะไร:

1. Render → เลือกบริการ **okami24** → แท็บ **Shell** (Web Shell)
2. พิมพ์บรรทัดนี้แล้วกด Enter:
   `cd /opt/render/project/src && node scripts/line-clicks.js --days 30`
3. **เห็นแบบนี้ = สำเร็จ:** บรรทัด `total: <ตัวเลข>` ตามด้วยตาราง by day · by spot · by page
   - `pill` = ปุ่มไลน์ลอยมุมจอ · `buy` = ปุ่มสั่งทางไลน์ในหน้าสินค้า · `footer` = ไอคอนท้ายเว็บ · `other` = ลิงก์ไลน์อื่นในเนื้อหน้า
   - เปลี่ยน `30` เป็น `7` = ดู 7 วัน · ต่อท้าย `--json` = ได้เป็น JSON
   - ถ้าขึ้น `no line_clicks table yet` = ยังไม่มีใครเข้าเว็บตั้งแต่ deploy — รอให้มีคนเข้าแล้วลองใหม่
   - ถ้าขึ้น `no database at …` = ค่า `OKAMI24_DATA_DIR` ของเครื่องไม่ตรง — ลอง `node scripts/line-clicks.js --db /var/data/app-data/okami24.db`

### ทำไมค่าพวกนี้สำคัญ (อ่านผ่าน ๆ พอ)

- **Disk `/var/data`** = ที่เก็บออเดอร์ ถ้าไม่มีอันนี้ ออเดอร์จะหายทุกครั้งที่อัปเดตเว็บ
- **`OKAMI24_DATA_DIR` / `OKAMI24_BACKUP_DIR`** = บอกเว็บว่าฐานข้อมูลและไฟล์สำรองต้องไปนอนบนดิสก์ก้อนนั้น
- **`TZ`** = ให้เวลาบนเซิร์ฟเวอร์เป็นเวลาไทย ไม่งั้นชื่อไฟล์สำรองจะเพี้ยนไป 7 ชั่วโมง
- **หนึ่งเครื่องเท่านั้น** ห้ามเพิ่ม instance เป็น 2 เด็ดขาด เพราะฐานข้อมูลเป็นไฟล์เดียว ถ้ามี 2 เครื่องออเดอร์จะแตกเป็นสองชุด

## 4. ต่อโดเมน okami24.store (10 นาที)

10. ในหน้าเว็บของเราใน Render → **Settings** → หัวข้อ **Custom Domains** → **Add Custom Domain**
11. พิมพ์ `okami24.store` → เพิ่มอีกครั้งสำหรับ `www.okami24.store`
12. Render จะโชว์ค่าที่ต้องเอาไปใส่ที่ Cloudflare **ก๊อปเก็บไว้** (ปกติจะเป็น A record สำหรับชื่อโดเมนเปล่า และ CNAME สำหรับ www)
13. เปิด `dash.cloudflare.com` → คลิกโดเมน **okami24.store** → เมนู **DNS** → **Add record** → กรอกตามที่ Render บอกเป๊ะ ๆ
14. **ตอนนี้ให้กดรูปเมฆให้เป็นสีเทา (DNS only) ก่อน** — ถ้าเปิดเมฆส้มตั้งแต่แรก Render จะออกใบรับรองความปลอดภัยไม่ได้
15. รอจนหน้า Render ขึ้นเครื่องหมายถูกสีเขียว / คำว่า **Verified** และ **Certificate Issued** (ปกติ 1–10 นาที)
16. กลับไป Cloudflare → เมนู **SSL/TLS** → ตั้งโหมดเป็น **Full**
17. กลับไปหน้า **DNS** → กดรูปเมฆให้เป็น **สีส้ม** (เปิด proxy)

**สำเร็จเมื่อ:** พิมพ์ `okami24.store` ในมือถือแล้วเว็บขึ้น มีรูปกุญแจล็อกหน้า URL ไม่มีคำเตือนสีแดง

> เปิดเมฆส้มไว้ดีกว่าปิด: รูปภาพจะโหลดเร็วขึ้นสำหรับลูกค้าในไทย

## 5. เอารูป QR พร้อมเพย์ขึ้นเซิร์ฟเวอร์ (5 นาที · ทำหลังเว็บขึ้นแล้ว)

> **ทำไมต้องทำ (บทเรียน 2026-09-07):** รูป QR **ไม่ได้อยู่ใน GitHub โดยตั้งใจ** (เป็นข้อมูลรับเงินของร้าน) มันอยู่แค่ในเครื่องเจ้าของ · เว็บจริงจึงขึ้นมาโดย**ไม่มี QR ทั้งวันแรก** — หน้าโอนเงินโชว์แค่เลขบัญชี และไม่มีใครรู้เพราะเซิร์ฟเวอร์ตอนบูตเงียบ (แก้แล้ว: ตอนนี้พิมพ์บรรทัด `[qr]` ทุกครั้ง ดูข้อ 23) · ต้องส่งขึ้นไปเอง**ครั้งเดียว**ด้วยวิธีข้างล่าง แล้วเซิร์ฟเวอร์จะเก็บไว้บนดิสก์ตลอด

**ฝั่ง Friday (Claude Code) เตรียมให้ก่อน** — สั่งในโปรเจกต์:

```bash
npm run qr:upload-text
```

ได้ไฟล์ `_incoming/qr-upload/promptpay-qr.b64` = รูป QR แปลงเป็นตัวหนังสือ **ราว 3,200 ตัวอักษร** — สคริปต์บีบลาย QR เป็นขาวดำ 2 สี แล้ววางโลโก้พร้อมเพย์สีต้นฉบับกลับตรงกลาง (ลาย QR เหมือนต้นฉบับทุกจุด สคริปต์ตรวจพิกเซลเทียบกันเองและจะไม่ยอมบีบถ้าไม่ตรง · รูปเดิมจะยาว 66,000 ตัวอักษร) · รูปต้นฉบับใน `.data/private/` **ไม่ถูกแตะ** · Friday ส่งไฟล์นี้ให้เจ้าของ**ในแชท Claude Code เท่านั้น** ไม่ผ่าน Javis (Cowork) ไม่เข้า git · **ทำบนคอมเท่านั้น** — รูปต้นฉบับอยู่ `.data/private/` บนคอมเครื่องเดียว แชทคลาวด์ไม่มีไฟล์นี้ (ตั้งใจ · รอบ B 27/09)

**ฝั่งเจ้าของทำต่อ (ทีละคลิก):**

18. เปิดไฟล์ `promptpay-qr.b64` ด้วย Notepad → **Ctrl+A** (เลือกทั้งหมด) → **Ctrl+C** (คัดลอก) — จะได้ตัวหนังสือบรรทัดเดียวยาว ๆ ขึ้นต้นด้วย `iVBORw0KGgo`
19. เข้า https://dashboard.render.com → คลิกบริการ **okami24**
20. เมนูซ้าย คลิก **Environment**
21. มองหาคีย์ `OKAMI24_PROMPTPAY_QR_BASE64` ในส่วน **Environment Variables**
    - **ถ้าเห็น** (ค่าว่าง) → คลิกช่อง Value ของบรรทัดนั้น แล้ว **Ctrl+V** วาง
    - **ถ้าไม่เห็น** (ปกติสำหรับ Blueprint ที่สร้างไว้ก่อน — Render ไม่เพิ่มคีย์ `sync: false` ให้เองตอนอัปเดต) → กด **+ Add Environment Variable** → Key พิมพ์ `OKAMI24_PROMPTPAY_QR_BASE64` (ตัวพิมพ์ใหญ่ทั้งหมด คั่นด้วยขีดล่าง) → Value **Ctrl+V**
22. กด **Save** → เลือก **"Save, rebuild, and deploy"** — **รอบเดียวจบ:** ได้ทั้งโค้ดล่าสุดจาก `main` และค่าใหม่พร้อมกัน ไม่ต้องแยก "merge+deploy" กับ "วางค่า" เป็นสองรอบ (พิสูจน์แล้ว 2026-09-07 — deploy `7e16bf6` ทำแบบนี้แล้ว QR ขึ้นทันที) · ถ้าเผลอเลือก "Save only" ค่าจะยังไม่ถูกใช้จนกว่าจะ deploy ครั้งหน้า
23. รอ deploy จบ (ราว 3–5 นาที) → เมนูซ้าย **Logs** → หาบรรทัดที่ขึ้นต้นด้วย `[qr]` (มีบรรทัดเดียวต่อการบูต 1 ครั้ง):

| เห็นบรรทัด | แปลว่า | ทำอะไรต่อ |
|---|---|---|
