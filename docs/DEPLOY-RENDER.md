# เอาเว็บ OKami24 ขึ้นออนไลน์ที่ Render (สิงคโปร์)

เขียน 2026-09-06 · เขียนให้คนที่อ่านโค้ดไม่ออกทำตามได้ · เจ้าของตัดสินใจเลือก Render สิงคโปร์แล้ว

**สิ่งที่เตรียมไว้ให้แล้วในโปรเจกต์ (ไม่ต้องทำอะไร):** ไฟล์ `render.yaml` คือใบสั่งงานที่บอก Render ว่าต้องตั้งค่าอะไรบ้าง
ถ้าใช้วิธี Blueprint ข้างล่าง Render จะอ่านไฟล์นี้แล้วกรอกช่องต่าง ๆ ให้เอง

---

## 0. ก่อนเริ่ม ต้องมีอะไรบ้าง

| ของ | สถานะ |
|---|---|
| บัญชี GitHub ที่มีโค้ดเว็บ (repo `okami24-web`) | มีแล้ว |
| โดเมน `okami24.store` ที่ Cloudflare | มีแล้ว |
| บัตรเครดิต/เดบิตที่จ่ายเงินต่างประเทศได้ | ต้องเตรียม |
| ไฟล์รูป QR พร้อมเพย์ | อยู่ในเครื่องแล้ว (ดูข้อ 5) |

ค่าใช้จ่ายที่จะเกิดขึ้น: ประมาณ **$7.25 ต่อเดือน (~250 บาท)** = ค่าเครื่อง $7 + ค่าดิสก์เก็บข้อมูล 1GB $0.25
Render จะตัดบัตรทุกเดือนจนกว่าจะยกเลิกเอง

---

## 1. สมัคร Render (5 นาที)

1. เปิด `render.com` → กด **Get Started** มุมขวาบน
2. เลือกสมัครด้วย **GitHub** → กด **Authorize Render**
3. หน้าจอถามว่าให้ Render เห็น repo ไหน → เลือก **Only select repositories** → ติ๊ก **okami24-web** → กด **Install**

**สำเร็จเมื่อ:** เห็นหน้า Dashboard ของ Render และมีปุ่ม **New +** อยู่มุมขวาบน

## 2. ผูกบัตร (3 นาที)

4. เมนูซ้าย → **Billing** → **Add payment method** → กรอกข้อมูลบัตร
5. **สำเร็จเมื่อ:** หน้า Billing แสดงเลข 4 ตัวท้ายบัตร (ยังไม่ถูกตัดเงินจนกว่าจะสร้างเครื่องจริง)

## 3. สร้างเครื่อง (10 นาที)

**วิธีที่ง่ายที่สุด — ให้ Render อ่านใบสั่งงานเอง:**

6. กด **New +** → เลือก **Blueprint**
7. เลือก repo **okami24-web** → เลือก branch **main** → กด **Connect**
8. Render จะอ่านไฟล์ `render.yaml` แล้วขึ้นสรุปว่าจะสร้างอะไร ตรวจว่าเห็น 4 อย่างนี้:
   - ชื่อ **okami24**
   - Region **Singapore**
   - Plan **Starter**
   - Disk **okami24-data** ขนาด **1 GB**
9. กด **Apply** / **Create** → Render เริ่มติดตั้งและ build (รอบแรกใช้เวลาประมาณ 5–10 นาที)

**สำเร็จเมื่อ:** สถานะขึ้นเป็น **Live** สีเขียว และกดลิงก์ `okami24-xxxx.onrender.com` แล้วเว็บเปิดได้จริง

> **ถ้า Blueprint ใช้ไม่ได้** (Render เปลี่ยนหน้าตาหรือฟ้อง error เรื่องไฟล์) ให้กด **New + → Web Service** แล้วกรอกมือตามตารางนี้
> ค่าทุกช่องคัดมาจาก `render.yaml` ตัวเดียวกัน:
>
> | ช่อง | ใส่ค่านี้ |
> |---|---|
> | Repository | okami24-web |
> | Branch | `main` |
> | Region | Singapore |
> | Runtime / Language | Node |
> | Build Command | `npm ci && npm run build` |
> | Start Command | `npm start` |
> | Instance Type | Starter ($7) |
> | Health Check Path | `/` |
> | Auto-Deploy | **Off** (ปิดไว้ก่อน) |
>
> แล้วเพิ่ม **Disk**: Name `okami24-data` · Mount Path `/var/data` · Size `1` GB
> แล้วเพิ่ม **Environment Variables** 5 ตัว:
>
> | Key | Value |
> |---|---|
> | `NODE_VERSION` | `22.11.0` |
> | `TZ` | `Asia/Bangkok` |
> | `SITE_URL` | `https://okami24.store` |
> | `OKAMI24_DATA_DIR` | `/var/data/app-data` |
> | `OKAMI24_BACKUP_DIR` | `/var/data/backups` |

### ทำไมค่าพวกนี้สำคัญ (อ่านผ่าน ๆ พอ)

- **Disk `/var/data`** = ที่เก็บออเดอร์ ถ้าไม่มีอันนี้ ออเดอร์จะหายทุกครั้งที่อัปเดตเว็บ
- **`OKAMI24_DATA_DIR` / `OKAMI24_BACKUP_DIR`** = บอกเว็บว่าฐานข้อมูลและไฟล์สำรองต้องไปนอนบนดิสก์ก้อนนั้น
- **`TZ`** = ให้เวลาบนเซิร์ฟเวอร์เป็นเวลาไทย ไม่งั้นชื่อไฟล์สำรองจะเพี้ยนไป 7 ชั่วโมง
- **หนึ่งเครื่องเท่านั้น** ห้ามเพิ่ม instance เป็น 2 เด็ดขาด เพราะฐานข้อมูลเป็นไฟล์เดียว ถ้ามี 2 เครื่องออเดอร์จะแตกเป็นสองชุด

## 4. ต่อโดเมน okami24.store (10 นาที)

10. ในหน้าเว็บของเราใน Render → **Settings** → หัวข้อ **Custom Domains** → **Add Custom Domain**
11. พิมพ์ `okami24.store` → เพิ่มอีกครั้งสำหรับ `www.okami24.store`
12. Render จะโชว์ค่าที่ต้องเอาไปใส่ที่ Cloudflare **ก๊อปเก็บไว้** (ปกติจะเป็น A record สำหรับชื่อโดเมนเปล่า และ CNAME สำหรับ www)
13. เปิด `dash.cloudflare.com` → คลิกโดเมน **okami24.store** → เมนู **DNS** → **Add record** → กรอกตามที่ Render บอกเป๊ะ ๆ
14. **ตอนนี้ให้กดรูปเมฆให้เป็นสีเทา (DNS only) ก่อน** — ถ้าเปิดเมฆส้มตั้งแต่แรก Render จะออกใบรับรองความปลอดภัยไม่ได้
15. รอจนหน้า Render ขึ้นเครื่องหมายถูกสีเขียว / คำว่า **Verified** และ **Certificate Issued** (ปกติ 1–10 นาที)
16. กลับไป Cloudflare → เมนู **SSL/TLS** → ตั้งโหมดเป็น **Full**
17. กลับไปหน้า **DNS** → กดรูปเมฆให้เป็น **สีส้ม** (เปิด proxy)

**สำเร็จเมื่อ:** พิมพ์ `okami24.store` ในมือถือแล้วเว็บขึ้น มีรูปกุญแจล็อกหน้า URL ไม่มีคำเตือนสีแดง

> เปิดเมฆส้มไว้ดีกว่าปิด: รูปภาพจะโหลดเร็วขึ้นสำหรับลูกค้าในไทย

## 5. เอารูป QR พร้อมเพย์ขึ้นเซิร์ฟเวอร์ (5 นาที · ทำหลังเว็บขึ้นแล้ว)

รูป QR **ไม่ได้อยู่ใน GitHub โดยตั้งใจ** (เป็นข้อมูลรับเงินของร้าน) เลยต้องส่งขึ้นไปเองครั้งเดียว

**ฝั่ง Javis เตรียมให้ก่อน** — สั่งในโปรเจกต์:

```bash
npm run qr:upload-text
```

จะได้ไฟล์ `_incoming/qr-upload/promptpay-qr.b64` = รูป QR ที่แปลงเป็นตัวหนังสือยาว ๆ

**ฝั่งเจ้าของทำต่อ:**

18. เปิดไฟล์นั้นด้วย Notepad → กด **Ctrl+A** (เลือกทั้งหมด) → **Ctrl+C** (คัดลอก)
19. ไปที่ Render → หน้าเว็บของเรา → **Environment** → **Add Environment Variable**
    - Key: `OKAMI24_PROMPTPAY_QR_BASE64`
    - Value: **Ctrl+V** (วางที่คัดลอกมา)
20. กด **Save Changes** → Render จะรีสตาร์ตเว็บให้เอง

**สำเร็จเมื่อ:** เปิดหน้าออเดอร์ที่ยังรอโอนเงินแล้วเห็นรูป QR ขึ้นมา (ถ้ายังไม่มีออเดอร์จริง ให้ Javis ตรวจใน log ว่าขึ้นบรรทัด `[qr] installed`)

> เว็บจะเขียนไฟล์ลงดิสก์ให้ครั้งเดียว และ**ไม่ทับของเดิม**ถ้ามีไฟล์อยู่แล้ว
> ถ้าวันหลังเปลี่ยน QR ใหม่ ให้บอก Javis — ต้องลบไฟล์เก่าบนดิสก์ก่อน ไม่งั้นของใหม่จะไม่ถูกใช้
> **ถ้าไม่มี QR เว็บไม่พัง** แค่โชว์เลขบัญชีให้ลูกค้าโอนแทน

## 6. ตรวจก่อนบอกว่าเปิดร้านได้ (สำคัญที่สุด)

ทำ 1 รอบหลังเว็บขึ้น เพื่อพิสูจน์ว่าออเดอร์ไม่หายตอนอัปเดตเว็บ:

21. สั่งซื้อทดสอบบนเว็บจริง 1 ออเดอร์ จดเลขออเดอร์ไว้
22. ใน Render กด **Manual Deploy** → **Deploy latest commit** (เท่ากับอัปเดตเว็บ 1 ครั้ง)
23. รอจนขึ้น Live แล้วเปิดหน้าออเดอร์เลขเดิม

**ผ่าน = ออเดอร์ยังอยู่** → ดิสก์ทำงานถูกต้อง เปิดขายได้
**ไม่ผ่าน = ออเดอร์หาย** → **หยุด อย่าเปิดขาย** แล้วบอก Javis ทันที (แปลว่าดิสก์ยังไม่ได้ผูกจริง)

24. ลบออเดอร์ทดสอบทิ้งก่อนเปิดขายจริง (บอก Javis)

## เรื่องที่ต้องรู้ไว้ ไม่ต้องทำอะไรตอนนี้

- **ตอนอัปเดตเว็บ เว็บจะดับสั้น ๆ ไม่กี่วินาที** เป็นเรื่องปกติของเครื่องที่มีดิสก์ติดอยู่ (Railway ก็เหมือนกัน)
- **Auto-Deploy ปิดไว้ก่อน** = โค้ดใหม่ที่ push ขึ้น GitHub จะยังไม่ขึ้นเว็บจนกว่าจะกด Deploy เอง
  เปิดทีหลังได้ที่ Settings เมื่อมั่นใจแล้ว
- **การสำรองข้อมูล** ทำเองอัตโนมัติทุก 6 ชั่วโมงตั้งแต่เว็บเปิด เก็บไว้บนดิสก์เดียวกันที่ `/var/data/backups`
  (60 ชุดล่าสุด) · Render ยังถ่าย snapshot ของดิสก์ให้ทุกวันอีกชั้น · รายละเอียด `docs/BACKUP.md`
- **แรม 512MB** ถ้า build ไม่ผ่านเพราะแรมไม่พอ ให้ขยับ Instance Type ขึ้นชั่วคราวตอน build แล้วลดกลับ
  (เจ้าของสั่งไว้แล้ว 2026-09-06 ว่าทำแบบนี้ ไม่ต้องเปลี่ยนโฮสต์)

## ถ้าอยากเลิกใช้ / ย้ายที่

ข้อมูลทั้งหมดอยู่ในไฟล์เดียว (`/var/data/app-data/okami24.db`) ก๊อปไฟล์นั้นออกมาก็ย้ายไปที่อื่นได้ทันที
ไม่มีอะไรผูกกับ Render เป็นพิเศษ นอกจากไฟล์ `render.yaml`
