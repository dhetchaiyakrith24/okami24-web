## เรื่อง 1 — deploy โดยไม่เปิดคอม (เจ้าของไม่ต้องกดทุกครั้ง)

ตัดทิ้งแล้ว: ทุกทางที่เจ้าของต้องกด "Deploy" ใน Render เองทุกครั้ง

| ทาง | ใครกด | ความเสี่ยง | ถอยกลับ | ความลับ / ใครถือ |
|---|---|---|---|---|
| **A (แนะนำ) GitHub Actions + Render deploy hook** — merge เข้า main แล้ว GitHub รันด่านเอง (tsc · eslint · verify:commerce · verify:catalog --full) ผ่านครบค่อยเรียก deploy hook · กรองด้วย `paths` ให้ deploy เฉพาะเมื่อ merge แตะของที่เว็บรัน (`src/` `public/` package · config) | ไม่มีใครกด — merge แล้ว deploy เอง | merge งานเอกสาร = ไม่ deploy (กรองพาธ) · ของไม่ผ่านด่าน = ไม่ deploy · `render.yaml` ไม่ต้องแก้ (`autoDeploy: false` คงเดิม — hook ใช้ได้แม้ปิด auto-deploy [เอกสาร render.com/docs/deploy-hooks]) | Render → Deploys → เลือกอันก่อน → Rollback [เอกสาร render.com/docs/rollbacks] หรือ revert PR แล้ว deploy ใหม่เอง | URL ของ deploy hook = ความลับ · เจ้าของสร้างครั้งเดียวใน Render แล้ววางใน GitHub Secrets · GitHub ปิดบังค่าในล็อกให้ [เอกสาร] · ไม่ผ่านแชทเลย |
| B Render "deploy เมื่อด่านผ่าน" (`autoDeployTrigger: checksPass` + `buildFilter`) [เอกสาร render.com/docs/blueprint-spec] | ไม่มีใครกด | ต้องแก้ `render.yaml` = เปลี่ยนคำตัดสินเจ้าของเรื่อง `autoDeploy: false` · ต้องมีด่านบน GitHub อยู่ดี (งานเท่า A) | Rollback ใน Render | ไม่มีความลับ |
| C ใส่ deploy hook ในช่อง "API credentials" ของ environment คลาวด์ ให้ Friday เรียกหลัง merge | Friday | ด่านก่อน deploy ขึ้นกับวินัยของ Friday ไม่มีเครื่องบังคับ · environment "Smog.z" อาจใช้ร่วมกับโปรเจกต์อื่น → ความลับของเว็บไปอยู่ในแชทโปรเจกต์อื่นได้ (กฎกลางข้อ 32) [เชื่อว่า] | Rollback ใน Render | อยู่ใน environment ของ claude.ai |

**สิ่งที่เจ้าของทำครั้งเดียวถ้าเลือก A** (Friday เขียน workflow ให้ในรอบถัดไป · รอบนี้ไม่แตะ token/Render):
1. Render → service okami24 → Settings → หา "Deploy Hook" → กดคัดลอก (ห้ามวางในแชท)
2. GitHub → รีโป okami24-web → Settings → Secrets and variables → Actions → New repository secret → ชื่อ `RENDER_DEPLOY_HOOK_URL` → วาง → Add secret
3. เห็นชื่อ `RENDER_DEPLOY_HOOK_URL` ในรายการ = สำเร็จ (ค่าจะไม่แสดงอีก)

## เรื่อง 2 — merge โดยไม่เปิดคอม

- นอกจาก `gh` มีทางทางการ: **เครื่องมือ GitHub ในแชทคลาวด์** (เปิด PR · merge PR ผ่าน GitHub App ของ Claude) — เห็นเครื่องมือในแชทนี้ [เชื่อว่า ใช้ได้ ยังไม่ได้ลอง merge] · ด่านบังคับบน main (`copy`) ยังบล็อกการ merge ผ่าน API จนกว่าจะเขียว [เอกสาร docs.github.com — protected branches] · และปุ่ม Create PR ในหน้าแชท [เอกสาร]
- ติดกฎ: 13.7 เขียนว่า "บนคลาวด์ไม่มี gh = ให้ Javis merge" · สคริปต์ `self-merge-check.js` ใช้ `gh`
- **คำแนะนำ:** 1 = ให้ Friday merge PR ที่ไม่แตะหน้าเว็บด้วยเครื่องมือ GitHub ในแชทคลาวด์ (เงื่อนไขเดิมของ 13.7 ทุกข้อ + ปรับสคริปต์ตรวจให้อ่านผ่านเครื่องมือนี้) · PR ที่แตะหน้าเว็บ = Javis เหมือนเดิม · 2 = คงเดิม Javis merge ทุก PR

## เรื่อง 3 — Chromium บนคลาวด์เปิดเว็บจริงไม่ได้ (ใบรับรอง)

- อาการ: `shot.js https://okami24.store/…` ได้หน้า "Your connection is not private" [ลองแล้ว] · เหตุ: เครือข่ายคลาวด์เซ็นใบรับรองใหม่ด้วย CA ของตัวเอง · curl/node เชื่อแล้ว แต่คลังใบรับรองของเบราว์เซอร์ (`/root/.pki/nssdb`) ว่าง 0 ใบ ทั้งที่คู่มือของเครือข่ายบอกว่าตั้งไว้แล้ว
- Friday ลองให้สคริปต์เชื่อเฉพาะ CA นี้ → **ระบบความปลอดภัยของแชทปฏิเสธ** → Friday หยุด ไม่ลองทางอื่น
- ผลกระทบ: ตรวจเว็บจริงหลัง deploy ด้วยภาพ/หน้าอังกฤษไม่ได้ (curl ได้) — งานในเครื่อง (build + ถ่ายภาพ + สแกน) ไม่กระทบ
- **คำแนะนำ:** 1 = Javis/เจ้าของแจ้ง Anthropic ว่าคลังใบรับรองเบราว์เซอร์ใน environment ว่าง (ให้แก้ที่ต้นทาง) · 2 = เจ้าของอนุญาตให้ Friday ตั้งให้ Chromium เชื่อเฉพาะ CA ของเครือข่ายคลาวด์ (เจ้าของเพิ่มสิทธิ์เองในการตั้งค่า — Friday ทำเองไม่ได้) · 3 = ตรวจเว็บจริงด้วย curl อย่างเดียวบนคลาวด์ (ภาพเว็บจริง = คอม)
