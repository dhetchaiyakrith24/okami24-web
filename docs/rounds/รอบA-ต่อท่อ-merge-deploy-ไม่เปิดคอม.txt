【ก้อน 1】Friday merge บนคลาวด์ (กฎเว็บ 13.7 + ด่านก่อน merge · ชั้น A)
 แนวคิด (คำแนะนำ Friday เรื่อง 2 ข้อ 1 · เจ้าของ 27/09 "ใช้ตามกฎ ให้ Friday merge"):
 · PR ที่ไม่แตะเว็บ = Friday merge เองบนคลาวด์ ภายใต้เงื่อนไขเดิมของ 13.7 ทุกข้อ (checker ผ่าน · ด่านเขียว ฯลฯ) · ด่านตรวจก่อน merge ใช้ได้ทั้งคอมและคลาวด์
 · PR ที่แตะเว็บ = Javis merge เหมือนเดิม
 · **PR ที่แตะ `.claude/` (settings · hook · สกิล · agent · กฎ) หรือ `.github/` (ตัว deploy) = ไม่ merge เอง ส่ง Javis** (Javis ถามเจ้าของ 1 บรรทัดก่อนกด — เจ้าของ 27/09)
 · **รายการ "แตะเว็บ" ชุดเดียว ใช้ทั้งด่าน merge (ก้อน 1) และตัวกรอง deploy (ก้อน 2)** — Friday เป็นคนกำหนดรายการ (อย่างน้อย `src/` `public/` ข้อมูลสินค้า package · config ที่เว็บรัน) ให้ครบในที่เดียว
 ผลที่ต้องได้:
 · 13.7 เขียนใหม่ให้ตรงของจริงทั้งคอมและคลาวด์ — บอกว่าทาง merge ทำอะไร ไม่ผูกชื่อเครื่องมือ (ชื่อเครื่องมือเปลี่ยนได้) · ไม่เก็บข้อความ "บนคลาวด์ไม่มี gh = Javis merge" ค้างคู่
 · merge จริง 1 ครั้งบนคลาวด์ กับ PR เล็กที่เป็นของจริงของรอบนี้ ไม่แตะเว็บ/`.claude/`/`.github/` (เช่น `docs/cloud-results/<รอบ>.md`) — ไม่ต้อง revert
 · ด่านก่อน merge แดง 1 ครั้งกับการแก้ที่แตะ `src/` — การแก้นั้นไม่ขึ้น GitHub และไม่เข้า main
 agent: rule-auditor → checker

【ก้อน 2】deploy อัตโนมัติหลังด่านผ่าน (ชั้น A · ไม่ deploy จริง)
 แนวคิด (คำแนะนำ Friday เรื่อง 1 ทาง A): merge เข้า main → GitHub รันด่าน (ชุดที่ Friday เห็นว่าพอ) → ผ่านครบ + merge แตะรายการ "แตะเว็บ" → เรียก deploy hook จาก GitHub Secret ชื่อ `RENDER_DEPLOY_HOOK_URL`
 ผลที่ต้องได้:
 · merge ที่ไม่แตะเว็บ = ไม่ deploy · ด่านตก = ไม่ deploy · ยังไม่มี secret = ข้ามพร้อมข้อความชัด ไม่ตกเงียบ
 · **workflow รันบน main ครั้งแรก = ตอน Javis merge PR ของรอบนี้เอง** → ต้องออกผล "ข้าม deploy" ที่เห็นได้ และ deploy ไม่ได้แม้ secret ถูกวางไว้แล้ว · ลองอะไรได้ก่อน merge ให้ลอง · บอกว่าเหลืออะไรที่พิสูจน์ได้ตอน Javis merge เท่านั้น
 · หลัง deploy อัตโนมัติ เจ้าของ/Javis เห็นจากมือถือได้ว่า deploy commit ไหน สำเร็จไหม (ยังไม่ลอง = บอก)
 · ขั้นตอนภาษาไทยทีละขั้นที่เจ้าของทำจากมือถือ (Render → Deploy Hook → GitHub Secrets) อยู่ใน `docs/CLOUD.md` + ในรายงาน · ติดป้าย [ยังไม่ได้ลองบนมือถือ] · เจ้าของทำ**หลัง Javis merge PR รอบนี้และเห็นผล "ข้าม" แล้ว**
 · ถอยกลับ: เขียนใน RECOVERY (Render Rollback · ปิด workflow)
 · ที่ Friday ควรเช็คก่อน: ด่านบน GitHub ที่มีอยู่แล้ว (`copy` ฯลฯ) ใช้ต่อหรือรวมได้ไหม · เวลาของ GitHub Actions พอไหม (1 บรรทัดในรายงาน)
 agent: checker

【ส่งมอบ】
 · commit แยกชนิดตาม 13.7 · push หลัง checker ผ่าน (ใกล้โควตาหมด = commit ลง branch ก่อนได้ แต่บอกในรายงาน) · doc-keeper อัปเดต §16
 · **จุดหยุด 1 = ขั้น 0 (อธิบายก่อนเริ่ม)** · **จุดหยุด 2 = ก่อน merge PR ของรอบ:** PR นี้แก้สิทธิ์ merge เอง + มี `.claude/`/`.github/` → Javis merge (ห้าม merge เอง) · ส่งลิงก์ compare + merge-pack + รายการ "เจ้าของต้องทำอะไร" (ขั้น Deploy Hook · ทำหลัง merge) + เรื่องที่ยังค้าง (เรื่อง → คำแนะนำ) ทีละเรื่อง
 · รายงานข้อ 4 ตอบตรง ๆ: (ก) หลังเจ้าของวาง secret แล้ว รอบฝังคลิป merge + deploy ได้โดยไม่เปิดคอมไหม (ข) PR ที่ลูกค้าเห็น — ตอนคอมปิด ใครกด merge ได้จากมือถือ (ทางที่ลองแล้ว vs ยังไม่ลอง) (ค) ยังติดอะไร ใครแก้
