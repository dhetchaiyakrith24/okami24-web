━━━ ส่วนที่ 1 · อัปแผน Render → Standard 2GB ━━━

【เหตุผล ให้เข้าใจตรงกัน ห้ามตีความเอง】
 - ไม่ใช่แค่แก้ OOM · เหตุผลหลักคือธุรกิจ: เจ้าของบรอดแคสต์ LINE เดือนละ 1 ครั้ง
   วันนั้นคนเข้า 2,000–6,000 คน และมาเป็นก้อนภายในชั่วโมงแรกหลังส่ง · Starter 512MB รับ spike แบบนั้นไม่ไหว
 - ผลพลอยได้: เงื่อนไข "เฝ้า Render Events 3 วัน" หลังแก้ OOM หมดความจำเป็น

【สิ่งที่ต้องแก้ — จุดเดียว】
 - `render.yaml` บรรทัด 18: `plan: starter` → `plan: standard`
 - **ห้ามไปกดเปลี่ยนแผนในแดชบอร์ด Render** — Cowork เปิดหน้าจอ Render ตรวจแล้ว 09/09
   หัวข้อบริการขึ้นป้าย "Blueprint managed" ชัดเจน = render.yaml คุมแผนจริง
   กดในแดชบอร์ดอาจถูก sync ทับกลับเป็น starter · แก้ที่ไฟล์เท่านั้น
 - **ตรวจก่อนแก้:** ยืนยันชื่อแผนที่ Render ใช้จริงในสเปก Blueprint ปัจจุบัน (standard = 2GB RAM)
   ถ้าชื่อไม่ตรงกับที่เขียนไว้นี้ **หยุด ถามเจ้าของ** ห้ามเดาชื่อแผน
 - ห้ามแตะบรรทัดอื่นในไฟล์: region · disk sizeGB · NODE_OPTIONS · env ที่เป็น sync:false

━━━ ส่วนที่ 2 · ปลดล็อก model ของ planner + designer ━━━

【สถานะและคำตัดสินของเจ้าของ】
 - ตอนนี้ `planner.md` และ `designer.md` เขียน `model: fable` ล็อกตายตัว
 - **โควตา Fable หมดแล้ว** เจ้าของขยับมาใช้ Opus เอง
 - **คำตัดสินเจ้าของ 09/09: ไม่ต้องการล็อก model ตัวไหนตายตัว ให้เลือกอิสระ พื้นฐานยังคงเป็น Opus-Fable**
   → จึง **ไม่ใช่** การเปลี่ยน `fable` เป็น `opus` (นั่นก็คือล็อกตายเหมือนเดิม แค่เปลี่ยนตัวล็อก)

【สิ่งที่ต้องทำ — ตรวจก่อน แล้วค่อยแก้】
 1. **ตรวจก่อนแก้ (บังคับ):** ยืนยันจากเอกสาร Claude Code ว่า
    ถ้า frontmatter ของ agent **ไม่มีบรรทัด `model:`** subagent จะสืบทอด model จากตัวหลักหรือไม่
    - ถ้าใช่ → ทำข้อ 2
    - ถ้าไม่ใช่ หรือหาคำตอบยืนยันไม่ได้ → **หยุด รายงานเจ้าของ ห้ามเดา**
 2. ลบบรรทัด `model: fable` ออกจาก `.claude/agents/planner.md` และ `.claude/agents/designer.md`
    - ลบทั้งบรรทัด ไม่ใส่อะไรแทน
    - **ห้ามแตะเนื้อหาอื่นในสองไฟล์นี้แม้แต่ตัวอักษรเดียว** — เนื้อคำสั่งของ agent เจ้าของพอใจอยู่แล้ว
    - ไฟล์ agent อีก 3 ตัว (checker · researcher · writer) **ห้ามแตะ**

【checkpoint】 git commit หรือ tag จุดกลับก่อนแก้ไฟล์ agent — เจ้าของสั่งให้เก็บ checkpoint ทุกงานที่ย้อนยาก

━━━ ตรวจก่อนส่ง ━━━
 - `git diff` ต้องมีแค่ 3 ไฟล์: `render.yaml` (1 บรรทัด) · `planner.md` (ลบ 1 บรรทัด) · `designer.md` (ลบ 1 บรรทัด)
   ถ้ามีมากกว่านั้น = ผิด หยุด รายงาน
 - tsc + checker 5 ช่อง ผ่านตามปกติ (รอบนี้ไม่ควรกระทบอะไร ถ้ากระทบ = มีอะไรผิด)
 - ทดสอบว่า planner หรือ designer ยังเรียกได้จริงหลังลบบรรทัด model (ยิงงานเล็ก ๆ ให้มันทำ 1 ครั้ง) — ถ้าเรียกไม่ขึ้น ให้ revert แล้วรายงาน

━━━ ส่งมอบ ━━━
 - commit แยกเป็น 2 ก้อน: config (`render.yaml`) และ agents (`.claude/agents/*`) — ห้าม `add -A` ก้อนเดียว
 - push → รายงาน 13.6 · **ห้าม merge ห้าม deploy** (Cowork/เจ้าของทำเอง)
 - ในรายงานบอกให้ชัดว่าหลัง merge ต้องทำอะไรต่อ: Manual Deploy (Auto-Deploy ปิดอยู่)
   และหลัง deploy ให้ดูที่ไหนเพื่อยืนยันว่าแผนขึ้นเป็น 2GB จริง

━━━ หลัง deploy — เจ้าของ/Cowork ตรวจ ━━━
 - Render → Events ยืนยันว่า instance ใหม่ขึ้นด้วยแผนใหม่
 - หัวข้อบริการต้องเปลี่ยนจาก "okami24 · Node · Starter" เป็น "Standard"
 - Metrics: เพดาน memory ต้องขยับจาก ~512MB เป็น ~2GB
 - เว็บจริง: okami24.store ตอบ 200 · /products 200 · /cart 307 → /products?order=line (ข้อ 43 ยังปิดขายตามเดิม)
