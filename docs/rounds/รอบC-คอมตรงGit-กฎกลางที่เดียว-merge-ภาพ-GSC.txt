เจ้าของกังวลที่สุด = "ของอยู่ 2 ที่แล้วไม่ตรงกัน โหลดไม่ครบ ข้อมูลไม่ตรง"

1. คอมกับ GitHub ต้องตรงกันเสมอ — ลงมือแก้
   วันนี้เปิดแชทบนคอมตอนโฟลเดอร์ช้ากว่า GitHub 16 PR → แชทโหลดกฎเก่าตั้งแต่แรก ต้องเปิดแชทใหม่
   ต้องได้: เปิดแชทบนคอมเมื่อไหร่ก็ได้ของล่าสุดก่อนโหลดกฎ โดยเจ้าของไม่ต้องทำอะไร · ทำไม่ได้ = มีตัวเตือนดัง ๆ ทันทีว่าล้าหลัง
   รวมถึงไฟล์คำสั่งและไฟล์งานที่รอบใหญ่บนคอมใช้ ต้องตรงกับ Git · ลองจริงให้เห็นทั้งตอนตรงและตอนล้าหลัง

2. กฎกลางอ่านจากที่เดียว — เจ้าของไม่เอาสำเนาในแต่ละรีโปแล้ว
   คำเจ้าของ: "แก้ครั้งเดียว ทุกโปรเจกต์เห็นหมด ไม่ต้องสำรองซ้ำ กลัวโหลดไม่ครบ ทับซ้อน เสียเวลาอ่านซ้ำ"
   ต้องได้: ทุกแชท (คอม + คลาวด์ · เว็บ + การ์ตูน) อ่านกฎกลางจาก smogz-rules ตัวเดียว · อ่านไม่ได้ = หยุดบอก ห้ามทำงานต่อแบบไม่มีกฎ
   ลำดับ: ลองให้ผ่านทั้งคอมและคลาวด์หลายครั้งก่อน (ระหว่างลองเก็บสำเนาไว้เป็นกันชน) → ผ่านแล้วค่อยลบสำเนา · ไม่ผ่าน = คงสำเนา + ตัวเตือนเมื่อสำเนาไม่ตรงต้นฉบับ
   บอก: ต้องใช้อะไร · ข้อเสียคืออะไร · ของในรีโปเว็บที่ต้องลบหรือแก้ · ฝั่งการ์ตูนต้องทำอะไร (เขียนเป็นรายการให้ Javis ส่งต่อ ไม่แก้เอง)
   ของใน smogz-rules ถ้าต้องแก้ = เปิด PR ให้ Javis merge หลังเจ้าของอนุญาต

3. กฎ merge ใหม่ (เจ้าของเคาะ 27/09 · แทนของเดิมใน 13.7)
   Friday merge ทุกงาน รวมงานที่ลูกค้าเห็น · งานเล็ก = merge เลยแล้วรายงาน · งานใหญ่ = บอกเจ้าของสั้น ๆ ก่อน merge เผื่ออยากตรวจ · Javis merge เฉพาะเมื่อเจ้าของสั่ง
   Friday เสนอว่า "เล็ก/ใหญ่" แบ่งยังไง แล้วเขียนลง 13.7 + site-paths ให้ตรงกัน
