ทิศทาง (คำเจ้าของ 24/09)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
งานรูปค้างมานานเพราะเจ้าของยกไปทำอย่างอื่นก่อน ตอนนี้กลับมา · หลักคือ **"สร้างมาตรฐานก่อน แล้ววัดว่าอันไหนได้ไม่ได้ หาได้ไหม สร้างได้ไหม"**
ปัญหาที่เจ้าของเห็นเอง (ให้ยืนยันด้วยการวัด ไม่ใช่รับมาเป็นข้อสรุป):
- รูปบางรูปขอบแตก ไม่ชัด ไม่ได้มาตรฐานเว็บ
- สินค้าที่มีหลายสี/หลายกลิ่น (เช่น M Bar / Marbo) มีรูปเดียว สีอื่นยังไม่ได้ลง — แบรนด์อื่นก็เป็น
- สินค้าหลายรายการถูกซ่อนเพราะยังหารูปไม่ได้ เจ้าของไม่แน่ใจว่าซ่อนอะไรไว้บ้าง
- หัวข้อ "ส่วนต่าง ๆ ของเครื่อง" (anatomy) บางแบรนด์ยังเป็นรูปต้นแบบที่เราวาดเอง

**มาตรฐานอ้างอิง = ชุดรูป UWELL Caliburn G5 บนเว็บเราตอนนี้** (เจ้าของ 24/09: "ต่ำกว่านี้ได้นิดหน่อย ไม่ติด") · มาตรฐานเดิมใน `docs/IMAGE_SPEC.md` ยังใช้ (ตอนนั้นอ้าง G4 → อัปเดตเป็น G5)

ต้องได้อะไร
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) มาตรฐานที่วัดได้จริง — อิง `docs/IMAGE_SPEC.md`
   - แก้ในสเปคได้อย่างเดียว: ตัวอ้างอิง G4 → G5 (คำเจ้าของ 24/09) · เกณฑ์อื่นที่จะเพิ่ม/เปลี่ยน เขียนเป็นหัวข้อ "เสนอ รอเจ้าของเคาะ" ห้ามเขียนเป็นกฎ
   - อะไรวัดด้วยสคริปต์ได้ (ขนาด · ความคม · ขอบ/alpha · พื้นหลัง · ขนาดไฟล์) กับอะไรต้องใช้ตา (designer) — แยกให้ชัด
   - "ต่ำกว่า G5 ได้นิดหน่อย" ต้องแปลงเป็นเกณฑ์ที่วัดซ้ำได้ Code เสนอตัวเลข (ไม่ใช่ Cowork ตั้ง) · ชั้นไหนที่ชุด G5 บนเว็บไม่มีให้อ้าง (เช่น hero · anatomy) รายงานว่าไม่มี ห้ามเดาเกณฑ์
   - เกณฑ์เดิมที่ขัดกับคำเจ้าของวันนี้ (ถ้ามี) ยกมาให้เห็น ไม่แก้เงียบ ๆ
2) ตรวจรูปทุกรูปในร้านกับมาตรฐานข้อ 1 — ทั้งสินค้าที่โชว์และที่ซ่อน · ทุกชั้น (การ์ด · สีเครื่อง/รส · แกลเลอรี · anatomy · hero)
   - `docs/IMAGE_AUDIT.md` เดิมนับไว้ 06/09 ล้าสมัยแล้ว → นับใหม่ทั้งหมด ไม่ต่อยอดตัวเลขเก่า
   - ผลต่อรูป: ค่าวัดดิบ (px · ไฟล์ · alpha ฯลฯ) เก็บแยกจากคำตัดสิน ผ่าน/ตก — ถ้าเจ้าของเปลี่ยนเกณฑ์จะจัดใหม่ได้โดยไม่วัดซ้ำ
3) รายการสินค้าที่ซ่อนอยู่ทั้งหมด — ตัวไหน · ซ่อนเพราะอะไร · ขาดรูปอะไรบ้างถึงจะเปิดได้
4) ทุกช่องว่าง จัดเป็น 4 ประเภท พร้อมหลักฐาน:
   - **หาได้** — มีรูปทางการจากผู้ผลิต/ตัวแทน (ระบุ URL · ขนาดที่เห็น · ผ่านเกณฑ์ไหม) — เจ้าของยืนยัน: รูปทางการใช้ได้ ผู้ผลิตปล่อยให้ใช้
   - **ประกอบเองได้** — จากรูปทางการรายสี (เช่น รูปรวมทุกสี ตามกฎ IMAGE_SPEC ข้อ 5)
   - **ต้องสร้างใหม่** — ไม่มีต้นฉบับทางการที่ใช้ได้เลย (บอกว่าสร้างด้วยอะไรได้บ้าง เวลาเท่าไหร่ คุณภาพจะถึง G5 ไหม · วิธีที่ IMAGE_SPEC ห้ามอยู่ เช่น upscale/AI ให้แยกไว้ในข้อ 5 ทาง (ข) เท่านั้น)
   - รูปทางการที่ต้องโหลดมาวัด เก็บนอก `public/` และนอกโฟลเดอร์รูปต้นทาง (เช่น `_incoming/round11a/samples/`) หรือดูขนาดจาก HTTP header ก็ได้
   - **ทำไม่ได้/ไม่คุ้ม** — บอกเหตุผล
5) หัวข้อ anatomy ("ส่วนต่าง ๆ ของเครื่อง"): รายการว่าแบรนด์/รุ่นไหนใช้รูปต้นแบบที่วาดเอง · แต่ละตัวมีรูปทางการมาแทนได้ไหม
   - เจ้าของสนใจ 2 ทาง: (ก) ใช้รูปทางการ (ข) สร้างเป็นของเราเอง เช่น 3D/AI — ให้เสนอทั้งสองทางแบบเทียบกัน: ผลที่ได้ · เวลา · ความเสี่ยงเรื่องความตรงกับของจริง · แนะนำทางไหนก่อน
   - **ทาง (ค) เจ้าของเสนอ 25/09: ภาพลายเส้นจากคู่มือผู้ผลิต** (เช่นหน้า "Product Introduction" ในคู่มือ UWELL Caliburn G4 PRO ที่มีภาพเครื่องพร้อมเลขชี้ส่วน) มาใช้แทนภาพวาดของเราในหัวข้อ anatomy — เจ้าของชอบว่า "ดูล้ำ" · ใส่ในตารางเทียบด้วย:
     รุ่นไหนมีคู่มือที่มีภาพแบบนี้ (ต่อรุ่น ต้องตรงรุ่น — บทเรียนรอบข้อมูล: สำเนาคู่มือผิดรุ่น 3 ฉบับ) · ที่มาของไฟล์ต้องสืบกลับเว็บผู้ผลิตได้ (myuwell.com/download ฯลฯ) หรือสแกนคู่มือกระดาษในกล่องที่ร้านมี (เจ้าของมีของจริง) · 
     ภาพลายเส้นดำบนขาวจะเข้ากับธีมมืดของเว็บยังไง (ใช้ตรง / กลับสี / วาดตามเป็นเวกเตอร์) และอ่านออกไหมที่จอ 390 · รุ่นที่ไม่มีคู่มือแบบนี้จะดูไม่เข้าชุดไหม · ชื่อส่วนที่ชี้ต้องตรงกับสเปก verified (ด่านรอบข้อมูล)
     · ไฟล์ PDF คู่มือ G4 PRO (ชื่อขึ้นต้น 2070301888-00-000) ที่เปิดอยู่ในเครื่องเจ้าของ อยู่ในโฟลเดอร์งานของ Code เอง เจ้าของไม่รู้ว่ามาจากไหน → บอกที่มาของไฟล์นี้ในรายงาน
   - **ทาง (ข) เครื่องมือที่มีแล้ว (เจ้าของ 25/09): เจ้าของสมัคร Higgsfield (higgsfield.ai) รายเดือน** — ใส่รูปอ้างอิงได้ · มีตัวสร้างรูปและ 3D · ข้อตกลงการใช้งานให้ใช้เชิงพาณิชย์ได้ [เชื่อว่า Cowork อ่านผ่านตัวดึงหน้าเว็บ ให้ Code/เจ้าของเช็คเอง] · Code/Cowork ล็อกอินบัญชีเจ้าของไม่ได้ → ถ้าเสนอทางนี้:
     Code เลือกรูปอ้างอิง (รูปทางการ/รูปจริงของร้าน) + เขียนคำสั่ง (prompt) ให้เจ้าของก๊อปไปรันเอง · ทดลองแค่ 1–2 รุ่น · ตัวหนังสือ/เลขชี้ส่วนไม่ให้ AI ใส่ในรูป (AI เขียนตัวอักษรเพี้ยน และต้องเป็น 3 ภาษา) ให้เว็บวางทับเอง ·
     รูปที่ได้ต้องเทียบกับของจริงทีละส่วน (ปุ่ม · จอ · ช่องลม · ช่องชาร์จ · หัวพอต · โลโก้) ผิดตำแหน่ง/เกิน/ขาด = ใช้ไม่ได้ · ภาพต้องอ่านออกว่าเป็นภาพประกอบ ไม่ใช่รูปถ่าย
   - ห้ามสร้างรูป AI/3D ลงเว็บในรอบนี้ — เป็นเรื่องรสนิยมและขัดกับ IMAGE_SPEC ข้อ 2 (รูปของจริงเท่านั้น) เจ้าของต้องเคาะก่อน (13.4 #6)
6) ข้อเสนอลำดับทำใน 11B — เรียงตามผลต่อลูกค้า (คำเจ้าของ 23/09: กำไรดีสุด = Marbo (SALTHUB) · UWELL · VOOPOO · ตัวขายดี = ชุดเดิม 08/09 ใน HANDOFF/BSOT) · แบ่งก้อนที่พอดีแชทเดียว · เก็บทั้งหมดใน `docs/IMAGE_AUDIT.md` ฉบับใหม่ (แทนของเดิมทั้งฉบับ ของเดิมย้าย `docs/archive/`)
