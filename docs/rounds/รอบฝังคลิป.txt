1) ต้องได้อะไร (ผล ไม่ใช่วิธี)
ก. คลิปร้านที่ติดหน้า 1 ของ Google อยู่บนหน้าเว็บที่ตรงคีย์ของมัน — คู่ตั้งต้นข้างล่าง (ที่มา = docs/SEO_LANDSCAPE.md ตาราง clip↔key รอบ 10C · ถ้าในไฟล์ไม่มีลิงก์คลิป ให้หาจากหน้าช่องของร้านบน YouTube · เปลี่ยนคู่ได้เฉพาะเมื่อมีหลักฐานในไฟล์นั้น เพราะบนคลาวด์ค้น Google ไม่ได้):
   - Marbo 54K → บทความเลือกกลิ่น Marbo (choosing-a-marbo-flavor) และ/หรือ m-bar-9k
   - คอยล์พอต → coil-and-pod-maintenance
   - พอตใช้แล้วทิ้ง → /products/disposables
   - m bar → /brands/salthub
   - pod system ตัวไหนดี → choosing-your-first-pod-system
   - หัว RELX Creator → muro-connector-20k
   คลิปใช้ได้เฉพาะช่องของร้าน: @OKM_24 (หลัก) · @PODSYSTEM-OKAMI-II (สำรอง) · @OKMYARZ
   รุ่นในคลิปต้องยังมีใน catalog ตอนนี้ — ไม่มีแล้ว = ไม่ฝัง แล้วรายงาน
ข. ข้อมูลวิดีโอที่ Google อ่านผ่าน: ตอนนี้ GSC ขึ้น "วิดีโอ: ตรวจพบรายการที่ไม่ถูกต้อง" บน 7 หน้าสินค้า (pod-159 · pod-180 · m-bar-9k · m-bar-10k · m-switch-kit · joiway-f4 · relx-smash-go-12k) — หาต้นเหตุเอง แก้ที่กลไก ไม่ใช่ทีละหน้า · ก่อน merge: ทุกหน้าที่มีคลิป (เก่า+ใหม่) เทียบกับข้อกำหนด VideoObject ของ Google ทีละช่อง (บนคลาวด์เปิดเครื่องตรวจของ Google ไม่ได้ — บอกในรายงานว่าเทียบจากอะไร) · หลังขึ้นเว็บ Javis ตรวจด้วยเครื่องมือ Google + กด "ตรวจสอบการแก้ไข" ใน GSC เอง · ถ้าการแก้กลไกทำให้ผลของ 7 หน้าเส้นฐาน (ข้อ 2) เปลี่ยน = เว้นหน้านั้นไว้ แล้วรายงาน
ค. หน้าไม่ช้าลงบนมือถือ — คลิปต้องไม่โหลดหนักตั้งแต่เปิดหน้า (เป้าเว็บเร็วมือถือยังอยู่ · Lighthouse ตอนนี้ 62–70) · วัดก่อน/หลังบนหน้าที่ได้คลิปอย่างน้อย 2 หน้า ด้วย build เดียวกันวิธีเดียวกันทั้งสองครั้ง ก่อน merge
ง. หน้า EN/ZH: คลิปขึ้นได้ทุกภาษา · ข้อความที่เว็บเราเขียนรอบคลิป (หัวข้อ · คำอธิบาย · ชื่อที่อ่านด้วยโปรแกรมอ่านจอ) = ภาษาของหน้านั้น · ชื่อคลิปที่ตัวเล่นของ YouTube แสดงเองเป็นไทยได้ (นอกการควบคุม) — ถ้าด่าน thai-leak จับตรงนี้ ให้ด่านรู้จักข้อยกเว้นนี้แบบแคบที่สุด · ข้อมูลวิดีโอสำหรับ Google เป็นไทยตาม HTML ฝั่งเซิร์ฟเวอร์ · บทความไทยล้วนยังซ่อนบน EN/ZH ตามเดิม · มีทางที่ดีกว่านี้ = เสนอได้
จ. ดูดีบนมือถือ 390 และจอคอม 1440 — ถ่ายภาพก่อน/หลังด้วย Chromium บนคลาวด์ (รอบ C ทำให้ใช้ได้แล้ว) · designer ตรวจ · ใช้ tier-b-proof ตอนปิด + merge-pack ก่อน merge
ฉ. (ถ้าอยู่หน้าเดียวกับที่แตะ และถอยแยกได้) ของที่ designer เห็นในรอบมือถือ (ดู docs/cloud-results/mobile-round-questions.md เรื่อง 11): หัวข้อบทความที่ 390 สองบรรทัดชิดกัน · ปุ่มดำหน้า G4 จมพื้นมืด (ถ้าเป็นหน้าเส้นฐาน = ห้ามแตะ) · การ์ด "สินค้าที่คุณอาจสนใจ" ที่ 390 รูปชิดป้าย "8 สี"/หัวใจ — ไม่ทำก็ได้ ให้บอกเหตุผล

2) ห้าม (ของที่ฝ่าฝืนแล้วเสียหาย)
- 7 หน้าเส้นฐาน SEO ห้ามฝังคลิป/แตะ <title> จน 05/10: drag-6 · drag-s3 · caliburn-g5-lite-se · m-bar-15k · caliburn-g5 · caliburn-g5-lite · argus-g4 · บทความห้ามลิงก์ไป m-bar-15k จน 05/10
- ตะกร้ายังปิด ห้ามเสนอเปิด
- ห้ามใส่ลิงก์เว็บลงใน YouTube หรือ LINE · ห้ามข้อความสุขภาพ/เลิกบุหรี่/ปลอดภัยกว่า · ห้ามข้อความซ่อนเพื่อ SEO
- ห้ามแก้ชื่อ/คำอธิบายคลิปใน YouTube (เจ้าของทำเอง) — ถ้ามีข้อเสนอ ใส่ในรายงาน

3) merge + ขึ้นเว็บ (13.7 ใหม่)
- รอบนี้เปลี่ยนหน้าตาเว็บ = งานใหญ่ → บอกเจ้าของสั้น ๆ ก่อน merge (PR ไหน · เปลี่ยนอะไร · ภาพก่อน/หลัง · ถอยยังไง) แล้วรอเจ้าของตอบ ยังไม่ตอบ = ยังไม่ merge
- นี่คือครั้งแรกที่ merge งานแตะเว็บแล้วขึ้นเว็บเองผ่าน GitHub Actions → หลัง merge ตรวจให้เห็นเอง: Actions ขึ้น "DEPLOY started" และรันผ่าน · เว็บจริง okami24.store เสิร์ฟของใหม่แล้ว (คลิปขึ้นบนหน้าที่ตั้งใจ) · ถ้าไม่ขึ้นเว็บเองภายในเวลาที่สมควร หยุดแล้วรายงาน (ห้ามกด deploy ทางอ้อม) · สถานะบน Render Javis เปิดดูเอง
- หลังขึ้นเว็บ: บอกรายชื่อหน้าที่ควรให้ Google ตรวจใหม่ (หน้าใหม่/หน้าที่ข้อมูลวิดีโอเปลี่ยน) — Javis เป็นคนกดขอใน GSC

4) พิสูจน์ให้พอดี
- โดเมนไหนที่ต้องใช้แล้วเครือข่ายคลาวด์บล็อก (เช่น รูปย่อคลิป) = รายงาน ไม่เดา
- พิสูจน์เฉพาะหน้าที่แตะ + ตัวอย่างหน้าที่ไม่ควรเปลี่ยนพอจับผิดได้ ไม่ต้องสแกนทั้งเว็บเต็มชุดถ้าไม่จำเป็น
- ทุกคำว่า ผ่าน/ครบ/0 ต้องมีตัวเลขจากการตรวจจริง · ที่ไม่ได้ตรวจให้เขียนว่าไม่ได้ตรวจ

5) รายงานปิดรอบ (ไทย สั้น 4 หัว: ทำอะไร · ตรวจยังไง · ติดอะไร/ตัดสินเอง · ต้องตัดสินใจ)
- ตารางหน้า → คลิปที่ฝัง (ลิงก์คลิป · ช่อง · รุ่นยังมีใน catalog ไหม)
- ต้นเหตุข้อมูลวิดีโอไม่ผ่าน + แก้ยังไง + ผลตรวจ
- ความเร็วก่อน/หลัง · ภาพก่อน/หลัง 390/1440 (ให้เจ้าของเปิดดูบนมือถือได้)
- EN/ZH เห็นอะไร
