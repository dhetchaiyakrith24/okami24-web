== สิ่งที่ขอ ==
1. วัดเวลาจริงของ 3 รอบล่าสุด: รอบเครื่องมือ · รอบข้อมูล 2 · รอบก่อนหน้านั้น 1 รอบ
   แหล่งวัด: เวลาในบันทึกแชทของ Claude Code บนเครื่อง (ไฟล์ .jsonl ของโปรเจกต์นี้) · git log · เวลาไฟล์ใน _incoming/<รอบ>/ · docs/ROUND_COST.md
   ถ้าอ่านบันทึกแชทไม่ได้ บอกตรง ๆ แล้วใช้แหล่งที่เหลือ

2. ตารางเวลาต่อรอบ แยกตามช่วงงาน ตัวอย่างช่วง (เพิ่ม/แยกได้ตามที่เจอจริง):
   อ่านไฟล์ตอนเปิดรอบ · วางแผน · ลงมือแก้ · build (กี่ครั้ง × กี่นาที) · test server · ถ่ายภาพ (กี่ภาพ × กี่วินาที)
   สแกนทั้งเว็บ (กี่หน้าจอ × เวลา) · verify ชุดเต็ม · เรียก agent (ตัวไหน กี่ครั้ง ครั้งละกี่นาที)
   ตรวจซ้ำหลังแก้ (13.5) · เขียนเอกสารปิดรอบ · รอเจ้าของตอบ · ช่วงว่าง/รอโดยไม่ได้ทำอะไร
   ใส่ป้ายทุกตัวเลข: [ตรวจแล้ว] วัดจากของจริง / [เชื่อว่า] ประมาณ

3. 5 อันดับที่กินเวลามากสุด พร้อมตอบทีละข้อว่า
   - มาจากอะไร: กฎข้อไหน (TEAM_RULES / ไฟล์กลาง / CLAUDE.md) · บรรทัดไหนในไฟล์คำสั่งของ Javis · agent/สกิลตัวไหน · สคริปต์ตัวไหน · ข้อจำกัดของเครื่อง/Windows
   - จำเป็นจริงไหม: ถ้าตัดหรือลดแล้ว ความเสี่ยงคืออะไร (เว็บพังได้ไหม ลูกค้าเห็นอะไรผิดได้ไหม)

4. เรื่องที่ Javis อยากให้ดูเป็นพิเศษ (ตอบว่าใช่/ไม่ใช่ พร้อมหลักฐาน)
   - ไฟล์คำสั่งของ Javis ยาวเกิน/สั่งวิธีละเอียดเกินไหม (รอบเครื่องมือ ~25 KB · Friday เคยรายงานว่าก้อน 2 สั่งวิธีเกินจำเป็น)
   - ไฟล์ที่ต้องอ่านทุกแชท/ทุกรอบรวมกันยาวแค่ไหน (CLAUDE.md · .claude/rules · TEAM_RULES · HANDOFF §16 · สกิลที่โหลด) นับเป็นขนาดไฟล์
   - แชทยาว (รอบเครื่องมือขึ้นไปถึง ~559k) ทำให้แต่ละขั้นช้าลงไหม · ควรย้ายแชทเร็วกว่านี้ไหม
   - กฎตรวจซ้ำ (checker ทุกก้อน · ตรวจซ้ำเมื่อไฟล์เปลี่ยนหลังตรวจ) ทำให้วนหลายรอบไหม
   - งานที่ทำทีละอย่างแต่ทำพร้อมกันได้ (เช่น ถ่ายภาพระหว่าง build · agent หลายตัวพร้อมกัน)
   - build ซ้ำโดยไม่จำเป็น · ถ่ายภาพ/สแกนมากเกินที่ต้องใช้ตัดสินใจ
   - การตั้งค่าของ Friday เอง (รุ่นโมเดล · ระดับการคิด) — แค่บอกว่าใช้อะไรอยู่ ห้ามเปลี่ยน

5. ข้อเสนอลดเวลา เรียงตาม "เวลาที่ประหยัดได้ × ความเสี่ยงต่ำ"
   แต่ละข้อ: แก้อะไร (กฎ/คำสั่ง/สกิล/สคริปต์/วิธีทำงาน) · ประหยัดได้ประมาณเท่าไหร่ต่อรอบ · เสียอะไร · ถอยกลับได้ไหม
   แยกให้ชัด: ข้อที่ Javis แก้ได้เองในไฟล์คำสั่ง · ข้อที่ต้องแก้กฎ (ต้องขอเจ้าของก่อน) · ข้อที่เป็นข้อจำกัดของเครื่อง แก้ไม่ได้
   ห้ามลงมือแก้ตามข้อเสนอ — เสนออย่างเดียว
