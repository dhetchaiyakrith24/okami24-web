รอบเก็บบ้าน Friday (เว็บ) — ถามพี่ก่อน ตรวจก่อน แล้วค่อยแก้ · ฉบับ 01/10 (รวมของพี่ + Friday + Javis + ผู้ตรวจอิสระ 01/10 เป็นเรื่องเดียว)
เปิดรอบ: อ่าน docs/HANDOFF.md §16 ก่อน แล้ว /round-open
เมื่อไหร่: หลังรูปชุดนี้จบ ก่อนขึ้นสินค้าตัวใหม่ (พี่ 30/09)
ทุกข้อในไฟล์นี้แย้งได้ — มีทางที่ดีกว่าบอกพี่ได้เลย

【เป้า】
บ้านฝั่ง Friday เคลียร์จริง — กฎ คู่มือ สกิล agent HANDOFF บทเรียน ความจำ เอกสาร ไฟล์งาน · ไม่ซ้ำ ไม่ขัด ไม่รก · แชทใหม่อ่านเร็ว งานเดินเร็ว
พี่ห่วงที่สุด 3 เรื่อง:
1. "ไม่ใช่แก้แล้วงานเละ" → รู้ก่อนว่าติดตรงไหน ช้าตรงไหน แล้วค่อยแก้
2. "ไม่มัดมือชก" → รอบนี้ต้องทำให้ Friday มีอิสระมากขึ้น ไม่ใช่มีกฎมากขึ้น · กฎ/ด่าน/ขั้นตอนที่บังคับ "วิธีทำ" โดยไม่ได้กันของพังจริง = เสนอตัดหรือผ่อน ·
   ที่เหลือ Friday ใช้สกิล สมอง ความคิดสร้างสรรค์ และพลังได้เต็มที่
3. "เขียนได้ แต่ต้องจัดการของเก่าด้วย" → ของใหม่เรื่องเดียวกัน = เขียนทับแล้วเกลา หรือลบแล้วเขียนใหม่ ไม่เก็บคู่ · ไม่เขียนเติมจนล้น ·
   พี่เชื่อว่าถ้าจัดการของเก่าและเรียบเรียงดี ของสำคัญยังอยู่ ไฟล์จะไม่โตเกินจำเป็นเอง (ไม่ต้องมีด่านวัดขนาด)

【ลำดับที่พี่อยากได้】
1. ถามพี่ก่อน — ชุดคำถามแบบเลือกตอบ ว่าอยากเก็บบ้านแบบไหน อะไรสำคัญ อะไรห้ามแตะ
2. ตรวจก่อนแก้ (ยังไม่แก้อะไร) — ใช้ผลของผู้ตรวจอิสระข้างล่างเป็นจุดเริ่ม ไม่ต้องไล่ใหม่ตั้งแต่ศูนย์ แล้วรายงานให้พี่เคาะ:
   ติดตรงไหน · ช้าตรงไหน · จะเพิ่ม/ลด/แก้อะไร · เป้าหลังเก็บเป็นตัวเลข · ความเสี่ยงและวิธีถอย
3. ลงมือตามที่พี่เคาะ
4. ทำ /เก็บบ้าน ของ Friday (สกิล) ให้พี่เรียกซ้ำได้ — เสนอให้พี่ดูก่อนบันทึก

【ที่เห็นแล้ว — ผู้ตรวจอิสระ 01/10 (อ่านไฟล์จริงบน GitHub) + Javis + ร่างเดิมของ Friday】
ก. กฎโตเร็ว (ผู้ตรวจ: 4 วัน TEAM_RULES +47% · LESSONS +59% · สกิลปิดรอบ +68% · แชทเว็บโหลดกฎ ~47k ตัวอักษร เทียบการ์ตูน ~30k ·
   agent 10 · สกิล 7 · สคริปต์ ~65) · Javis นับ 01/10: TEAM_RULES 27,654 · LESSONS 30,745 ตัวอักษร (ยังโตในวันเดียวกัน)
   → ตัดข้อที่เหลือแค่ตัวชี้ (13.8 · 13.9 · 13.10 ข้อ 2–14 เก็บไว้แค่กันเลขเลื่อน) · ตัดประวัติในเนื้อกฎ ("เจ้าของเคาะ …" 18 ที่ใน TEAM_RULES · git มีครบ) ·
     รวบตัวชี้หลายชั้นเหลือชั้นเดียว · ความหมายกฎเท่าเดิม และพิสูจน์ได้ว่าไม่มีกฎหายเงียบ (เช่นตาราง "ก่อน → หลัง → ไปอยู่ไหน")
ข. ข้อห้ามสำคัญเป็นแค่ข้อความ — เว็บมี hook ตัวเดียว (ซิงค์ตอนเปิดแชท) · ห้ามปิด node ทั้งเครื่อง (เคยเกิดจริง) · force push · แตะ render.yaml / .env* / สวิตช์ตะกร้า
   → ย้ายข้อห้ามที่กันพังจริงไปเป็นตัวล็อกจริง แล้วลบข้อความนั้นทิ้ง (อ่านน้อยลง อิสระมากขึ้น) · แบบอย่างที่พิสูจน์แล้ว = รีโปการ์ตูน
   → ไม่เอาระบบตั๋วขออนุมัติ (พี่: แผนที่คุยกันไว้แล้ว = อนุญาตแล้ว · ตั๋ว = ขั้นตอนเกินจำเป็น) · Friday ออกแบบเองว่างานที่อยู่ในแผนผ่านตัวล็อกยังไง
ค. ชุดตรวจแบบเบา (13.12) ยังมี 6 ขั้นย่อย → ทางด่วนแบบการ์ตูน เช่น แก้ข้อความหน้าเดียว = ตรวจครั้งเดียวจบ (ข้อ 7 A–D พี่เคาะแล้ว 01/10 · Friday รับไปทำเป็น PR แยกในรอบรูป — ถ้ายังไม่เสร็จ ทำในรอบนี้)
ง. HANDOFF เล็กลง — เหลือเฉพาะที่แชทถัดไปใช้จริง · ประวัติรอบที่ปิดแล้วย้ายไฟล์เก็บ (ไม่ลบ) · ตัวชี้ที่ชี้เข้า §3 ยังหาเจอ · รายการรอเจ้าของใน §16 แยก ยังรอจริง / ตอบแล้ว / ล้าหลัง
จ. เรื่องเดียวกันเขียนหลายฉบับ — เช่น IMAGE_SPEC §0 ข้อ 5 กฎรูปแรกซ้อน 3 ฉบับ (รวมทุกกลิ่น → พัด 5 → Caliburn)
ฉ. ของรก — รูปไม่ใช้ ~17 ไฟล์ · worktree ค้าง 3 · ของค้างใน _incoming
   · agent 10 · สกิล 7 · สคริปต์ ~65 ตัวไหนไม่ได้ใช้แล้วหรือทำซ้ำกัน = ลบหรือรวม · ความจำ `.claude/memory` · เอกสารเก่าใน `docs/` ที่ไม่มีใครชี้ถึง
