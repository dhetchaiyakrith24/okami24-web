# /handoff — HANDOFF §16 สำหรับแชทใหม่

เจ้าของอ่านโค้ดไม่ออก และ AI ตัวถัดไปจะเชื่อทุกคำในนี้ → **ซื่อสัตย์ยิ่งกว่าปกติ** · ภาษา: อังกฤษ (13.9 — Cowork แปลให้เจ้าของ)

## เมื่อไหร่ (ที่เดียว)

- **(ก) ปิดก้อน / จบรอบ** → ตัวหลักเขียน §16 ตามสเปกข้างล่าง (สกิล `round-close` ขั้น 6) · ไม่ต้องบอกเจ้าของแยก
- **(ข) เจ้าของพิมพ์ handoff / /handoff** → ขั้น 1–3 ทั้งหมด
- **(ค) ก่อนเริ่มงานยาว** (นิยาม = กฎกลาง §12 ข้อ 29) → ถึงเกณฑ์ "เกิน 600k + งานถัดไปยาว" = เขียน §16 แล้วย้ายแชท · ยังไม่ถึง = ไม่ต้องเขียน §16
  (งานระหว่างทาง commit + push ลง branch งานตามปกติ — แชทปิดกะทันหันก็อ่าน `git log` ได้ · เจ้าของ 15/10)
- **(ง) แชทยาวจนจับต้นชนปลายไม่ถูก หรือเห็นคำเตือนของระบบ** (วัดไม่ได้) → บอกตรง ๆ ว่า "ควรเปิดเซสชันใหม่แล้ว" (กฎกลาง §12 ข้อ 29) แล้วย้ายแชทแบบ (จ)
- **(จ) context ถึง 700k** (กฎกลาง §12 ข้อ 29) → ย้ายแชท
- **(ฉ) เจ้าของบอกว่าไปนอน** → ไม่ย้ายแชท (TEAM_RULES 13.6 "กลางคืน") · commit + push → §16 ข้อ 3 "ขั้นถัดไป" ให้ตรง (กันบีบอัดแล้วหลง) → ทำงานต่อในแชทนี้
  · ดูแลแชทลูก: เริ่มคืน = ขอ `request_keep_awake` (คอมหลับ = Chrome หลุด งานรูปหยุด) · แชทลูกจบตาเมื่อไหร่ = ตรวจของจริง (PR · บรรทัด `Checker:` ·
  curl หน้าที่แก้ · ภาพด้วย "Owner eye") · คำถามเทคนิคของแชทลูก = Friday ตอบเอง · เรื่องของเจ้าของ (13.3) = ลง `docs/รอพี่ตรวจ.md` ให้แชทลูกทำส่วนอื่นต่อ ·
  ตื่นมา = ไล่แชทลูกทุกตัว (`list_sessions` linked) แล้วรายงานรวมชุดเดียว
- ย้ายแชท = commit + push ทุกอย่างลง branch งาน (13.6) → §16 → ข้อความพร้อมก๊อปให้เจ้าของ ·
  แชทลูกที่ Friday เปิด = จบตาด้วยรายงานว่า "ขอย้ายแชท" แทนข้อความก๊อป — Friday เปิดแชทต่อเอง (ใครเปิด = 13.6 "ย้ายแชทในเว็บ")

## ย้ายแชท · แชทลูก (วิธี — กฎ = TEAM_RULES 13.6 "ย้ายแชทในเว็บ")

- **แชทลูกเปิดแชทต่อ:** ตรวจว่า §16 + งานอยู่บน GitHub ครบ → เปิดแชทต่อด้วย `start_session` (`effort: "medium"` · คำสั่งชี้ §16) → แชทใหม่ตอบว่าเริ่มงานได้ →
  archive แชทเก่าเอง แล้วบอก 1 บรรทัดในสรุปรวมรอบถัดไป
- **บรีฟ:** ต้องมีทุกคำขอของเจ้าของที่ยังเปิดของรอบ ไม่ใช่แค่ส่วนที่กำลังทำ (สกิล `round-close` Step 0) · ลง `_incoming/next-chat.md` ก่อน — บรรทัดแรก `status: ready` → แชทใหม่เขียน `status: started` · เขียนทับได้เมื่อบรีฟเดิมขึ้น `started` แล้วเท่านั้น (ตัวล็อกปัด)
  · ย้ายหลายสาย = ทีละสาย · ต้องเปิดพร้อมกันจริง = สายอื่นใช้ไฟล์แยก `_incoming/next-chat-<สาย>.md` (ready → started เหมือนกัน)
- **แชทที่ทำพร้อมกัน** = worktree ของตัวเองใต้ `_incoming/` ไม่สลับ branch ของโฟลเดอร์หลัก (LESSONS พ27) · โฟลเดอร์เดียวกัน = แก้ไฟล์ทีละแชท
  · ทั้งแชทใช้ worktree เดียว (LESSONS พ49)
- **แอปให้ `start_session` เฉพาะรอบที่เจ้าของพิมพ์จากหน้าจอแอปบนคอม** — พิมพ์จากมือถือ (Remote Control) · รอบที่ถูกปลุกด้วยโน้ตแชทลูก = ถูกปัด (LESSONS พ38)
  → แชทเก่าหยุดที่ขอบ PR · ทำการ์ด (`own_initiative` = การ์ดเสนอแชทใหม่ที่เจ้าของกดเริ่มเอง) + บอกเจ้าของ 1 บรรทัด → เปิดเมื่อเจ้าของพิมพ์จากคอม → archive แชทเก่า

## ขั้น 1 — ตรวจของจริงก่อน ห้ามข้าม

`git status` · `git log -10 --oneline` · `git fetch && git log --oneline origin/main..HEAD` · อ่าน §16 เดิม ·
ความจำในแชทขัดกับ git = **เชื่อ git** แล้วเขียน 1 บรรทัดว่าเจออะไรไม่ตรง

## ขั้น 2 — เขียนทับ §16 (สเปกที่เดียว)

§16 = บล็อกก๊อปวางสำหรับแชทใหม่ เก็บ **5 อย่างเท่านั้น**:
1. **main** — คำสั่ง `git fetch && git log -1 --oneline origin/main` + ที่ git บอกไม่ได้เท่านั้น (จุดถอยของรอบ · PR ที่เปิดอยู่ · deploy run ล่าสุด)
2. **branch นำหน้า main อะไร** — คำสั่ง `git log --oneline origin/main..<branch>` + commit ไหนยังไม่ผ่าน checker · งานเบื้องหลังที่ยังรัน · ไฟล์ที่ยังไม่ commit
3. **รอบที่เปิด** — ไฟล์คำสั่ง · ก้อนทั้งหมดพร้อมชั้น A/B · หยุดตรงไหน · ขั้นถัดไปขั้นแรก
4. **รอเจ้าของ** — 1 บรรทัดชี้ `docs/รอพี่ตรวจ.md` (รายการเดียว — ไม่เขียนรายการรอเจ้าของใน §16 · คำตอบที่เป็นคำตัดสินถาวร ย้ายไป §18)
5. **คำถามค้าง / งานค้างข้ามรอบ** — ที่ยังเปิดจริง · หัวข้อ `5 open / dated` · ข้อละบรรทัด `  - ` · ผูกกับวัน = `dd/mm` ต้นบรรทัดหรือหลัง ` · `
   (`scripts/stale-work.js` อ่านรูปนี้ — วันที่ที่อื่นในบรรทัดนับเป็นวันที่พูด ไม่ใช่วันครบกำหนด)

- **เรื่องเดิม = เขียนทับ ไม่ย้ายของเก่าไปเก็บ · เรื่องใหม่ = เพิ่มในข้อของมัน** — ของที่จบแล้ว = ลบ (git เก็บฉบับเก่า) · ไม่มีเลขฉบับ ไม่มีบรรทัดหัวเก็บประวัติ
- ≤ 15 KB · ไม่มีบรรทัดไหนเกิน 2,000 ไบต์ (ภาษาไทย 3 ไบต์ต่อตัว — ตัดเป็นหลายบรรทัด · commit ที่เกิน = pre-commit ปัด `scripts/handoff-size-check.js`)
- ปิดท้ายด้วยข้อความพร้อมก๊อป: `อ่าน docs/HANDOFF.md §16 ก่อน` + path ไฟล์คำสั่งรอบ (แชทคลาวด์ = `docs/CLOUD.md` ข้อ 3)
- §17 (กฎและเครื่องมือ) และ §18 (คำตัดสินถาวร) แก้เมื่อของนั้นเปลี่ยนเท่านั้น

## ขั้น 3 — บันทึกแล้วบอกเจ้าของ

commit + push ลง branch งาน → บอกเจ้าของ path เต็มของไฟล์ + ข้อความพร้อมก๊อป

## กฎเหล็ก

1. ติดป้าย `[ตรวจแล้ว]` / `[เชื่อว่า]` / `[รอเจ้าของ]` ทุกข้อที่บอกว่าเสร็จ ใช้ได้ หรือเป็นตัวเลข (กฎกลาง §12 ข้อ 9) · "ผ่านเกณฑ์" ≠ "เจ้าของอนุมัติ"
2. ตัวเลขทุกตัวบอกว่านับจากไหน · สองชุดวัดคนละอย่าง = เตือนว่าห้ามบวกกัน
3. ห้ามซ่อนงานค้างใต้คำว่า "ทีหลัง" — ทุกอย่างที่ยังไม่ทำอยู่ใน §16
4. ปัญหาเครื่องมือของเซสชัน (เบราว์เซอร์ค้าง · cache เก่า) = เขียนว่าเป็นข้อจำกัดของเซสชัน ไม่ใช่บั๊กของโปรเจกต์
