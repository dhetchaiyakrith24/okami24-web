## 1. พิสูจน์ "ของเดิมไม่เปลี่ยน" ด้วย HTML ที่เรนเดอร์จริง ไม่ใช่ด้วยการอ่านแล้วบอกว่าเหมือน
*(รอบ 6 "about3lang" B1 · 2026-09-23)*

**ทำอะไร:** ย้ายข้อความกลุ่ม ก (กล่องยืนยันอายุ) ออกจากคอมโพเนนต์เพื่อเพิ่ม en/zh — งานที่เสี่ยง
ที่สุดคือไทยเปลี่ยนโดยไม่ตั้งใจ จึงดึง `outerHTML` ของกล่องจาก Chrome จริงบน production build
**ก่อนแก้** เก็บไว้ แล้วดึงซ้ำหลังแก้ + อีก 5 ชนิดหน้า เทียบด้วย md5

**ทำไมได้ผล:** เกณฑ์กลายเป็นตัวเลขที่เถียงไม่ได้ (md5 เดียวกัน 7 ครั้ง) แทนคำว่า "ดูแล้วเหมือนเดิม"
และมันจับสิ่งที่ตาจับไม่ได้ — อักขระล่องหน (U+2060/NBSP) ที่กลไก typography จะแอบใส่ให้
checker อิสระคำนวณ md5 เองซ้ำแล้วตรงกัน designer ก็ยอมรับว่าตัวเองพิสูจน์ระดับไบต์ไม่ได้

**หลักฐาน:** checker PASS 5/5 ไม่มีตีกลับ · md5 `d2f9730a…` ใน
`_incoming/about3lang/b1-evidence.md` · commit `8f6a8ae`

**ใช้ซ้ำเมื่อไหร่:** ทุกครั้งที่ต้องแตะไฟล์ที่มีข้อความ "ห้ามเปลี่ยน" อยู่ในนั้น — ย้าย รีแฟกเตอร์
เปลี่ยนที่เก็บ ฯลฯ · สูตร: `AGE_KEY=<ชื่อคีย์ปลอม> node scripts/shot.js <out.png> <url>
--eval "document.querySelector('<sel>').outerHTML"` แล้ว `md5sum` เทียบ

### 1ก. ถ้า md5 ของ HTML ดิบไม่ตรง ยังไม่ใช่ว่าพัง — ตัดคอมเมนต์ของ React ออกก่อน
*(รอบ 6 B2 · 2026-09-23 · [ตรวจแล้ว] checker ยืนยันด้วยวิธีของตัวเอง)*

พอ literal ในโค้ดกลายเป็น `{ตัวแปร}` React จะแทรก `<!-- -->` คั่น text node คนละจุดกับเดิม
md5 ของ HTML ดิบจึงไม่ตรง **ทั้งที่ข้อความและ markup เหมือนเดิมทุกไบต์** — สูตรข้อ 1 ตรง ๆ
จะฟ้องผิดในงานรีแฟกเตอร์ทุกครั้ง แก้ด้วยการวัด **2 ชั้นพร้อมกัน**:
`innerText` md5 (ข้อความ) + HTML ที่ `replace(/<!--[\s\S]*?-->/g,"")` แล้วยุบช่องว่าง (โครง)
ถ้าตรงทั้งคู่ = ทั้งคำและโครงไม่ขยับ · B2 ได้ text md5 เท่าเดิม + HTML 7,630 ตัวอักษรเท่ากันเป๊ะ
checker ไปแกะ AST เทียบทีละฟิลด์เองแล้วได้ผลตรงกัน

### 1ข. grep หาข้อความไทยบนหน้าที่เรนเดอร์แล้ว ต้องตัด U+2060/U+00A0 ทิ้งก่อนเสมอ
*(รอบ 6 B2 · 2026-09-23)*

`thaiTypography` แทรก WORD JOINER กลางคำตอน render → `grep "หัวพอต"` ใน HTML ที่เสิร์ฟจริง
ได้ 0 ทั้งที่คำอยู่บนหน้า · ครั้งแรกที่เจอเกือบสรุปผิดว่าประโยคไม่ได้ขึ้นหน้าแบรนด์
**สูตร:** `html.replace(/[\u2060\u00A0]/g,"")` ก่อน match เสมอ · ใช้ตอนพิสูจน์ว่าคำเก่าหายครบ
ทุกหน้า/คำใหม่ขึ้นเฉพาะหน้าที่ควรขึ้น (B2 กวาด 18 หน้า: เก่า 0/18 · ใหม่เฉพาะ 2 หน้า)

## 2. ถามว่า "ข้อความจะไหลผ่านกลไกไหนบ้าง" ก่อนเลือกที่เก็บข้อความ
*(รอบ 6 "about3lang" B1 · 2026-09-23)*

**ทำอะไร:** ที่ถูกต้องตามสามัญสำนึกคือเอาข้อความเข้า dictionary เหมือนข้อความอื่นทั้งเว็บ
แต่ `LocaleProvider` ส่ง dictionary ไทยผ่าน `thaiTypographyDeep` และข้อยกเว้น `JOINED` ที่ผูกกับวลี
"ไม่มีการกล่าวอ้างด้านสุขภาพ" ชนประโยคนิโคตินของกล่องคำต่อคำ (เพราะ /about มีประโยคเดียวกัน)
จึงเก็บไว้เป็นโมดูลของตัวเอง `src/i18n/age-gate-copy.tsx` แบบ `ServiceCopy<T>` แทน

**ทำไมได้ผล:** ถ้าเข้า dictionary ไทยจะถูกเติมอักขระล่องหนเงียบ ๆ = แก้ข้อความกลุ่ม ก โดยไม่มีใครสั่ง
และเป็นการลากข้อยกเว้นที่เจ้าของอนุมัติไว้เฉพาะประโยคบน /about ไปใช้ที่อื่นเอง

**หลักฐาน:** md5 ของข้อ 1 ว่างเปล่าเพราะไม่ผ่านกลไกจริง ๆ · เจ้าของเคาะตามมา 2026-09-23
ว่าประโยคนี้ **ไม่ต้อง** ผูกอักขระ = การตัดสินใจไม่ลากไปเกินขอบเขตถูกต้อง

**ใช้ซ้ำเมื่อไหร่:** ก่อนย้ายข้อความเข้า dictionary/overlay ใด ๆ — ไล่ก่อนว่ามี transform ตอน render
ไหม และข้อความใหม่ไป match `within` ของ `JOINED` หรือ `NEVER_SPLIT` หรือเปล่า

## 3. แก้ "เพดานที่เดาเอา" ด้วยโครงสร้างที่ไม่ต้องเดา
*(รอบ 6 "about3lang" B3 · 2026-09-23 — [ตรวจแล้ว] checker + designer ผ่าน)*

**ทำอะไร:** Cowork เสนอขยายเพดานป้ายปุ่มไลน์ 9rem → 11rem · เปลี่ยนเป็นคอลัมน์กริด `0fr → 1fr`
แทน ป้ายจึงกว้างเท่าข้อความของตัวเองเสมอ ไม่มีเพดานให้ผิดอีก

**ทำไมได้ผล:** เลขเพดานทุกค่าคือการเดาว่าฟอนต์สำรองของเครื่องลูกค้ากว้างแค่ไหน — 11rem

`scrollWidth === clientWidth` ซึ่งจริงโดยโครงสร้าง ไม่ใช่จริงเพราะฟอนต์วันนี้บังเอิญพอดี

**หลักฐาน:** commit `c3eb1ae` · วัดตอนป้ายกางจริง 113.42 / 80.80 / 62.44px (ไทย/อังกฤษ/จีน)

## 4. ผู้ตรวจที่เดาจากโค้ดโดยไม่มีภาพ = ให้ไปวัด ไม่ใช่ให้ตัดทิ้ง

**ทำอะไร:** designer รายงานข้อหนักสุดพร้อมติดป้ายเองว่า "อนุมานจากซอร์ส ไม่มีภาพยืนยัน" —
กล่องยืนยันอายุอยู่ในชั้นคลุมที่เลื่อนไม่ได้ จอเตี้ยจะกดปุ่มไม่ถึง · แทนที่จะปัดตกเพราะไม่มีหลักฐาน
เขียนสคริปต์วัดที่ตั้งขนาดจอเองได้ (`_incoming/about3lang/viewport-probe.js` — นอก git เก็บเป็นประวัติ) แล้ววัดจริง

(390×360 ไทย/อังกฤษ/จีน + 320×320) · checker ผ่าน

**ใช้ซ้ำเมื่อไหร่:** เมื่อ agent ติดป้ายว่า [เชื่อว่า] ในข้อที่ผลกระทบสูง — ต้นทุนการเขียนตัววัด
มักน้อยกว่าต้นทุนของการเดาผิด · และถ้าเครื่องมือเดิมวัดสิ่งนั้นไม่ได้ นั่นคือเหตุผลที่บั๊กรอดมานาน

## 5. เว็บจริง = commit เดียวกับ HEAD → วัด "ก่อน" จากเว็บจริง ไม่ต้อง build
*(รอบ 7 "SEO ค" B1 · 2026-09-23 · [ตรวจแล้ว] checker B2 ใช้ไฟล์จับภาพชุดนี้เป็น baseline แล้วผ่าน)*

**ทำอะไร:** ตอนเปิดรอบ `origin/main` = เว็บจริง = HEAD จึงเขียน `scripts/head-audit.js` (ย้ายเข้า git 2026-09-25 · วิธีใช้ = หัวไฟล์) ดึง title/desc/H1/JSON-LD/
ลิงก์ใน `<main>` ของทุก URL ใน sitemap จาก okami24.store ตรง ๆ (99 หน้า ~2 นาที) แทนการ build + เปิด server
· ไฟล์เดียวกันรันซ้ำกับ localhost:3412 หลังแก้ = ตาราง ก่อน→หลัง ด้วยวิธีเดียวกัน
**ทำไมได้ผล:** "ก่อน" คือของที่ลูกค้าและ Google เห็นจริง ไม่ใช่ build ในเครื่อง · ได้กราฟลิงก์ภายใน
(`inbound.json`) ฟรี ซึ่งตอบคำถาม "33 หน้าไม่ถูกเก็บเพราะลิงก์น้อยไหม" ได้ทันที (ไม่ใช่)
**กับดักที่เจอ:** sitemap ใส่ origin ของ SITE_URL → ตอนชี้ localhost สคริปต์ยังไปดึงเว็บจริง ต้อง
`replace(/^https?:\/\/[^/]+/, base)` เหมือน og-gate.js · และการ strip U+2060 ก่อนอ่านทำให้ด่าน "head
ต้องมี 0 อักขระดิบ" วัดไม่ได้ → นับดิบแยกอีกรอบ (seo-auditor จับได้)
**ใช้ซ้ำเมื่อไหร่:** ทุกรอบที่เปิดหลัง deploy เสร็จ — เช็ค `git rev-parse origin/main` = HEAD ก่อน

## 6. ให้ผู้ตรวจอ่าน "ชุดที่จะลง" ก่อนลง ไม่ใช่หลังลง — จับหน้าที่แย่งคำกันเองได้ก่อนเสียรอบ build
*(รอบ 7 B2 · 2026-09-23 · [ตรวจแล้ว] checker B2 ผ่าน 5/5 รอบเดียว 0 ตีกลับ)*

**ทำอะไร:** เขียนสตริง head ทั้งชุดลง `b2-head-set.md` แล้วส่ง thai-copy (คำ/เพดาน) กับ seo-auditor

## 7. ลิงก์ "ก่อน" ต้องนับทุกชนิด — ตัวกรองแคบเกินทำให้ regression มองไม่เห็น
*(รอบ 7 B3 · 2026-09-23 · [ตรวจแล้ว] designer จับได้จากภาพ · checker รอบ 2 ยืนยัน)*

**ทำอะไร/พลาด:** นับเฉพาะ `/guides/` ลิงก์ → รายงานว่า pod-180 "ก่อน = 0" ทั้งที่มีลิงก์ `/technology/`
อยู่ 1 · กฎใหม่ 3 ข้อดันลิงก์เก่าที่เจาะจงสินค้าหลุดจากเพดาน 3 ต่อหน้า · designer เห็นจากภาพ before
**ทางแก้ที่ได้ผล:** ในฟังก์ชันที่มีเพดาน ให้กฎที่อ้างข้อเท็จจริงของสินค้านั้น (mesh · โอห์ม · หมวด) มาก่อน
กฎทั่วไป (format · แบต) เสมอ · และตัววัด "ก่อน" ต้องนับ href ทุก prefix ที่บล็อกนั้นสร้างได้
**ใช้ซ้ำเมื่อไหร่:** ทุกครั้งที่เพิ่มกฎเข้ารายการที่มี `MAX_*` — ถามก่อนว่าอะไรจะหลุด ไม่ใช่แค่อะไรจะเพิ่ม

## 8. ต่อประโยคท้าย lede = แตะ head โดยไม่รู้ตัว — ให้ seo-auditor "จำลองการตัด" ก่อนลง
*(รอบ 8 B2 · 2026-09-23 · [ตรวจแล้ว] checker B1–B4 ยืนยัน meta ของ m-bar-pod ตรงตัวอักษร)*

**ทำอะไร:** ส่งชุดที่จะลง (ประโยค Marbo ต่อท้าย shortDescription 3 หน้า) ให้ seo-auditor อ่านก่อน build
· มันจำลอง `withPriceSuffixTh` แล้วพบว่า m-bar-pod จะถูกตัดเป็น "…เรียกตระกูล M Bar ว่า ของแท้ ราคา ฿129" (คำว่า "ว่า"
ไม่อยู่ใน DANGLING_TAIL) — แก้ด้วยแถว `PRODUCT_DESCRIPTION_HEAD_TH["m-bar-pod"]` = ข้อความก่อนรอบ head จึงไม่ขยับ
**ทำไมได้ผล:** ข้อความ "เนื้อหน้า" กับ "head" ในโปรเจกต์นี้มาจากฟิลด์เดียวกัน (shortDescription → meta ผ่านตัวตัด)
การต่อประโยคในเนื้อจึงเปลี่ยน head ของหน้าที่กำลังวัดผลอยู่โดยไม่มีใครสั่ง · ตรวจบนกระดาษถูกกว่า build+ตรวจซ้ำ (ต่อยอดข้อ 6)
**ใช้ซ้ำเมื่อไหร่:** ทุกครั้งที่แตะ `shortDescription` / `descriptionTh` ของหน้าที่ไม่มีแถว head override — ถามก่อนว่า
มันไหลไป `<meta>` ไหม และเส้นฐาน 05/10 กำลังวัดหน้านั้นอยู่ไหม

## 9. ตัวนับคลิก = ตัวฟังตัวเดียวที่ `document` ไม่ใช่ onClick ทีละปุ่ม

**ทำไมได้ผล:** ลิงก์ไลน์ที่เพิ่มในอนาคตถูกนับเองโดยไม่ต้องจำ · แตะไฟล์น้อย (diff = attribute ล้วน ไม่มีข้อความเปลี่ยน)

**ใช้ซ้ำเมื่อไหร่:** ทุก "นับ/ติดตาม" ที่ผูกกับ href หรือ selector — ฟังที่ document ก่อน ค่อยเพิ่ม data-attribute เฉพาะจุดที่ต้องแยกชื่อ

## พ1. "เซฟ ๆ ให้ด้วย" = "ระวัง ๆ ให้ด้วย" ไม่ใช่คำสั่งให้ไปเซฟ

กลัวทับซ้อน รก ขัดกันเอง ไม่จำเป็น"
**ทำไมพลาด:** เจ้าของพูดตามความรู้สึก (หมวด 12 ข้อ 1) — คำกำชับกับคำสั่งหน้าตาเหมือนกัน · การสร้างของใหม่นอกแผน (กิ่ง ไฟล์ สำเนา)
เพิ่มของให้ Cowork/แชทหน้าต้องมาเดาว่าคืออะไร
**ใช้ซ้ำเมื่อไหร่:** เจ้าของพูดทำนอง "ระวัง / อย่าให้หาย / เซฟ ๆ" กลางงาน → ตอบว่างานปลอดภัยอยู่แล้วเพราะอะไร (commit/push ไหนแล้ว ·
อะไรยังอยู่แค่ในเครื่อง) · จะสร้างกิ่ง/สำเนา/ไฟล์ใหม่นอกแผน = ถามก่อน 1 บรรทัด
(ย้ายแชทกลางก้อน = commit + push ลง branch งานตาม 13.6 — อยู่ในแผน ไม่ใช่ "นอกแผน" ของบทเรียนนี้)

## พ2. ส่งข้อความข้ามแชทโดยไม่เช็คว่าแชทนั้นเป็นของโปรเจกต์ไหน

**ใช้ซ้ำเมื่อไหร่:** ก่อนส่งอะไรเข้าแชทอื่น (ข้อความ งาน คำขอให้เขียนไฟล์) ต้องยืนยันก่อนว่าแชทนั้นเป็นของโปรเจกต์นี้ (รีโป/โฟลเดอร์ที่เห็นจริง
หรือเจ้าของบอก) · ยืนยันไม่ได้ = ไม่ส่ง แล้วบอกเจ้าของ · กฎที่ครอบเรื่องนี้ = กฎกลางข้อใหม่ "แยกโปรเจกต์ขาดจากกัน" (เปิด PR ใน smogz-rules #6 วันเดียวกัน รอ merge)

## 18. รูปผู้ผลิตรายกลิ่นเป็นโปสเตอร์รก แต่ตัวสินค้าในรูปถูก = ให้ AI "ตัดออกมาโดยห้ามจัดท่าใหม่" แล้วใช้ GPT Image ลบพื้นเป็นโปร่งใส (รอบรูป-ทั้งเว็บ 30/09 แชท 10 · M Switch 15K 17 กลิ่น)

## 19. ตัวอักษรเรืองแสง / แถบป้ายมันวาว ต่างกันแค่สี = แยกแต่ละพิกเซลเป็น "ขาวเทา + สีต้นแบบ" แล้วเปลี่ยนแค่ส่วนสี (รอบรูป-ทั้งเว็บ 30/09 แชท 11 · INFY 20K 22 กลิ่น · MURO SC 8000 12 ซอง)

INFY 20K = ตัวอักษร INFY แกนขาว ขอบสีตามกลิ่น · ซอง MURO = แถบป้ายมันวาวสีตามกลิ่น · ย้อมแบบบทเรียน 17 (สัดส่วนความเข้ม) ทำแกนขาวกับเงามันเพี้ยน · ทางที่ได้: ต่อพิกเซล แก้สมการ p = a·(1,1,1) + w·C (least squares, C = สีต้นแบบในรูปหลัก) แล้วเขียนใหม่ = a·(1,1,1) + w·T (T = สีของกลิ่นนั้น อ่านจากรูปร้าน) — แกนขาว (w≈0) เงามัน (a สูง) ขอบลบรอย (ผสม) อยู่ครบ · ชื่อกลิ่นบนตัวเครื่อง/ป้าย = เติมพื้นที่เดิมด้วยแถวผิวข้างเคียง แล้วพิมพ์ด้วยฟอนต์จริง (บทเรียน 11) · 1 รูปหลัก Higgsfield (2 เครดิต) ต่อสินค้า · 0 เครดิตต่อกลิ่น · ทรงเหมือนกันเป๊ะทุกกลิ่น · สคริปต์ `_incoming/image-sitewide/infy/recolour.js` · `muro/compose.js` · **กับดัก:** รูปร้านบางกลิ่นเป็นเรนเดอร์ไฟปิด ตัวเครื่องดูเป็นสีเทา — เช็คกับรูปถ่ายจริงก่อนตัดสินสีตัวเครื่อง (INFY: รูปจริง Strawberry Banana ตัวดำ) · ร้านใช้ซองผิดกลิ่นในโปสเตอร์ได้ (MURO Watermelon = ซอง Apple Shisha ทั้ง 2 ร้าน) = อ่านชื่อบนป้ายทุกรูปก่อนเก็บสี · **ใช้ซ้ำเมื่อไหร่:** สินค้าที่ต่างกันแค่สีของลาย/ป้ายที่มีขาวหรือเงามันปนอยู่ (M Switch Pod รอบแก้ทรงเพี้ยน)

## 20. ตัวเลือกทรงเดียวกัน แต่รูปรายตัวทำจาก AI คนละครั้งจนทรงเพี้ยน = เลือกรูปที่ทรงดีที่สุด 1 รูปเป็นแม่แบบ แล้วย้าย "ป้ายจริง" ของแต่ละตัวมาแปะ (รอบรูป-ทั้งเว็บ 30/09 แชท 12 · M Switch Pod 17 กลิ่น · [ตรวจแล้ว] checker PR #152 อ่านชื่อบนป้าย 8 ไฟล์ตรงทุกไฟล์)
