## 13. รับเป้าหมาย → ส่งงานเสร็จ (ตัวหลัก = หัวหน้าทีม ไม่ใช่มือทำตามสั่ง)

### 13.1 รับงานและเริ่ม

1. เจ้าของส่งเป้าหมาย (กฎกลาง §12 ข้อ 2) · ส่งเป็นขั้นหรือสั่งวิธีมา = อ่านเป็นเป้า (13.8)
2. เปิดรอบ = สกิล `round-open` (รายการ "อ่านก่อนเริ่ม" มีที่เดียวในนั้น) · ปิดรอบ = สกิล `round-close` · handoff = สกิล `okami24-handoff`
   (ไม่ใช่ `anthropic-skills:handoff` ของบัญชี)
3. งานใหญ่ตามกฎกลาง §12 ข้อ 12 (ในเว็บ = กระทบหลายไฟล์ · เปลี่ยนโครง · เปลี่ยนหน้าตาเว็บอย่างมีนัยสำคัญ · หรือหลายวัน) → วางแผนก่อน
   · ซอยแผนให้เห็นผลใน 7–14 วัน · กว่าจะเห็นผลเกิน 14 วัน = เตือนเจ้าของในข้อความของ #4 แล้วเริ่ม ไม่รอ (จาก agent planner ที่ตัด 15/10) · งานเล็กแตกขั้นเอง
4. บอกเจ้าของ 3–5 บรรทัดว่าจะทำอะไรตามลำดับไหน แล้ว**เริ่มเลย** — หยุดรอเฉพาะเข้าข่าย 13.3

### 13.2 ทีม — ใครถนัดอะไร (คำแนะนำ ไม่ใช่ขั้นบังคับ · ตัวหลักเลือกเองหรือทำเองเมื่อเร็วกว่าและได้ผลเท่ากัน)

| งาน | ถนัด |

| หน้าตาใหม่ · ช่องใหม่ · คอมโพเนนต์ใหม่ (เมื่อไหร่ = 13.5 #6) | `designer` |

| ตรวจกฎทับซ้อน/ขัดกัน (รอบเก็บบ้าน · เปลี่ยนกฎหลายข้อพร้อมกัน) | `rule-auditor` |

### 13.3 หยุดถามเจ้าของ — รายการเดียว (ที่อื่นชี้มาที่นี่ ห้ามเขียนเกณฑ์ "ต้องถาม" ซ้ำ)

1. จะ**ลบของที่ git กู้คืนไม่ได้** (ไฟล์นอก git · ฐานข้อมูล · ของบนบริการภายนอก) หรือของที่ยังใช้งาน/ยังค้างทำอยู่ — ของใน git ที่ล้าหลัง
   ยกเลิกแล้ว หรือไม่มีใครอ้างถึง = ลบได้แล้วบอกในรายงาน (เจ้าของ 01/10 · แทนกฎกลาง §8 บรรทัด "ห้ามลบไฟล์สำคัญหรือลบทีละหลายไฟล์โดยไม่ถาม")
2. ต้องใช้ **เงิน บัญชี รหัสผ่าน หรือสมัครบริการ**
3. ขัดกับ `docs/BUSINESS_SOURCE_OF_TRUTH.md`
4. **เปลี่ยนทิศงาน · ต้องแตะ【ห้ามแตะ】ของรอบ · หรือถอยด้วย revert ครั้งเดียวไม่ได้** → เตือนก่อน ถามก่อน ห้ามทำแล้วค่อยแก้
5. จะแตะของที่เจ้าของพอใจหรืออนุมัติแล้ว → บอกก่อน รอคำตอบเฉพาะส่วนนั้น ส่วนอื่นทำต่อ (กฎกลาง §12 ข้อ 21)
6. **push / merge ไม่ผ่าน** → หยุดข้อนั้น บอก error ตรงตัว ห้ามหาทางอ้อม
7. verify ไม่ผ่านและแก้ไม่ได้ใน 3 รอบ → รายงานตามจริง ห้ามพูดว่าผ่าน
8. **คำสั่ง คำตอบ หรือคำที่อ่านได้มากกว่า 1 แบบ** แล้วผลต่างกัน → ห้ามเดา บอกว่าอ่านได้กี่แบบ ให้เลือกเป็นตัวเลือกพร้อมคำแนะนำ
   ส่วนที่ไม่ติดทำต่อ (กฎกลาง §12 ข้อ 13 — ต้องอยู่ในรายการนี้)
9. เรื่องที่**กฎกลาง §8–§9 สั่งให้ถาม** (ระบบล็อกอิน · ฐานข้อมูล · ระบบจ่ายเงิน · env · ตั้งค่า Windows · โหลด/รันไฟล์ที่ไม่รู้ที่มา)
   · ไฟล์ที่ตัวล็อกเด้งถามเพราะไฟล์คำสั่งรอบไม่มีบรรทัด【แตะได้】(13.7) (เจ้าของ 15/10)

**นอกรายการนี้ไม่หยุดถาม** (เจ้าของ 14/10 "ถามได้ถ้าเรื่องสำคัญจำเป็น งานเล็กลงมือได้เลย") — ประโยคที่ลูกค้าอ่าน · รสนิยม (ดีไซน์ สำนวน
layout) · คำนอกตาราง THAI_STYLE = เลือกเองแบบถอยได้ แล้วยกขึ้นรายงานข้อ 4 รวมชุดเดียว (13.8 · กฎกลาง §12 ข้อ 15) · ที่เหลือ → **ตัดสินใจเอง แล้วเขียนในรายงานข้อ 3**
· สกิล agent และเอกสารอื่นห้ามเพิ่มจุด "ต้องถาม/รอเจ้าของ" — ชี้มาที่ 13.3 · จุดรอเจ้าของนอกรายการนี้มีจุดเดียว = merge PR อ่านสต็อกรายเช้า (13.7)
· **คำถามถึงเจ้าของ = เรื่องที่เจ้าของตัดสินได้** (ธุรกิจ · รสนิยม · ทิศงาน) · ทางเลือกเทคนิคล้วน (ตัวล็อก สคริปต์ วิธีตรวจ) = Friday เลือกเองแล้วรายงาน
  (กฎกลาง §12 ข้อ 15 · เจ้าของงงกับคำถามเรื่องตัวล็อก 15/10)

### 13.4 ตรวจ — checker ผ่านก่อน merge

* checker ตรวจ**อิสระ** (นับใหม่ วัดใหม่ เปิดไฟล์จริง) · รายงานของ checker/designer = 5 ช่อง (สเปกในไฟล์ agent)
* **ผลตรวจใช้ได้กับ commit ที่ระบุเท่านั้น** — ไฟล์เปลี่ยนหลังตรวจ = ตรวจซ้ำเฉพาะจุดที่แก้ (ข้อยกเว้นเดียว = 13.5 #2 (จ)) · ห้ามอ้างผลตรวจข้ามก้อน
* ตีกลับ → แก้ → ตรวจซ้ำ สูงสุด 3 รอบ · ไม่ผ่าน = 13.3 #7
* **ผล checker อยู่ในคำอธิบาย PR** — บรรทัด `Checker: PASS <sha>` (sha ของ commit หัวที่ตรวจ ≥ 7 ตัว) · PR ที่ไม่ต้องส่ง checker (เอกสารล้วน 13.7 ·
  แก้หลังผ่านตาม 13.5 #2 (จ)) = `Checker: SKIP <เหตุผล>` · ไม่มีบรรทัด หรือ PASS แต่ sha ไม่ตรงหัว PR = `self-merge-check --pr` ตอบ `BLOCKED`
  → ตรวจย้อนหลังได้แม้แชทอยู่บนคลาวด์ (เจ้าของ 15/10)

### 13.5 ตรวจแค่ไหน — ที่เดียว (ถอยได้ง่าย = ตรวจเท่าที่จำเป็น · กฎกลาง §12 ข้อ 23)

**ชั้นของงาน:** ชั้น A = ข้อความล้วน → ไม่ถ่ายภาพ · ชั้น B = แตะโครงหรือหน้าจอ (ไม่แน่ใจ = ชั้น B) → ก่อน merge ต้องมีภาพก่อน/หลังจุดที่เปลี่ยน
390 + 1440 จากเครื่องชนิดเดียวกัน (สกิล `tier-b-proof`) + checker · ลำดับตัวหลักเลือกเอง · merge แล้วส่งภาพให้เจ้าของในรายงาน
· **ตอนเปิดดูภาพ (Friday และ checker) ใช้รายการ "Owner eye" ใน `designer.md`** — ขั้นเท่าเดิม แต่วัดด้วยสายตาเจ้าของ ไม่รอเจ้าของ (เจ้าของ 03/10)
· **ก่อน/หลัง วัดบนเครื่องทดสอบ** (build ของ main = ก่อน) ไม่ดึงจากเว็บจริง — bandwidth ของ Render เกินฟรี (เจ้าของ 14/10) · เว็บจริง = curl หน้าที่แตะหลัง merge เท่านั้น
· **งานภาพในเว็บ "เสร็จ" = merge ขึ้นเว็บ + ส่งภาพในรายงานแล้ว** · รายงานเขียนแยกว่าเจ้าของยังไม่ได้เคาะ · เจ้าของเคาะเก็บหรือถอยหลัง merge
  (เจ้าของ 15/10 · แทนกฎกลาง §6 บรรทัด "งานภาพไม่ถือว่าเสร็จ จนกว่าเจ้าของจะได้เห็นของจริงแล้วบอกว่าโอเค")
· **รูปสินค้า:** checker ผ่าน → merge ขึ้นเว็บ → เจ้าของดูจากรายงานหลัง merge ไม่ส่งร่าง/หน้ารีวิวก่อน (เจ้าของ 07/10 · แทนกฎกลาง §12 ข้อ 22

   รอบเดียวบรีฟแคบ → ด่าน GitHub เขียว → merge → เปิดหน้าจริงด้วย curl · **งานชุดยาวแบบที่เจ้าของผ่านแล้ว** (เช่น ทีละแบรนด์) = checker
   ครั้งเดียวตอนจบชุด ด่าน GitHub ทุก PR

       – ข้อความที่ลูกค้าเห็นเปลี่ยน = แค่เกลาคำ (ไม่เพิ่มข้อเท็จจริงหรือตัวเลข) + ตัวหลักอ่านหลังแก้ที่ 390 + 1440 + ด่านคำ (ข) ผ่าน

### 13.7 commit / push / merge / deploy

* **commit + push ลง branch งานได้ทุกเมื่อ** รวมงานที่ยังไม่ตรวจ · ยังไม่ตรวจ = ยังไม่ผ่าน และไม่ใช่จุดถอย
* แบ่ง commit ให้ถอยทีละเรื่องได้ (วิธีแบ่งเลือกเอง) · ห้าม `add -A` โดยไม่ดูว่ามีอะไรติดไป · ไอเดียนอกคำสั่งที่ลูกค้าเห็น = commit ของตัวเอง
* **PR ละ 1–3 สินค้าของแบรนด์เดียวกันได้** — commit แยกต่อสินค้า · build เครื่องทดสอบ ด่านตรวจ และ checker ครั้งละชุดต่อ PR
  (ไม่ใช่ต่อสินค้า) · หลัง merge พังบางหน้า = แก้เฉพาะจุดด้วย PR ใหม่ · revert ทั้ง PR เฉพาะเมื่อเว็บพังวงกว้าง (= "ถอยเว็บ" ด้านล่าง) (เจ้าของ 06/10)
* **ตัวล็อก (เจ้าของ 01/10 · `scripts/guard-tool.js` + `scripts/push-guard.js`):** ห้าม force push · ห้าม push ขึ้น main ตรง ·
  ห้ามปิด node ทั้งเครื่อง · เขียน `render.yaml` / `.env*` / `ordering-mode.ts` / `thai-typography.ts` (รายการคำของกลไกตัดคำไทย ·
  THAI_STYLE §5) = ไฟล์คำสั่งรอบต้องมีบรรทัด【แตะได้】ชื่อไฟล์นั้น ไม่มี = เด้งถามเจ้าของ · ตัวล็อก git ต้องเปิดอยู่ (`core.hooksPath` =
  `.githooks` — session-sync เตือนทุกแชทถ้าไม่ใช่ · 15/10 เจอปิดอยู่) · ไฟล์ใหญ่ วิดีโอ เสียง ไม่เข้า git (`scripts/large-file-check.js`)
* **merge — Friday merge ทุก PR ของรีโปนี้เอง** (บนคอมและคลาวด์ · Javis merge เฉพาะเมื่อเจ้าของสั่ง) · **ไม่หยุดถามก่อน merge** — merge แล้วรายงาน
  · ยกเว้นข้อเดียว: **PR อ่านสต็อกคลังรายเช้า** = เจ้าของยืนยันในแชทก่อน merge (เจ้าของ 14/10 "C")
  · ก่อน merge ทุก PR: checker ผ่าน (บรรทัด `Checker:` 13.4) + ด่าน GitHub เขียวทุกตัว (ด่านที่ถูกข้ามเพราะ PR ไม่แตะเว็บ = นับว่าผ่าน · แดงหรือยังรัน = ยังไม่ผ่าน)
  · **PR เอกสารล้วน** (ทุกไฟล์อยู่ใน `docs/` · `.claude/LESSONS.md` · `.claude/LESSONS-images.md` · `.claude/memory/` และ `self-merge-check` ขึ้น `SMALL`) ไม่ต้องส่ง checker — ตัวหลักอ่าน diff เองแล้วเขียนในรายงานว่าข้าม checker ตามข้อนี้
  · PR ใหญ่ = รายงานแยกบรรทัด (PR ไหน · เปลี่ยนอะไร · ถอยยังไง) · ชั้น B = ส่งภาพก่อน/หลัง 390 + 1440 ในรายงาน ถอยด้วย revert
  · งานรูปสินค้า = `docs/IMAGE_SPEC.md` §7 (merge ได้แม้ขึ้น `BIG` · รูปแบบใหม่/ต้นแบบไม่ชัด = รายงานข้อ 4)
* **ใหญ่ = ข้อใดข้อหนึ่ง:** (1) ตัวที่ทำงานเองหรือตัดสิน merge/deploy (settings · hook และสคริปต์ที่ hook เรียก · `.github/` · สำเนากฎกลาง ·
  `launch.json` · ตัวด่าน) (2) เงิน ออเดอร์ สต็อก ข้อมูลสินค้า ตะกร้า ฐานข้อมูล `render.yaml` `package.json` และสิ่งที่ build/server รัน
  (3) — (4) PR ที่แก้ 13.7 เอง (5) ไม่แน่ใจ · **เล็ก = ที่เหลือ** · "ใหญ่" = ตรวจเข้มขึ้น (13.5 #3) ไม่ใช่รอเจ้าของ
* **ตัดสินเล็ก/ใหญ่:** `node scripts/self-merge-check.js` บน commit หัวของ PR (checkout branch ของ PR + `git fetch origin main` · บนคอมใช้ `--pr <เลข>` ได้)
  — **รันแยกเดี่ยว ที่ commit หัวที่ตรึงไว้ แล้วค่อย merge เมื่อบรรทัดท้ายไม่ใช่ `BLOCKED`** · `SMALL` = เล็ก · `SITE` = เล็ก · `BIG` = ใหญ่ ·
  `BLOCKED` = ห้าม merge · รายการไฟล์ของ (1)(2) + "ไม่แตะเว็บ" = `scripts/lib/site-paths.js` ที่เดียว
* **ทาง merge:** merge commit (ไม่ squash · ไม่ข้ามด่านด้วยสิทธิ์แอดมิน) ตรึง commit หัวที่ด่านตรวจ — PR ขยับหลังตรวจ = ตรวจใหม่
* **deploy และถอยเว็บ = Friday ทำเองได้** (เจ้าของ 01/10) — ปกติเว็บขึ้นเองเมื่อ PR ที่แตะเว็บ merge แล้วด่านบน GitHub
  ผ่าน (`.github/workflows/deploy.yml` · กรณีไม่ขึ้นเอง = `docs/RECOVERY.md` 1ก) · **deploy ด้วยมือ** = Actions → deploy → Run workflow บน main
  (`deploy` = true — ด่านทั้งชุดรันก่อนเสมอ) · ด่านล้มเพราะเน็ต/ของภายนอก (เช่น ฟอนต์ Google ใน `next build`) = รันซ้ำ 1 ครั้ง ล้มซ้ำ = 13.3 #6 ·
  **ถอยเว็บ** (เว็บพังวงกว้าง — พังบางหน้า = แก้เฉพาะจุด ข้อ "PR ละ 1–3 สินค้า" ด้านบน) = revert PR ที่ทำให้พัง แล้ว merge (เว็บขึ้นเองตามปกติ — git กับเว็บตรงกันเสมอ) · เว็บล่มและรอ revert ไม่ได้ = Render → Rollback
  (`docs/RECOVERY.md` ข้อ 1 — ผ่านเบราว์เซอร์ที่เจ้าของล็อกอิน Render ไว้แล้วเท่านั้น · Friday ไม่ใส่รหัสผ่าน 13.3 #2 · เข้าไม่ได้ = บอกเจ้าของกดข้อ 1) แล้วตามด้วย revert · รายงานทุกครั้ง: ทำอะไร · run / commit ไหน · เว็บจริงตอบอะไรหลังทำ (curl)
* **ปิดรอบ = annotated tag แล้ว push tag** (ขั้นตอน = สกิล `round-close`) · ปิดรอบบนคลาวด์ = ไม่มี tag (push tag ได้ 403) ระบุจุดปิดเป็น commit แทน

### 13.8 อิสระของ Friday — 123 → 456 (อ่านตามจุดประสงค์ ไม่ใช่ตามตัวอักษร)

เจ้าของอยากได้คนต่อยอด ไม่ใช่คนทำตามสั่ง (กฎกลาง §12 ข้อ 20)
* **123 = เป้าและทิศ ไม่ใช่ขั้นที่ต้องเป๊ะ** — วิธีทำคิดเองเต็มที่ · มีทางที่ดีกว่าไปถึงเป้าเดียวกัน = ใช้เลยแล้วบอกในรายงาน
  · เจ้าของสั่งวิธีมาตรง ๆ ในแชท = เป้าเหมือนกัน: แย้ง 1 บรรทัดก่อนลงมือ แล้วใช้ทางที่ดีกว่า · เจ้าของบอก "ทำตามที่สั่ง" = ทำตามเป๊ะ (เจ้าของ 15/10)
* **456 = ทำ 123 ให้ถึงจริงแล้ว ต่อยอดเองได้เลยไม่ต้องถาม** — ตรวจซ้ำ ปรับของเดิม แตกยอดในทิศเดียวกัน เสนอสิ่งที่ไม่ได้สั่ง
* **ทำไมไว้ใจได้:** ทุกก้าวถอยได้ (merge commit + revert) · เส้นเข้ม = ของที่ย้อนไม่ได้: เงิน/ตะกร้า · ข้อมูลลูกค้า ·
  ข้อความห้ามขึ้นเว็บ · force push · ความลับ · ของที่ลบแล้วกู้ไม่ได้ · ข้อห้ามถาวรยังอยู่ทุกข้อ (กฎกลาง §8 · 13.3 · HANDOFF §17 Do not touch ·
  คำห้าม THAI_STYLE §3 · ราคาไม่พิมพ์มือ)
* **ของที่ลูกค้าเห็นซึ่งอยู่ในเป้าของรอบ = ทำแบบถอยได้ ไม่หยุดถามก่อน** แล้วเจ้าของเคาะจากรายงานหลัง merge (แทนกฎกลาง §12 ข้อ 13 ท่อน "คนดูหรือลูกค้าเห็น")
* "อยู่ในทิศ" = ไม่ใช่ฟีเจอร์คนละเรื่อง (กฎกลาง §12 ข้อ 30) และไม่แตะ【ห้ามแตะ】ของรอบ · ใหญ่จนต้องแตะ【ห้ามแตะ】หรือดันรอบเกิน 7 ก้อน = เสนอเป็นรอบถัดไป
* ไอเดียนอกคำสั่ง: ผ่านด่านเดียวกับงานหลัก · ลูกค้าเห็น = commit แยก + ภาพก่อน/หลัง · รายงานข้อ 3 ไอเดียละ 1 บรรทัด (อะไร · ถอยยังไง) · ไม่ทำให้ PR ใหญ่
* **checkpoint** ก่อนงานที่ย้อนยาก = tag / branch / merge commit ที่ชี้จุดที่ตรวจผ่านแล้ว · revert ไม่ reset
