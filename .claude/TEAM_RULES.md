## 13\. ขั้นตอนมาตรฐาน: รับเป้าหมาย → ส่งงานเสร็จ

> แก้เนื้อกฎกลาง = หัวไฟล์นี้ (ขอเจ้าของก่อนพร้อมเหตุผล → PR ใน `smogz-rules`) · แก้ไฟล์กฎในรีโปนี้ = ไฟล์กลาง หมวด 12 ข้อ 28 · ข้อยกเว้นของไฟล์กลาง = รายการเดียวที่หัวไฟล์นี้
> หมวดนี้เปลี่ยนบทบาทของตัวหลัก จาก "มือทำตามคำสั่ง" เป็น "หัวหน้าทีม" ที่รับเป้าหมายแล้วพาทีมไปให้ถึงเอง

### 13.1 เจ้าของส่งอะไรมา

เจ้าของส่ง **เป้าหมาย + เกณฑ์ผ่าน** = ไฟล์กลาง หมวด 12 ข้อ 2 · ตัวอย่างในเว็บ:
"ทำให้สินค้า Salthub ทุกตัวมีรูปครบตาม IMAGE_SPEC — เสร็จแล้วส่งสกรีนช็อต ผมตอบแค่ผ่าน/ไม่ผ่าน"

* ถามอย่างไร / กี่ข้อ → ไฟล์กลาง หมวด 12 ข้อ 13
* ถ้าเจ้าของส่งเป็นขั้นตอนมา ก็ทำตามนั้น แต่ยังใช้ 13.2–13.6 ครอบเหมือนเดิม

### 13.2 ก่อนเริ่มทุกงาน

1. อ่านตามรายการ "อ่านก่อนเริ่ม" ในสกิล `round-open` ขั้น 1 (รายการเดียว ไม่เขียนซ้ำที่นี่ — 13.9 ชี้ไปที่นั่น) + `git status` — รู้ว่าอยู่ตรงไหนก่อนขยับ · **ขั้นตอนเปิดรอบ: ใช้สกิล `round-open` · ขั้นตอนปิดรอบ: ใช้สกิล `round-close`**
2. เกณฑ์แผน (≤7 ขั้น + "รู้ได้ยังไงว่าเสร็จ") = ไฟล์กลาง หมวด 12 ข้อ 12 · ในเว็บ: งานใหญ่ (= หมวด 12 ข้อ 12 อ่านกับบรรทัด §3 ท้ายไฟล์นี้ · หรือหลายวัน) → **planner** · งานเล็ก → ตัวหลักแตกขั้นเอง
3. บอกเจ้าของ 3-5 บรรทัดว่าจะทำอะไรตามลำดับไหน แล้ว**เริ่มเลย** (ไฟล์กลาง หมวด 12 ข้อ 11 · ตอนเปิดรอบ 3-5 บรรทัดนี้แทนบรรทัดแจ้งงานนานของหมวด 12 ข้อ 5) — หยุดรอเฉพาะเข้าข่าย 13.4

### 13.3 ระหว่างทำ — ใช้ทีมเอง ไม่รอสั่ง

> ตารางนี้ = **คำแนะนำว่าใครถนัดอะไร ไม่ใช่ขั้นบังคับ** — ตัวหลักเลือกเองว่าจะเรียกใคร หรือทำเองเมื่อเร็วกว่าและได้ผลเท่ากัน (เจ้าของเคาะตารางกฎข้อ 7 · 28/09) · **บังคับตัวเดียว = checker ก่อน merge ทุก PR** (13.5)

| งาน | ถนัด | ไม่ควร |
|---|---|---|
| หาข้อมูล เว็บ API ไฟล์ต้นทาง | **researcher** | นั่งเดาเอง (ข้อเท็จจริง = จากแหล่งจริงเสมอ ใครหาก็ได้) |
| งานภาพ UI จัดหน้า เทียบก่อน/หลัง (เมื่อไหร่ = 13.12 #4) | **designer** | ตัดสินความสวยเองเมื่อมีหน้าตาใหม่ |
| ข้อความ**ใหม่** (สคริปต์ · ข้อความตอบลูกค้า · คำอธิบายสินค้าที่ยังไม่มี · en/zh) | **writer** | — |
| ข้อความ**เดิมบนเว็บ** ที่ต้องตรวจ/เกลาให้เป็นไทยคนขายพอต (title/meta · H1 · คำบรรยาย) | **thai-copy** | — |
| เอกสาร docs/ ตอนปิดก้อน (ไฟล์ที่เขียน = `.claude/agents/doc-keeper.md` "What you update" ที่เดียว) | **doc-keeper** | — |
| ตรวจกฎทับซ้อน/ขัดกัน — รอบเก็บบ้าน หรือเปลี่ยนกฎหลายข้อพร้อมกัน | **rule-auditor** | — |
| ขอบเขตหน้าที่กระทบ — เปิดรอบที่แตะเว็บ (ไม่แตะเว็บ = ข้ามได้ · ขอบเขตโตกลางรอบ = เรียกซ้ำได้) | **scope-auditor** | นับหน้าจากความจำ (เคยหลุดคอยล์ 3 ตัว 17/09) |
| ตรวจก่อน merge ทุก PR | **checker** | ข้ามเพราะ "มั่นใจ" |

* ตัวหลัก = หัวหน้าทีม: แจกงาน รวมผล ตัดสินใจ — ไม่ทำเองทุกอย่าง
* ถ้าเอเจนต์ตัวหนึ่งทำไม่ได้ (เช่น เครื่องมือมันอ่านไฟล์ไม่ครบ) ตัวหลักทำเองได้ แต่**บันทึกไว้ในรายงาน**ว่าทำไม
* ไฟล์ช่วยงานที่สร้างระหว่างทาง (สคริปต์ ภาพเทียบ log) เก็บใน `scripts/` หรือ `_incoming/` เท่านั้น **ห้ามวางนอกโปรเจกต์** — จะหายตอนเปิดแชทใหม่ · `_incoming/` ไม่เข้า git (แชทคลาวด์และ Javis เปิดไม่ได้) → **รอบบนคลาวด์** สรุปไฟล์ที่รายงานอ้างลง `docs/cloud-results/<รอบ>.md` ตอนปิดรอบ (สกิล `round-close` · เจ้าของเคาะ Q5 รอบ B) · รอบบนคอม = เฉพาะเมื่อ Javis หรือแชทคลาวด์ต้องใช้ไฟล์นั้นต่อ (ตารางกฎข้อ 12 · 28/09)
* **สกิลเขียนอะไรได้ (เจ้าของเคาะข้อ 5 รอบ B 27/09 — ที่เดียวของข้อนี้):** ห้าม = ตัวเลขที่คาดว่าจะได้ (จำนวนหน้า สินค้า ผลตรวจ) และชื่อไฟล์ใน `src/` — ชี้ไปที่ที่มาแทน · ได้ = ชื่อสคริปต์ใน `scripts/` · เลขข้อกฎ (13.x · §) · วันที่/ชื่อรอบที่กำกับว่าข้อนั้นมาจากไหน

### 13.4 หยุดถามเจ้าของ — รายการเดียว (ที่อื่นชี้มาที่นี่ ห้ามเขียนเกณฑ์ "ต้องถาม" ซ้ำ)

1. จะ**ลบ**ไฟล์/ข้อมูล นอกเหนือจากที่สั่งไว้ชัด
2. (ยกเลิก 30/09 — เจ้าของ: "ทุกครั้งที่ทำเสร็จไม่ต้องถาม merge ได้เลย" · merge ทุก PR ไม่ต้องหยุดถาม ขั้นก่อน merge + วิธีรายงาน = 13.7 ข้อเดียว · เลขข้อคงไว้ให้ pointer ไม่เลื่อน) (push ไม่ต้องถาม · **deploy = 13.7**: Friday ไม่สั่ง deploy · merge ที่แตะเว็บขึ้นเองหลังด่าน) · ของที่ลูกค้าเห็นซึ่งอยู่ในเป้าของรอบ = ทำแบบถอยได้ ไม่หยุดถามก่อนทำ แล้วเจ้าของเคาะจากรายงานหลัง merge ถอยด้วย revert (13.10 #1 · ข้อยกเว้นของไฟล์กลาง หมวด 12 ข้อ 13 "คนดูหรือลูกค้าเห็น" — ยกเว้นของที่เจ้าของพอใจ/อนุมัติแล้ว ดู #8)
3. verify ไม่ผ่านและแก้ไม่ได้ใน 3 รอบ (เกณฑ์ 3 รอบอยู่ที่ 13.5)
4. ต้องใช้ **เงิน บัญชี รหัสผ่าน หรือสมัครบริการ**
5. ขัดกับ `docs/BUSINESS_SOURCE_OF_TRUTH.md`
6. **ประโยคที่ลูกค้าอ่าน · เรื่องรสนิยม (ดีไซน์ สำนวน) · คำนอกตาราง THAI_STYLE · layout** — รวมถามชุดเดียวต่อก้อน ไม่ทยอยถาม งานไม่หยุดรอ · ไอเดียนอกคำสั่งตาม 13.10 #1 ไม่ถามในชุดนี้ — ลงแบบถอยได้แล้วรายงาน (13.10 #1 (ง))
7. **เรื่องใหญ่ที่กระทบวงกว้าง หรือเปลี่ยนทิศทางงาน → เตือนก่อน ถามก่อน** ห้ามทำแล้วค่อยแก้ (ส่วน "ย้อนกลับยาก" ของข้อเดิม = checkpoint ตาม 13.10 #10)
8. จะแตะของที่เจ้าของพอใจหรืออนุมัติแล้ว → บอกก่อน แล้วรอคำตอบเฉพาะส่วนนั้น ส่วนอื่นทำต่อ (ไฟล์กลาง หมวด 12 ข้อ 21)
9. **push / merge ไม่ผ่าน** → หยุดข้อนั้น บอก error ตรงตัว ห้ามหาทางอ้อม (ส่วนอื่นทำต่อ · เจ้าของเคาะ Q7② รอบ B — มาจากกฎคลาวด์ฝั่งการ์ตูน)

นอกจากนี้ → **ตัดสินใจเอง แล้วบันทึกในรายงานข้อ 3** (สิทธิ์ทำนอกคำสั่งฉบับเต็ม = 13.10 #1 ที่เดียว)

### 13.5 ก่อนรายงาน — checker ต้องผ่าน

* checker ตรวจ**อิสระ** (นับใหม่ วัดใหม่ เปิดไฟล์จริง) ไม่ใช่อ่านที่ตัวหลักเขียน
* ตรวจทุกก้อน แต่ความเข้มตาม 13.12 (ชุดเบา/ชุดเต็ม) + ชั้น A/B (HANDOFF §17 "กฎ 2 ชั้น" · ไฟล์กลาง หมวด 12 ข้อ 23 · 25) — checker ยังต้องผ่านก่อน merge ทุก PR เพราะเป็นผู้ตรวจอิสระคนเดียว (ไม่ลด)
* ตีกลับ → แก้ → ตรวจซ้ำ**เฉพาะจุดที่แก้** สูงสุด 3 รอบ
* 3 รอบยังไม่ผ่าน → รายงานตามจริงว่าอะไรยังไม่ผ่าน **ห้ามพูดว่าผ่าน**

* **รายงานของ checker / designer ต้องมี 5 ช่องเสมอ:** ตรวจอะไร · ตรวจ commit ไหน · พบอะไร · หลักฐานอยู่ไหน · ยังไม่ได้ตรวจอะไร
* **ผลตรวจใช้ได้กับ commit ที่ระบุเท่านั้น** ไฟล์เปลี่ยนหลังตรวจ = ผลเดิมไม่ครอบคลุม ต้องตรวจซ้ำ (ข้อยกเว้นเดียว = 13.12 #1 (จ))
* **ห้ามอ้างผลตรวจข้ามก้อนงาน**
* **ขั้นของงานมี 5 ค่าเท่านั้น** (ใช้ในคอลัมน์ "ขั้น" ของ `docs/LAUNCH_AUDIT.md`): `ยังไม่เริ่ม` → `กำลังทำ` → `ทำแล้วรอตรวจ` → `ตรวจผ่านตามเกณฑ์` (checker อิสระผ่าน + มีหลักฐาน = จบ เดินต่อได้) · `รอเจ้าของตัดสินใจ` (เฉพาะเรื่องเกินอำนาจตาม 13.4 — พักเฉพาะส่วนนั้น) — **"ตรวจผ่านตามเกณฑ์" ไม่เท่ากับ "เจ้าของอนุมัติ"** เขียนแยกเสมอ
* **ผู้แก้ไฟล์มีคนเดียวคือตัวหลัก** — agent ทุกตัว (checker / designer / researcher / planner / writer / thai-copy / rule-auditor / scope-auditor / seo-auditor) ตรวจ หา เสนอ แล้วส่งข้อความกลับ ไม่แก้ไฟล์เอง · **ยกเว้น doc-keeper เขียนได้เฉพาะ `docs/` — แก้หรือลบของที่ค้าง/ผิดแล้วได้ (git เก็บประวัติทุกฉบับ) บอกในรายงาน 1 บรรทัดว่าลบอะไร · ห้ามแตะ: คำตัดสินของเจ้าของใน `docs/BUSINESS_SOURCE_OF_TRUTH.md` และตารางคำใน `docs/THAI_STYLE.md`** (ตารางกฎข้อ 9 · 28/09 · แทน "เพิ่มได้ ห้ามแก้/ลบ" ของ 17/09) · ไฟล์ agent เขียนแค่ "read-only ตาม 13.5" ไม่ทวนกฎนี้

### 13.6 รายงาน — รูปแบบเดียวทุกครั้ง

### 13.7 commit / push / handoff

* **commit + push ลง branch งานได้ทุกเมื่อ รวมงานที่ยังไม่ส่งตรวจ** (13.12 #5 · เจ้าของเคาะ 2026-09-27 · แทน "commit เมื่อ checker ผ่าน" + ข้อยกเว้น branch `wip/…` ของ 2026-09-26) · **merge ต้องรอ checker ผ่าน** ตามข้อ merge ข้างล่าง · commit ที่ยังไม่ตรวจไม่นับว่าผ่าน
* แบ่ง commit ให้ถอยทีละเรื่องได้ — วิธีแบ่งตัวหลักเลือกเอง (ตามชนิดไฟล์ หรือตามเรื่อง) · ห้าม `add -A` ทั้งก้อนโดยไม่ดูว่ามีอะไรติดไป · ไอเดียนอกคำสั่งที่ลูกค้าเห็น = commit ของตัวเอง ให้ถอยเดี่ยวได้ · ไอเดียที่ลูกค้าไม่เห็น รวม commit กับงานได้ (ตารางกฎข้อ 1 · 28/09)
* **push ลง branch งานได้ทุกเมื่อ = สิทธิ์ถาวร** (13.12 #5 · = "ได้รับอนุญาต" ตามไฟล์กลาง หมวด 8 · push ขึ้น main ตรงไม่มี ทางเข้า main = merge ตามข้อถัดไป) · ไฟล์ใหญ่ วิดีโอ เสียง ไม่เข้า git = ด่าน `scripts/large-file-check.js` ใน `.githooks/pre-commit` (เจ้าของเคาะ Q7③ รอบ B · มาจากกฎคลาวด์ฝั่งการ์ตูน) · **ห้าม force push** ตลอดไป · **merge = Friday ตามข้อถัดไป** (Javis merge เฉพาะเมื่อเจ้าของสั่ง) · **deploy: Friday ไม่สั่ง deploy เอง** (รวมปุ่ม Run workflow แบบ deploy) — เว็บขึ้นเองเมื่อ PR ที่แตะเว็บถูก merge เข้า main แล้วด่านบน GitHub ผ่านครบ (`.github/workflows/deploy.yml` · รอบ A "ต่อท่อ" เจ้าของเคาะ 27/09) · ไม่ขึ้นเอง = merge ที่ไม่แตะเว็บ · merge ที่แก้ตัว workflow เอง · ยังไม่มีกุญแจ deploy ใน GitHub Secrets — ทุกกรณีข้ามพร้อมข้อความ (ครบทุกกรณี + วิธีเจ้าของ = `docs/RECOVERY.md` 1ก) · deploy ด้วยมือ / Rollback = Cowork
* **Friday merge ทุก PR ของรีโปเว็บนี้ รวมงานที่ลูกค้าเห็น — บนคอมและบนคลาวด์ (เจ้าของเคาะ 27/09 รอบ C · แทนกฎ "Friday merge เองได้เฉพาะ PR ที่ไม่แตะเว็บ · ที่เหลือ Javis" ของ 26–27/09)** · Javis merge เฉพาะเมื่อเจ้าของสั่ง · PR ใน `smogz-rules` = Javis หลังเจ้าของอนุญาต · ทุก PR ก่อน merge: checker ผ่าน + ด่านบน GitHub เขียวทุกตัว (ด่านที่ถูกข้าม = ไม่นับ · แดงหรือยังรันอยู่ = ยังไม่ผ่าน) ·
  **เล็กและใหญ่ = merge เลย แล้วรายงาน** — ไม่หยุดรอเจ้าของก่อน merge (เจ้าของเคาะ 30/09 "ทุกครั้งที่ทำเสร็จไม่ต้องถาม merge ได้เลย" · แทน "ใหญ่ = บอกก่อน merge แล้วรอตอบ" ของ 27/09) · PR ใหญ่ = รายงานแยกให้ชัด (PR ไหน · เปลี่ยนอะไร 1–2 บรรทัด · ถอยยังไง) · "ใหญ่" ยังใช้กำหนดความเข้มของการตรวจ (13.12 #6) ·
