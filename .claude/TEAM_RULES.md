### 13.3 หยุดถามเจ้าของ — รายการเดียว (ที่อื่นชี้มาที่นี่ ห้ามเขียนเกณฑ์ "ต้องถาม" ซ้ำ)

1. จะ**ลบของที่ git กู้คืนไม่ได้** (ไฟล์นอก git · ฐานข้อมูล · ของบนบริการภายนอก) หรือของที่ยังใช้งาน/ยังค้างทำอยู่ — ของใน git ที่ล้าหลัง
   ยกเลิกแล้ว หรือไม่มีใครอ้างถึง = ลบได้แล้วบอกในรายงาน (เจ้าของ 01/10 · แทนกฎกลาง §8 บรรทัด "ห้ามลบไฟล์สำคัญหรือลบทีละหลายไฟล์โดยไม่ถาม")
   · **branch ที่ merge เข้า main แล้ว ทั้งในเครื่องและบน GitHub = ลบเองได้ ไม่ต้องถามทุกครั้ง** (commit อยู่ใน main ครบ · เจ้าของ 16/10 "ได้" ·
   แทนกฎกลาง §8 บรรทัดเดียวกัน) — ข้อยกเว้นและวิธี = สกิล `house-clean` "รายการเดียว" ข้อ 1
2. ต้องใช้ **เงิน บัญชี รหัสผ่าน หรือสมัครบริการ**
3. ขัดกับ `docs/BUSINESS_SOURCE_OF_TRUTH.md`
4. **เปลี่ยนทิศงาน · ต้องแตะ【ห้ามแตะ】ของรอบ (หรือรายการ HANDOFF §17 "Do not touch" ที่ไฟล์คำสั่งรอบไม่ได้ระบุให้แตะ) · หรือถอยด้วย revert ครั้งเดียวไม่ได้** → เตือนก่อน ถามก่อน ห้ามทำแล้วค่อยแก้
5. จะแตะของที่เจ้าของพอใจหรืออนุมัติแล้ว → บอกก่อน รอคำตอบเฉพาะส่วนนั้น ส่วนอื่นทำต่อ (กฎกลาง §12 ข้อ 21)
6. **push / merge ไม่ผ่าน** → หยุดข้อนั้น บอก error ตรงตัว ห้ามหาทางอ้อม
7. verify ไม่ผ่านและแก้ไม่ได้ใน 3 รอบ → รายงานตามจริง ห้ามพูดว่าผ่าน
8. **คำสั่ง คำตอบ หรือคำที่อ่านได้มากกว่า 1 แบบ** แล้วผลต่างกัน → ห้ามเดา บอกว่าอ่านได้กี่แบบ ให้เลือกเป็นตัวเลือกพร้อมคำแนะนำ
   ส่วนที่ไม่ติดทำต่อ (กฎกลาง §12 ข้อ 13 — ต้องอยู่ในรายการนี้)
9. เรื่องที่**กฎกลาง §8–§9 สั่งให้ถาม** (ระบบล็อกอิน · ฐานข้อมูล · ระบบจ่ายเงิน · env · ตั้งค่า Windows · โหลด/รันไฟล์ที่ไม่รู้ที่มา)
   · ไฟล์ที่ตัวล็อกเด้งถามเพราะไฟล์คำสั่งรอบไม่มีบรรทัด【แตะได้】(13.7) (เจ้าของ 15/10)

**ถามแล้วเจ้าของยังไม่ตอบ** (กฎกลาง §12 ข้อ 14 · เจ้าของ 26/10 "ใช่ครับตามนั้นเลย"): **รอคำตอบเสมอ** = #1 · #2 · #9 · #4 ท่อน "ถอยด้วย revert ครั้งเดียวไม่ได้" ·
PR สต็อกที่ผิดปกติ (13.7) · **ส่งถึงคนนอก** (กฎกลาง §12 ข้อ 14: ข้อความถึงลูกค้า คู่ค้า ดีลเลอร์ · โพสต์ · ส่งลิงก์หรือตัวอย่างให้คนนอก ·
เปิดช่องทางใหม่ เช่น เว็บหรือบัญชีใหม่) แม้ติด #5 หรือ #8 · **ไม่นับเป็นส่งถึงคนนอก:** ลงสินค้า หน้าใหม่ หรือแก้หน้าบนเว็บที่เปิดอยู่แล้ว (13.8 · เจ้าของ 26/10 "ไม่นับ ลงสินค้าหรือหน้าใหม่บนเว็บทำได้ตามปกติ") — ระหว่างรอทำส่วนอื่น · **ครบ 30 นาทีแล้วเลือกทางที่แนะนำเอง** = #3 · #4 ท่อนเปลี่ยนทิศ / 【ห้ามแตะ】 · #5 · #8 →
ลงมือแบบถอยได้ แล้วเขียนในรายงานว่าเลือกเองเพราะยังไม่ได้คำตอบ · #3 = ทางที่เลือกต้องไม่ขัด BSOT และไม่แก้ BSOT (ทำส่วนที่ไม่ขัด · เรื่องที่ขัดยังรอ) ·
#6 #7 ไม่ใช่คำถาม (รายงานตามจริง) · คำถามนอกรายการ (รสนิยม · ประโยค) = ถามได้ ไม่หยุดรอ
(แทนกฎกลาง §12 ข้อ 13 ท่อน "อ่านได้มากกว่า 1 แบบ = ห้ามเดา … ให้เลือกก่อนทำ" และข้อ 21 ท่อน "รอคำตอบเฉพาะส่วนนั้น" — เฉพาะเมื่อถามแล้วครบ 30 นาทีไม่มีคำตอบ)

**นอกรายการนี้ไม่หยุดถาม** (เจ้าของ 14/10 "ถามได้ถ้าเรื่องสำคัญจำเป็น งานเล็กลงมือได้เลย") — ประโยคที่ลูกค้าอ่าน · รสนิยม (ดีไซน์ สำนวน
layout) · คำนอกตาราง THAI_STYLE = เลือกเองแบบถอยได้ แล้วยกขึ้นหัวข้อ "ต้องตัดสินใจ/ทำ" ของรายงาน รวมชุดเดียว (13.8 · กฎกลาง §12 ข้อ 15) · ที่เหลือ → **ตัดสินใจเอง แล้วเขียนในข้อ "ตัดสินใจเอง" ของรายงาน**
· สกิล agent และเอกสารอื่นห้ามเพิ่มจุด "ต้องถาม/รอเจ้าของ" — ชี้มาที่ 13.3 · จุดรอเจ้าของนอกรายการนี้ = PR สต็อกที่ติดเงื่อนไขผิดปกติ (13.7) · งานเต็มของหน้าตาใหม่ที่ไม่มีของเดิมให้เทียบและยังไม่มีรูปอ้างอิง
  (กฎกลาง §6 — ระหว่างรอทำร่างและส่วนอื่นต่อ ไม่ใช่หยุดงาน · Friday เลือก 15/10 เจ้าของค้านได้)
· **คำถามถึงเจ้าของ = เรื่องที่เจ้าของตัดสินได้** (ธุรกิจ · รสนิยม · ทิศงาน) · ทางเลือกเทคนิคล้วน (ตัวล็อก สคริปต์ วิธีตรวจ) = Friday เลือกเองแล้วรายงาน
  รวมกฎ/คู่มือที่ขัดกันเรื่องเทคนิคล้วน (แทนกฎกลาง §12 ข้อ 28 ท่อน "ของซ้ำที่ขัดกัน … ส่งตารางให้เจ้าของเคาะ" เฉพาะเรื่องเทคนิค)
  (กฎกลาง §12 ข้อ 15 · เจ้าของงงกับคำถามเรื่องตัวล็อก 15/10 · "technical choices are Friday's — never asked")

### 13.4 ตรวจ — checker ผ่านก่อน merge

* **ก่อนส่ง checker ทุก PR = `node scripts/pre-checker-gate.js` ขึ้น `GATE PASS`** (branch · push แล้ว · ไม่มีของค้าง/ขยะ · ไฟล์ล็อก ·
  คำห้าม · ตารางทั้งร้านในไฟล์ client — รายการเต็มที่หัวสคริปต์) · ตก = แก้แล้วรันใหม่ ไม่ใช่จุดถามเจ้าของ (ยกเว้นแถว `locked` = 13.3 #9)
  · ผ่านแล้วด่านจดว่า "checker กำลังอ่าน" → ตัวล็อกปัด Edit/Write ใน tree นั้นนอก `_incoming/` · git ที่ย้ายหรือเขียน tree · build · start/stop/build
  เครื่องทดสอบ จนกว่ารายงานกลับแล้วรัน `--done` (โน้ตหมดผลเองใน 3 ชม. · checker ทำนานกว่านั้น = รันด่านใหม่) · rm / sed -i / redirect ใน tree ล็อกไม่ครอบ = Friday ไม่ทำเอง (LESSONS พ22 · รอบตัวล็อก 15/10)

### 13.7 commit / push / merge / deploy

* **commit + push ลง branch งานได้ทุกเมื่อ** รวมงานที่ยังไม่ตรวจ · ยังไม่ตรวจ = ยังไม่ผ่าน และไม่ใช่จุดถอย
  · **PR = draft จนกว่า checker ผ่าน** (`gh pr create --draft` · ด่าน `pre-checker-gate` และ checker ทำบน draft ได้ — ตรวจบนเครื่องทดสอบ) ·
    checker ผ่านแล้วกด Ready (`gh pr ready`) **ครั้งเดียว** ให้ด่าน GitHub รัน แล้ว merge · checker ตีกลับ = `gh pr ready --undo` ก่อนแก้
    (ทุก push เข้า PR ที่ไม่ใช่ draft = รันด่านบน GitHub กินนาที Actions ที่เสียเงิน · เจ้าของ 21/10 "ลดรอบ" · อีเมลงบ 90% 21/10)
* แบ่ง commit ให้ถอยทีละเรื่องได้ (วิธีแบ่งเลือกเอง) · add ไฟล์ทีละชื่อหลังดู `git status --short` (`add -A` / `add .` / `commit -a` = ตัวล็อกปัด) · ไอเดียนอกคำสั่งที่ลูกค้าเห็น = commit ของตัวเอง
* **PR ละ 1–3 สินค้าของแบรนด์เดียวกันได้** — commit แยกต่อสินค้า · build เครื่องทดสอบ ด่านตรวจ และ checker ครั้งละชุดต่อ PR
  (ไม่ใช่ต่อสินค้า) · หลัง merge พังบางหน้า = แก้เฉพาะจุดด้วย PR ใหม่ · revert ทั้ง PR เฉพาะเมื่อเว็บพังวงกว้าง (= "ถอยเว็บ" ด้านล่าง) (เจ้าของ 06/10)
* **รวมงานเล็กเป็นก้อน ขึ้นเว็บครั้งเดียว** (เจ้าของ 26/10): งานเล็กหลายเรื่องที่พร้อมใกล้กัน = PR เดียว commit แยกต่อเรื่อง (ถอยทีละ commit ได้)
  — ทุก deploy = เว็บดับ 30–60 วินาที + build + checker หนึ่งรอบ · ของพังหรือราคาผิด = ไม่รอรวม
* **ตัวล็อก (เจ้าของ 01/10 · `scripts/guard-tool.js` + `scripts/push-guard.js`):** ห้าม force push · ห้าม push ขึ้น main ตรง ·
  ห้ามปิด node ทั้งเครื่อง · เขียน `render.yaml` / `.env*` / `ordering-mode.ts` / `thai-typography.ts` (รายการคำของกลไกตัดคำไทย ·
  THAI_STYLE §5) = ไฟล์คำสั่งรอบต้องมีบรรทัด【แตะได้】ชื่อไฟล์นั้น ไม่มี = เด้งถามเจ้าของ · ตัวล็อก git ต้องเปิดอยู่ (`core.hooksPath` =
  `.githooks` — session-sync เตือนทุกแชทถ้าไม่ใช่ · 15/10 เจอปิดอยู่) · ไฟล์ใหญ่ วิดีโอ เสียง ไม่เข้า git (`scripts/large-file-check.js`)
  · รอบตัวล็อก 15/10 (กฎที่เคยพึ่งความจำ): ห้าม commit บน main · build เปล่าในโฟลเดอร์หลัก · `add -A` · self-merge-check พ่วง merge ในคำสั่งเดียว ·
  path หน้าเว็บใน Git Bash ที่ไม่มี `MSYS_NO_PATHCONV=1` · Chrome 2 งานพร้อมกัน (งานที่สองรอ) · แตะ tree/3412 ระหว่าง checker อ่าน (13.4) — ทุกตัว
  มีตัวอย่างปลอมใน `node scripts/pre-checker-gate.js --self-test` (house-check รันทุกสัปดาห์)
* **merge — Friday merge ทุก PR ของรีโปนี้เอง** (บนคอมและคลาวด์ · Javis merge เฉพาะเมื่อเจ้าของสั่ง) · **ไม่หยุดถามก่อน merge** — merge แล้วรายงาน
  · **PR สต็อกรายชั่วโมง** (งานตั้งเวลา 08:00–00:00) = Friday merge เองได้ ไม่รอเจ้าของ (เจ้าของ 24/10 "Merge ได้เลยโดยไม่ต้องรอ" · แทนข้อเดิม 14/10 "C")
    · ยกเว้นเมื่อผิดปกติ (สินค้าเปลี่ยนพร้อมกันเกิน 15 ตัว · รหัสหายจากที่อ่าน · diff แตะไฟล์อื่น · ตัวอ่านแจ้งปัญหา — เกณฑ์เต็มอยู่ในพรอมต์ของงานตั้งเวลา) = ค้างเป็น draft แล้วถามเจ้าของ
    · **รูทีนอ่านสต็อกจากหน้าคีย์ออเดอร์** (เจ้าของ 24/10 "ตรงกัน 100 %"): หน้ารายการสินค้าของ Shipnity Max บอก "มีของ" ทั้งที่หมดได้ — ของจริง = ปุ่ม "เพิ่ม" ในหน้าคีย์ออเดอร์
      (อ่านอย่างเดียว: ไม่เลือกลูกค้า ไม่ใส่สินค้า ไม่กดบันทึก — วิธี = หัว `scripts/order-entry-stock.js`) · รูทีนปิดและเปิดขายกลับได้เองตามที่อ่าน (`stock-sync.js --order-entry`)
      · อ่านจากหน้ารายการสินค้าอย่างเดียว = ปิดได้อย่างเดียว เปิดกลับต้องให้เจ้าของยืนยันแล้ว Friday ใช้ `--reopen`
  · ก่อน merge ทุก PR: checker ผ่าน (บรรทัด `Checker:` 13.4) + ด่าน GitHub เขียวทุกตัว (ด่านที่ถูกข้ามเพราะ PR ไม่แตะเว็บ = นับว่าผ่าน · แดงหรือยังรัน = ยังไม่ผ่าน ·
    `self-merge-check --pr` อ่านด่านเองแล้ว BLOCKED เมื่อยังไม่เขียว หรือ deploy ถูกข้ามตอนเป็น draft — แก้ = `gh pr ready --undo` แล้ว `gh pr ready` · #667)
  · **PR เอกสารล้วน** (ทุกไฟล์อยู่ใน `docs/` · `.claude/LESSONS.md` · `.claude/LESSONS-images.md` · `.claude/memory/` และ `self-merge-check` ขึ้น `SMALL`) ไม่ต้องส่ง checker — ตัวหลักอ่าน diff เองแล้วเขียนในรายงานว่าข้าม checker ตามข้อนี้
  · PR ใหญ่ = รายงานแยกบรรทัด (PR ไหน · เปลี่ยนอะไร · ถอยยังไง) · ชั้น B = ส่งภาพก่อน/หลัง 390 + 1440 ในรายงาน ถอยด้วย revert
  · งานรูปสินค้า = `docs/IMAGE_SPEC.md` §7 (รูปแบบใหม่/ต้นแบบไม่ชัด = หัวข้อ "ต้องตัดสินใจ/ทำ" ของรายงาน)
* **ใหญ่ = ข้อใดข้อหนึ่ง:** (1) ตัวที่ทำงานเองหรือตัดสิน merge/deploy (settings · hook และสคริปต์ที่ hook เรียก · `.github/` · สำเนากฎกลาง ·
  `launch.json` · ตัวด่าน) (2) เงิน ออเดอร์ สต็อก ข้อมูลสินค้า ตะกร้า ฐานข้อมูล `render.yaml` `package.json` และสิ่งที่ build/server รัน
  (3) — (4) PR ที่แก้ 13.7 เอง (5) ไม่แน่ใจ · **เล็ก = ที่เหลือ** · "ใหญ่" = checker บังคับ (ข้ามแบบเอกสารล้วนไม่ได้) + รายงานแยกบรรทัด · ความเข้ม = 13.5 (ข้อ (1) = ชุดเต็ม #3) · ไม่ใช่รอเจ้าของ
* **ตัดสินเล็ก/ใหญ่:** `node scripts/self-merge-check.js` บน commit หัวของ PR (checkout branch ของ PR + `git fetch origin main` · บนคอมใช้ `--pr <เลข>` ได้)
  — **รันแยกเดี่ยว ที่ commit หัวที่ตรึงไว้ แล้วค่อย merge เมื่อบรรทัดท้ายไม่ใช่ `BLOCKED`** · `SMALL` = เล็ก · `SITE` = เล็ก · `BIG` = ใหญ่ ·
  `BLOCKED` = ห้าม merge · รายการไฟล์ของ (1)(2) + "ไม่แตะเว็บ" = `scripts/lib/site-paths.js` ที่เดียว
* **ทาง merge:** merge commit (ไม่ squash · ไม่ข้ามด่านด้วยสิทธิ์แอดมิน) ตรึง commit หัวที่ด่านตรวจ — PR ขยับหลังตรวจ = ตรวจใหม่
* **deploy และถอยเว็บ = Friday ทำเองได้** (เจ้าของ 01/10) — **Render สร้างและขึ้นเว็บเองทุก merge เข้า main** (`render.yaml` `autoDeployTrigger: commit` ·
  เจ้าของ 21/10 "จะได้ไม่เสียเงิน 2 ต่อ") · ด่าน GitHub = ตรวจ PR แบบเร็ว (tsc · eslint · contract tests ไม่ build) · build เต็ม + leak check = `verify:catalog --full`
  บนเครื่องทดสอบก่อน checker (13.5 #2 (ก) · ด่าน `full`) · Render build อีกครั้งตอนขึ้นเว็บ (build ล้ม = ไม่ขึ้น เว็บเดิมอยู่ต่อ) · ดูว่าขึ้นไหม / ไม่ขึ้นเอง = `docs/RECOVERY.md` 1ก · **deploy ด้วยมือ** = Render → okami24 → Manual Deploy
  (ผ่านเบราว์เซอร์ที่เจ้าของล็อกอินไว้) · build บน Render ล้มเพราะเน็ต/ของภายนอก (เช่น ฟอนต์ Google ใน `next build`) = deploy ซ้ำ 1 ครั้ง ล้มซ้ำ = 13.3 #6 ·
  **ถอยเว็บ** (เว็บพังวงกว้าง — พังบางหน้า = แก้เฉพาะจุด ข้อ "PR ละ 1–3 สินค้า" ด้านบน) = revert PR ที่ทำให้พัง แล้ว merge (เว็บขึ้นเองตามปกติ — git กับเว็บตรงกันเสมอ) · เว็บล่มและรอ revert ไม่ได้ = Render → Rollback
  (`docs/RECOVERY.md` ข้อ 1 — ผ่านเบราว์เซอร์ที่เจ้าของล็อกอิน Render ไว้แล้วเท่านั้น · Friday ไม่ใส่รหัสผ่าน 13.3 #2 · เข้าไม่ได้ = บอกเจ้าของกดข้อ 1) แล้วตามด้วย revert · รายงานทุกครั้ง: ทำอะไร · run / commit ไหน · เว็บจริงตอบอะไรหลังทำ (curl)
* **ปิดรอบ = annotated tag แล้ว push tag** (ขั้นตอน = สกิล `round-close`) · ปิดรอบบนคลาวด์ = ไม่มี tag (push tag ได้ 403) ระบุจุดปิดเป็น commit แทน

### 13.8 อิสระของ Friday — 123 → 456 (อ่านตามจุดประสงค์ ไม่ใช่ตามตัวอักษร)

เจ้าของอยากได้คนต่อยอด ไม่ใช่คนทำตามสั่ง (กฎกลาง §12 ข้อ 20)
* **123 = เป้าและทิศ ไม่ใช่ขั้นที่ต้องเป๊ะ** — วิธีทำคิดเองเต็มที่ · มีทางที่ดีกว่าไปถึงเป้าเดียวกัน = ใช้เลยแล้วบอกในรายงาน
  · เจ้าของสั่งวิธีมาตรง ๆ ในแชท = เป้าเหมือนกัน: แย้ง 1 บรรทัดก่อนลงมือ แล้วใช้ทางที่ดีกว่า · เจ้าของบอก "ทำตามที่สั่ง" = ทำตามเป๊ะ (เจ้าของ 15/10)
* **456 = ทำ 123 ให้ถึงจริงแล้ว ต่อยอดเองได้เลยไม่ต้องถาม** — ตรวจซ้ำ ปรับของเดิม แตกยอดในทิศเดียวกัน เสนอสิ่งที่ไม่ได้สั่ง
* **ทำไมไว้ใจได้:** ทุกก้าวถอยได้ (merge commit + revert) · เส้นเข้ม = ของที่ย้อนไม่ได้: เงิน/ตะกร้า · ข้อมูลลูกค้า ·
  ข้อความห้ามขึ้นเว็บ · force push · ความลับ · ของที่ลบแล้วกู้ไม่ได้ · ข้อห้ามถาวรยังอยู่ทุกข้อ (กฎกลาง §8 · 13.3 · HANDOFF §17 Do not touch ·
  คำห้าม THAI_STYLE §3 · ราคาไม่พิมพ์มือ)
* **ของที่ลูกค้าเห็นซึ่งอยู่ในเป้าของรอบ = ทำแบบถอยได้ ไม่หยุดถามก่อน** แล้วเจ้าของเคาะจากรายงานหลัง merge (แทนกฎกลาง §12 ข้อ 13 ท่อน "คนดูหรือลูกค้าเห็น")
* "อยู่ในทิศ" = ไม่ใช่ฟีเจอร์คนละเรื่อง (กฎกลาง §12 ข้อ 30) และไม่แตะ【ห้ามแตะ】ของรอบ · ใหญ่จนต้องแตะ【ห้ามแตะ】หรือดันรอบเกิน 7 ก้อน = เสนอเป็นรอบถัดไป
* ไอเดียนอกคำสั่ง: ผ่านด่านเดียวกับงานหลัก · ลูกค้าเห็น = commit แยก + ภาพก่อน/หลัง · รายงานข้อ "ทำอะไร" ไอเดียละ 1 บรรทัด บอกว่าทำเพิ่มเอง (อะไร · ถอยยังไง) · ไม่ทำให้ PR ใหญ่
* **checkpoint** ก่อนงานที่ย้อนยาก = tag / branch / merge commit ที่ชี้จุดที่ตรวจผ่านแล้ว · revert ไม่ reset
